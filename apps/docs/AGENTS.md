Fumadocs documentation site (ADR 0514): gen writes it into `.stackra/site/`, React Router prerenders it, and the
`stackra-docs` Cloudflare Worker serves it at docs.stackra.figentra.com. Tier tag `tier:app`.

## Where code goes

- Pages in `src/docs/` (ADRs in `src/docs/adr/`, served at `/adr/<file>`), images, logos and the brand kit in
  `src/assets/`, snippets in `src/snippets/`, the site configuration in `src/config/docs.config.ts` (a `DocsConfig`
  subclass from `@stackra/gen`). Member files (`README.md`, `AGENTS.md`, `package.json`, `stackra.config.ts`,
  `tsconfig.json`) and scripts (`scripts/`) stay outside `src/`.
- The Worker's one script, `worker/main.ts`, only answers `/-/version` (the running version id, for the deploy smoke's
  proof, ADR 0536); everything else is the static site. Its tests sit in `worker/__tests__/`.
- `src/docs/customers/` is the buyer-facing tab: plain, accurate, no invented promise. A term the owner has not
  decided (support levels, EOL dates, how to buy) stays a marked placeholder (`Owner to supply (STA-n)`).
  `customers/packages.mdx` (the package index) and `customers/reference/*.mdx` (one TypeScript reference page per
  package) are generated by `scripts/api-reference/`: never edit them. `/licensing` redirects to `customers/install`
  (the registry points `npm login` there).
- Never write the site, `llms.txt` or the API reference: gen writes them into `.stackra/site/`, which is never edited
  or committed. Moved paths go in `redirects` of `src/config/docs.config.ts`.
- A new page is an `.mdx` under `src/docs/` plus an entry in a group of `src/config/docs.config.ts`; a new ADR needs no
  entry (the `{ folder: "adr" }` group lists it). Every media file in `src/assets` is referenced by a page (the brand
  kit by `src/docs/brand.mdx`).

## System map (`scripts/system-map/`)

- `render-system-map.ts` (pure) and `write-system-map.ts` (node) turn the merged `SystemGraph` of `@stackra/gen` into
  `index.mdx`, `flows/*.mdx` and `services/<repo>/<member>.mdx` under `src/docs/system-map/`. Those pages are
  generated: never edit them and never list services or flows by hand; change the code or the repo's
  `stackra.flows.json` and run the writer again.
- Read the graph only through `@stackra/gen`'s exported types (`SystemGraph`, `GraphNode`, `GraphFlow`, `GraphEdge`).
- Tests sit in `scripts/system-map/__tests__/`. The console renderer is later work (OS console).

## API reference (`scripts/api-reference/`)

- `write-api-reference.ts` lists every published package (`packages/<category>/<name>/package.json`, `private` ones left
  out), reads the exported symbols of each `exports` entry with one TypeScript program (`typescript6`, the JS API
  beside TypeScript 7, as in @stackra/gen) and writes `customers/packages.mdx` plus `customers/reference/<name>.mdx`:
  every exported name with its kind, declaring file, declaration (bodies, initializers, private and `#private` members
  removed), TSDoc (summary, remarks, parameters, returns, throws, deprecation, examples) and members. `@internal` names
  are left out; a name another package declares is listed as a re-export of that package. A package with more than
  `SPLIT_AT` (500) names gets one page per entry point besides `.` (`<name>--<entry>.mdx`), so no page outgrows a
  browser. No TypeDoc or API Extractor.
- Regenerate after changing a package's `package.json` (`version`, `stackra.summary`, `exports`) or any exported
  declaration or its TSDoc: `pnpm --filter @figentra/docs api-reference`, and commit the pages. `pnpm validate` runs
  it with `--check` and fails on a missing, changed or stale page (STA-2857); oxfmt skips the pages so the bytes match.
- The release version step regenerates them: `changeset:version` in the root package.json (the changesets bot's
  `version-script` in runway-npm.yml) ends with the same command, so the "chore(release): version packages" PR carries
  the new versions in the index and every page and passes the check. Keep it the last step (a test pins it).
- The renderers are pure; tests sit in `scripts/api-reference/__tests__/` (a throwaway repository, never the real one).
- MDX safety lives in `prose`: braces escaped, `<` written `&lt;` (gen's component scan reads `\<X>` as a tag), a
  line-start `import`/`export` kept out of ESM; code spans and fences pass through.

## Architecture map (`scripts/architecture-map/`)

- `stackra architecture-map` (a command of @stackra/cli) generates `architecture-map.yaml` (an archify architecture candidate) from the members'
  `stackra` field, `turbo.jsonc` tags and the root `stackra.graph.json`, and renders `src/assets/architecture-map.html`
  with `.agents/skills/archify`. Both files are generated: never edit them; run
  `stackra architecture-map` from the root and commit both.
- `pnpm validate` fails when the committed candidate drifts. Tests are in `@stackra/cli`
  (`src/node/architecture-map/functions/__tests__/architecture-map.test.ts`, vitest, run by its `test` task).
- The map draws; it never decides. A rule goes in validate, oxlint, turbo boundaries or gen, not in the generator.

## Rules that fail the build

- gen's refusals (`docs_source_misplaced`, `docs_page_unlisted`, `docs_page_missing`, `docs_asset_unreferenced`, …);
  `pnpm build` (React Router's prerender) fails on a page that does not render; `pnpm lint` builds the site the same
  way.
- Versions only from catalogs; `turbo.jsonc` extends `//` with one tier tag.

## Tasks

`pnpm dev`, `build`, `lint`, `format`, `test` (the `scripts/` tests), `api-reference` (`:check` compares), `clean`.
