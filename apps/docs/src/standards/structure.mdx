The rules below are the single source for the scaffold (`pnpm new`) and the validator (`pnpm validate`). Each row names the ADR, or the settlement item, it comes from.

## Package categories

A package lives at `packages/<category>/<name>`. Tooling presets live at `packages/tooling/<name>` and carry `tier:config`.

| Category         | Holds                                                                     | Source         |
| ---------------- | ------------------------------------------------------------------------- | -------------- |
| `foundation`     | contracts, validation and errors every layer imports                      | ADR 0127       |
| `application`    | actions, AI, IR and the registry                                          | ADR 0127       |
| `communication`  | webhooks, versioning, integrations, templates and mail                    | ADR 0127, 0270 |
| `commerce`       | money, ledger and pricing primitives                                      | ADR 0127       |
| `cross-cutting`  | brand and concerns that span layers (settlement Q3.1)                     | ADR 0127       |
| `data`           | model, database, content, media, search, assets, filesystem, storage      | ADR 0127       |
| `developer`      | CLI, gen, coding standard and the Vite plugin                             | ADR 0127       |
| `experience`     | UI, experience, navigation, console, panel, builder and collaboration     | ADR 0127, 0270 |
| `infrastructure` | Pulumi-based packages named `infra-<name>`                                | ADR 0127       |
| `runtime`        | outbox, queue, scheduler, workflow, realtime, locking and cache           | ADR 0127       |
| `security`       | identity, IAM, tenancy, connections, entitlements and licensing           | ADR 0127       |
| `state`          | settings, feature flags and theming                                       | ADR 0127       |

Root module: `src/<name>.module.ts`, test `<name>.module.int.test.ts`, ADR 0090.

React hooks: `use-<name>.ts` beside their component, test `use-<name>.test.ts` (unit), ADR 0129. Extension hooks are the only `hooks/` files.

Static files: `assets/<kind>/` beside the root module (`public`, `lang`, `templates`, `stubs`, `data`), ADR 0234. static files shipped with a module; the word resource is reserved for @Resource.

## Banned folders

| Folder         | Why                                                                 | Source   |
| -------------- | ------------------------------------------------------------------- | -------- |
| `controllers`  | raw endpoints live in raw/ only; actions are the unit               | ADR 0130 |
| `dtos`         | Zod schemas replace DTO classes                                     | ADR 0095 |
| `repositories` | MikroORM models and queries replace repositories                    | ADR 0014 |
| `helpers`      | name the kind the code serves instead                               | ADR 0126 |
| `utils`        | shared pure functions go to @stackra/support or the kind they serve | ADR 0126 |
| `presentation` | there is no presentation layer folder                               | ADR 0130 |

## Test tiers

| Tier       | File infix       | Holds                                            | Source   |
| ---------- | ---------------- | ------------------------------------------------ | -------- |
| `unit`     | `.test`          | fast, no external services                       | ADR 0182 |
| `int`      | `.int.test`      | needs a real database or container               | ADR 0182 |
| `contract` | `.contract.test` | checks a declared contract, such as the manifest | ADR 0182 |
| `load`     | `.load.test`     | k6 load tests, run weekly against staging        | ADR 0182 |
| `e2e`      | `.e2e.test`      | runs a whole app                                 | ADR 0022 |

Every test file sits directly in a `__tests__/` folder beside its subject (ADR 0022). `.spec.*` is not used.
