Stackra's changes are written once, as changesets, in the pull request that makes them. The release turns them into
each package's `CHANGELOG.md` ([0013](/adr/0013-versioning-and-release)). This site does not copy them: a copy would
drift.

## Where to read them

| Source                               | What it holds                                                                                                         |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| The package's `CHANGELOG.md`         | every release of that package, newest first; it ships inside the tarball, so it is in `node_modules/@stackra/<name>/` |
| GitHub releases                      | one release per tag `<name>@<version>`, with that version's notes and the signed SBOM attached                        |
| [Package index](/customers/packages) | a link to every package's changelog on GitHub                                                                         |

Because every Stackra package releases at the same version, one release moves every package; a package with no change
of its own shows a version line with only its dependency updates.

## Breaking releases

A major release (or, before `1.0.0`, a breaking minor) also carries a release note written for you: what changes, the
steps to take, how to verify, and how to roll back. It is published with the GitHub release.
