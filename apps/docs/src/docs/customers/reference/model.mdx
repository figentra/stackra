### `EncryptedFieldsOptions`

Interface · declared in `src/core/types/encrypted-fields-options.type.ts`

```ts
interface EncryptedFieldsOptions {
    readonly subject?: string | undefined;
    readonly lookup?: readonly string[] | undefined;
    readonly scope?: string | undefined;
}
```

How a model's encrypted fields are keyed.

| Member | Description |
| ------ | ----------- |
| `readonly subject?: string \| undefined;` | The property holding the subject's public id (`userId`, or `id` for the subject's own row). Each row's encrypted fields are sealed under that subject's own key, so erasing the subject (destroying its salt) shreds them. |
| `readonly lookup?: readonly string[] \| undefined;` | Encrypted fields that also keep a blind index, an HMAC of the plain text under the scope's key in the property `<field>Bidx` (column `<field>_bidx`) the model declares, so `whereEncrypted` finds a row by equal value. Not with `subject`: an index under the scope's key would outlive the subject's shred. |
| `readonly scope?: string \| undefined;` | The property holding the id of the scope that owns the row (`tenantId` on a `BelongsToTenant` model). Each value is then bound to `<model key>.<field>@<scope id>`, so a sealed value copied into another scope's row does not open (ADR 0476). The property must hold an id whenever a value is sealed or opened. |
