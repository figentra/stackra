### `addCalendarMonths`

Function · declared in `src/core/functions/add-calendar-months.function.ts`

```ts
function addCalendarMonths(instant: Date, months: number, timeZone: string, anchorDay?: number): Date;
```

Returns the instant `months` calendar months after `instant` (before it when negative) on the wall clock of
`timeZone`, with the same time of day.

The day is `min(anchorDay ?? the day of instant in timeZone, the last day of the target month)`. Pass `anchorDay`
when a chain is built from the previous result, so the day does not drift: 31 Jan, 28 Feb, 31 Mar, not 28 Mar.

Daylight saving: a wall time the target day skips (a spring-forward gap) moves forward to the first valid instant
after the gap; an ambiguous wall time (a fall-back change) takes the earlier offset, the first of its two
occurrences.

| Parameter | Description |
| --------- | ----------- |
| `instant` | the instant to start from; not mutated. |
| `months` | whole months to add; negative subtracts. |
| `timeZone` | an IANA zone name such as `Europe/Berlin` or `UTC`. |
| `anchorDay` | the day of month to keep across months, 1 to 31; defaults to the day of `instant` in `timeZone`. |

**Returns** a new `Date`.

**Throws** RangeError for an invalid `instant`, a non-integer `months` or `anchorDay`, or an unknown `timeZone`.

**Example**

```ts
addCalendarMonths(new Date("2026-01-31T10:00:00Z"), 1, "Europe/Berlin"); // 2026-02-28T10:00:00.000Z
addCalendarMonths(new Date("2026-01-31T10:00:00Z"), 3, "UTC", 31); // 2026-04-30T10:00:00.000Z
```

### `time`

Constant · declared in `src/core/constants/time.constant.ts`

```ts
const time: Readonly<{ addSeconds: (date: Date, amount: number) => Date; subSeconds: (date: Date, amount: number) => Date; addMinutes: (date: Date, amount: number) => Date; subMinutes: (date: Date, amount: number) => Date; ... 5 more ...; subMonths: (date: Date, amount: number) => Date; }>;
```

Fixed-length time arithmetic over instants. Every helper takes a `Date` and an amount, returns a new `Date` and
leaves the input untouched. A negative amount shifts the other way; a fractional amount is allowed and the result
is truncated to whole milliseconds by `Date`.

Units are exact lengths on the UTC timeline: a minute is 60 s, an hour 3,600 s and a day 86,400 s. A `Date` is a
UTC instant, so `addDays` moves the UTC calendar date by whole days; across a daylight-saving change in some zone
the local wall-clock hour shifts by the offset change, which is the intended behaviour for cutoffs and expiries.
Calendar months (`addMonths`, `subMonths`) move the UTC calendar date and clamp the day to the target month's last
day. Shift from a fixed anchor (`addMonths(anchor, n)` for the n-th period), never from the previous result: chained
shifts drift (31 Jan, 28 Feb, 28 Mar). A period that starts on a wall-clock date in a zone passes that date as UTC
midnight and reads the result the same way. Years are `addMonths(date, 12 * years)`.

Named in camelCase, not SCREAMING_SNAKE, because it is a namespace of functions that consumers call as
`time.subMinutes(...)` (the template contract), not a constant value.

Every helper throws a `RangeError` when the date is invalid or the amount is not finite.

**Example**

```ts
import { time } from "@stackra/support";

const cutoff = time.subMinutes(ctx.now(), settings.autoCancelAfterMinutes);
const expiresAt = time.addDays(issuedAt, 30);
```
