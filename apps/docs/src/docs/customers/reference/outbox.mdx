**Example**

```ts

```

| Member | Description |
| ------ | ----------- |
| `batchWindowSeconds: number;` | How long, in seconds (0 to 60), the relay lets due messages gather before it delivers them: a tick waits until the oldest due message has been due this long, or a full batch is due. `0` delivers at once (ADR 0221's lag); a service that sends in batches (the audit read trail, five seconds) sets it in runway. |
| `changeRetentionDays: number;` | How many days (1 to 400) the change log keeps a change after it was written, whether or not every consumer read it; a consumer replays or backfills within this window. Whole daily partitions are dropped once they are older. |
| `pruneAfterDays: number;` | After how many days (1 to 400) the `outbox_message.prune` job deletes a dead-lettered message (from its dead time) and a received event id of the inbox (from its receipt). The inbox window must outlast every producer's retries. |
| `driver: DriverName<OutboxDriver>;` | Which driver runs: `postgres` keeps messages and ids in the service's database; `memory` in the process. |
