Never copy an existing member to start a new one. `stackra new` (`pnpm new` is its alias) picks the right directory, package scope, tier tag and script set, copies the target repo's `LICENSE` (packages and tooling only) and formats the result. Members come out in the programming model v3 shape: `stackra.config.ts`, one root module and no authored `main.ts` or entry barrel ([ADR 0294](/adr/0294-programming-model-v3-grammar-folders-identities-and-naming) rule R12, [ADR 0295](/adr/0295-build-and-entry-stackra-config-generated-tool-configs-and-entries)). The kinds are decided in [ADR 0126](/adr/0126-member-shapes-and-scaffold-templates).

```bash
stackra new <kind> <name> --description "<one sentence>" [--category <c>] [--entries react,native|none] [--data] [--title "<Title>"] [--port <n>] [--repo <path>] [--dry-run]
```

Run it with `--dry-run` first to see what it would write. Then run `pnpm install` and `pnpm verify`.

A service is one command with a three-command first run, and no hand edit between them:

```bash
stackra new service demo --area app --summary "Demo."
pnpm install
cd services/demo && stackra gen && stackra test
```

`--area` is required (`app`, `admin`, `public` or `platform`): it sets the service's auth exposure, so it is never defaulted (ADR 0082). `--data` adds the database test peers, `@stackra/testing`, an example module (`src/modules/notes/`: a model, its migration, a unit test on PGlite and one `.int.test.ts`) and a `test:int` script (`stackra test --tier int`, which needs Docker). Writing a service writes no tool config: gen writes its Vitest, tsdown and integration-tier configs into `.stackra/` on its first run.

## Kinds

| Kind          | Template                                             | Lands in                     | Pick it for                                                                           |
| ------------- | ---------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------- |
| `service`     | the CLI's own template (`stackra new service`)       | `services/<name>`            | A backend service: plain TypeScript, root module, runway v3, no Encore file           |
| `package`     | `templates/packages/package` + `entries/*` + `data/` | `packages/<category>/<name>` | Any library: entry folders and the root module in `src/node/`                         |
| `tooling`     | `templates/packages/tooling`                         | `packages/tooling/<name>`    | A shared config preset, data only                                                     |
| `app:console` | `templates/apps/console`                             | `apps/<name>`                | A panel app: Vite, React Router 7, HeroUI; port from 3710                             |
| `app:mobile`  | `templates/apps/mobile`                              | `apps/<name>`                | iOS and Android: Expo SDK 57, React Navigation, HeroUI Native; no hyphens in the name |
| `app:desktop` | `templates/apps/desktop`                             | `apps/<name>`                | An Electron app packaged by electron-builder                                          |
| `app:docs`    | `templates/apps/docs`                                | `apps/<name>`                | A Mintlify site; port from 3334                                                       |

`--category` is required for `package` and must be one of: foundation, application, communication, commerce, connectors, cross-cutting, data, developer, experience, infrastructure, runtime, security, state. Names are kebab-case. There is no Next.js kind.

## Flags

| Flag                     | Does                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--entries react,native` | `package` only: the optional entries. Core, `contracts`, `node` and `testing` always come. Without the flag, a terminal is asked; a script gets none.                                                                                                                                                                                                     |
| `--data`                 | `package`: the module's `src/node/database/{migrations,factories,seeders}/`, for a package that owns models. `service`: the example module, the database test peers and `test:int`.                                                                                                                                                                       |
| `--repo <path>`          | Scaffold into another folder or monorepo (for example the private figentra-os), for every kind. A service written into a folder with no `pnpm-workspace.yaml` also gets a minimal workspace root: the catalogs it names (`stackra` pinned to the CLI's version) and an `.npmrc` naming the Stackra registry, no token. An existing root is never touched. |
| `--description`          | Required for every kind: one sentence, which becomes the `package.json` description and opens the README and AGENTS. There is no placeholder, so generated output holds no TODO.                                                                                                                                                                          |
| `--title`, `--port`      | Fill the tokens; the port defaults to the next free one in the kind's range.                                                                                                                                                                                                                                                                              |
| `--dry-run`              | Print the file list, write nothing.                                                                                                                                                                                                                                                                                                                       |

Every flag is non-interactive, so agents and CI run `pnpm new` without a prompt.

## Tokens

The scaffold replaces these tokens in file contents **and** path names. Other double-brace text (JSX style objects) is left alone.

| Token             | Value                                                                                                 |
| ----------------- | ----------------------------------------------------------------------------------------------------- |
| `{{NAME}}`        | kebab-case short name                                                                                 |
| `{{PASCAL}}`      | PascalCase of the name                                                                                |
| `{{TITLE}}`       | Title Case name, or `--title`                                                                         |
| `{{DESCRIPTION}}` | the `--description` sentence; becomes `description` in `package.json` and opens the README and AGENTS |
| `{{PORT}}`        | dev port, the next free one in the kind's range (or `--port`)                                         |
| `{{CATEGORY}}`    | the `packages/` folder                                                                                |
| `{{ENTRIES}}`     | the package's tsdown entry map: one public file per exported entry                                    |

`TITLE` and `DESCRIPTION` are JSON-escaped when written into `.json` and `.jsonc` files. Template files hold tokens, so oxfmt and oxlint skip `tools/scaffold/templates/**`; the generator formats what it renders.

## What you get

Every member gets `package.json`, `turbo.jsonc` with its one tier tag, `README.md`, `AGENTS.md` with a `## PII` table, `CHANGELOG.md` and, for packages and tooling only, the `LICENSE` (apps and services are UNLICENSED, ADR 0195), with code in `src/` and tests in `__tests__/`. Every template with code ships a passing test, because the vitest preset fails an empty suite.

| Kind                  | v3 shape                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `package`             | `stackra.config.ts`; `assets/` (`public/`, `lang/`, exported as `./assets/*`); `src/config/<name>.config.ts` (the Config class, exported from `.`); `src/contracts/` (the leaf); `src/core/`; `src/node/<name>.module.ts` (the root module); `src/testing/`; `src/react/` and `src/native/` with `--entries`; `src/node/database/` with `--data`. The decorators presets for TypeScript, tsdown and vitest.                                                                                                       |
| `service`             | `stackra.config.ts`; `runway.yaml` (runway v3: `requires`, `secrets`, `environments`, no member key, [ADR 0296](/adr/0296-runway-v3-member-requires-and-root-topology-groups)); `src/<name>.module.ts` (`extends Module({})`) and `src/__tests__/<name>.module.test.ts` (`createTestingModule`); `src/modules/<name>/` with `--data`. No config class (add one when the service has settings), no tool config, no `main.ts`, no `stackra.module`, no `dev` or `start` script. `--over` never writes under `src/`. |
| `app:console`         | `stackra.config.ts`; `src/<name>.module.ts`; `src/routes/home/` (`home.route.ts` and its page `home.tsx`); `src/components/panel-shell/`; `src/styles/app.css`.                                                                                                                                                                                                                                                                                                                                                   |
| `app:mobile`          | `stackra.config.ts`; `src/<name>.module.ts`; `src/config/chrome.config.ts` (status bar and tab bar); `src/routes/{home,item,settings}/`; `src/components/screen/`; `src/styles/global.css`.                                                                                                                                                                                                                                                                                                                       |
| `app:desktop`         | `stackra.config.ts`; `src/<name>.module.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `tooling`, `app:docs` | Unchanged: both are exempt from rule R12 (tool configuration and a Mintlify site).                                                                                                                                                                                                                                                                                                                                                                                                                                |

**Entry barrels are generated, never authored** (ADR 0294 decision 15). Until `stackra gen` writes them (STA-339), a package's `exports` key names its entry's one public file: `.` is the config class `src/config/<name>.config.ts`, exported so a host can subclass it ([ADR 0294](/adr/0294-programming-model-v3-grammar-folders-identities-and-naming) decision 19), and `./node` is the root module. `core/`, `contracts/` and `testing/` hold a README and are exported with their first file. A package whose entry gets a second public file before gen ships adds a stand-in `src/<entry>/index.ts` whose header `Purpose:` starts with `Stand-in barrel:`.

**Stand-ins until gen.** Nothing generates entries or tool files yet, so what gen will write stays authored and is marked with a `shortcut:` comment: an app's runtime entry (`src/main.ts(x)`, whose comment names STA-339, gen writing the entries, as the trigger to delete it), the mobile shell and navigators, and the tool files (`index.html`, Vite, Expo, EAS, Metro, tsdown, vitest, electron-builder). The kind bases do not exist either, so the root module, the Config class and the route classes are plain classes, and `stackra.config.ts` exports plain data, each with the `shortcut:` line that names the base it will extend. No member gets `stackra.manifest.json`: gen writes it on its first run (rule R10).

After scaffolding:

1. Fill in the README and AGENTS with the member's real purpose and its PII table.
2. `pnpm install` to link the new member, then `pnpm verify`.
3. Add a changeset (`pnpm changeset`).

## Changing a template

Edit the template under `tools/scaffold/templates/` (a service is the CLI's `serviceTemplate`, in `packages/developer/cli/src/node/functions/service-template.function.ts`), then run the scaffold test of @stackra/cli (`pnpm --filter @stackra/cli test`). The test renders every kind into a temporary directory and fails if a token is left in a path or a file, if a rendered `.json` file does not parse, or if the rendered member fails the validator's member, service and exports checks. It asserts the v3 tree of every kind (no authored `main.ts` or barrel in packages and services, exports naming existing files, runway v3, route folders), and covers the optional entries, `--data`, the required `--description` (no TODO in any rendered file), the JSON escaping, the target repo's `LICENSE`, port allocation and `--dry-run`.

When you add a kind, add a row to the test's case list and to `tools/scaffold/README.md`.

## Moves are scripted, never hand edits

Moving or renaming a file or folder means rewriting every import and link that points at it. Do that with a codemod, not an editor: a script `git mv`s each path, rewrites every relative specifier and link from the file's new location, prints what it changed and can run with `--dry-run`.

<Note>
  Status: target. Stackra has no move codemod yet. Port one before the first large restructuring.
  Until then, move in small steps, run `pnpm typecheck` and `pnpm verify` after each, and never mix
  a move with a behaviour change in one commit.
</Note>
