## Where each secret name lives

A name appears in exactly one store. Application code reads it from the runtime, never from a file. No `.env`, no repository secret ([Secrets](/runbooks/secrets)).

### Encore `secret()` (application secrets, per environment)

Declared as `secret("NAME")` in the service that uses it; a human sets each value in each environment with `encore secret set`. A new name must exist in an environment before the deploy that declares it, or provisioning fails.

| Name                                           | Purpose                       | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------------------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ResendApiKey`, `ResendWebhookSecret`          | Email send, delivery webhooks | Planned                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `StripeSecretKey`, `StripeWebhookSecret`       | Payments                      | Planned; test keys outside prod                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `BetterAuthSecret`                             | Session and cookie signing    | Planned; generated per environment                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `SentryDsn`                                    | Crash reporting               | Planned; not confidential                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `ScanAwsAccessKeyId`, `ScanAwsSecretAccessKey` | Malware-scan callbacks        | TODO: likely replaced by role-based access                                                                                                                                                                                                                                                                                                                                                                                                           |
| `PostHogApiKey`                                | Server-side analytics         | Planned                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `APPLE_SIGN_IN_KEY`                            | Sign in with Apple `.p8` key  | Not an Encore secret: the identity Pulumi stack reads it as `zitadel:APPLE_SIGN_IN_KEY` (the name the seed's `appleSignIn.privateKeySecret` gives), Infisical first ([ADR-0173](/adr/0173-secrets-infisical-is-the-source-of-production-secrets)). The team id, services id and key id are public, in the seed. Each other social provider's client secret follows the same pattern, one stack config secret per provider, held by ZITADEL. STA-1578 |

This repository has no runtime secret (`runway.yaml`: "core has no runtime secret"). A package driver reads a secret by name through its secret store (`this.secret("NAME")`), and the product that binds the driver declares the name; in a product the authoritative list is what `git grep 'secret("'` finds, and `secrets-doctor` (not built) will compare it with `encore secret list`.

### Infisical

| Path           | Environment | Names                                                                                                                                                                                 |
| -------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/agents`      | `dev`       | `HEROUI_PERSONAL_TOKEN`, `GITHUB_PERSONAL_ACCESS_TOKEN`, `CONTEXT7_API_KEY`, `STRIPE_SECRET_KEY` (restricted test key, optional), `RESEND_API_KEY` (optional)                         |
| `/ci`          | `prod`      | `CLOUDFLARE_API_TOKEN` (Worker deploys), `MINTLIFY_ADMIN_KEY` (docs deploy), `HEROUI_AUTH_TOKEN`, `UNIWIND_AUTH_TOKEN` (Quality Gate install): the `secrets.ci` list of `runway.yaml` |
| `/ci/turbo`    | `prod`      | `TURBO_TOKEN` (remote cache; `deploy-turbo-cache.yml` sets it on the Worker as `TURBO_CACHE_TOKEN`)                                                                                   |
| `/ci/registry` | `prod`      | `REGISTRY_SIGNING_KEY` (set on the registry Worker by `deploy-registry.yml`), `REGISTRY_ISSUER_TOKEN` (read by the Figentra OS billing caller, not by a workflow here)                |

Checked against the workflows on 2026-10-29. Every workflow here reads `prod`; `runway.yaml` maps `dev` and `production` to `dev` and `prod`. `NPM_FIGENTRA_TOKEN` is retired with `npm.figentra.com` ([0453](/adr/0453-the-stackra-registry-one-npm-compatible-store-on-cloudflare-and-our-own-licence-engine) decision 17); package publishing needs no token at all (OIDC, [Release](/runbooks/release)). `EXPO_TOKEN`, `ENCORE_API_KEY` and `SENTRY_AUTH_TOKEN` are read by no workflow in this repository; a product repository that deploys keeps them in its own `/ci`. CI logs in with OIDC through three machine identities, whose ids are the repository variables below.

The Quality Gate reads `HEROUI_AUTH_TOKEN` and `UNIWIND_AUTH_TOKEN` from `/ci` in `prod` ([0310](/adr/0310-stackra-ui-pro-private-heroui-pro-wrappers)).
`HEROUI_PERSONAL_TOKEN` in `/agents` is for the HeroUI MCP servers only.

Apple and Google store credentials live in EAS credentials, not in Infisical.

### GitHub repository variables (not secrets)

`INFISICAL_CI_IDENTITY_ID`, `INFISICAL_GATE_IDENTITY_ID` and `INFISICAL_REGISTRY_IDENTITY_ID` (the Infisical machine identities), `MINTLIFY_PROJECT_ID`, `REGISTRY_D1_DATABASE_ID` and `REGISTRY_KV_NAMESPACE_ID`. This repository deploys no console, so it has no public build-time keys; a product names its own (`VITE_SENTRY_DSN` and the like).

Repository **secrets** are empty except two GitHub App credentials that cannot come through Infisical OIDC before the job has a token: `STACKRA_BOT_APP_ID` and `STACKRA_BOT_PRIVATE_KEY` (the release App, `release.yml`), and `LINEAR_AGENT_CLIENT_ID`, `LINEAR_AGENT_CLIENT_SECRET` and `LINEAR_API_KEY` (`linear-sync.yml`).

### Cloudflare Worker bindings

Workers hold their own secrets as bindings, set by their deploy workflow from Infisical, never by hand: `REGISTRY_SIGNING_KEY` on `stackra-registry` (`deploy-registry.yml`, from `/ci/registry`) and `TURBO_CACHE_TOKEN` on the cache Worker (`deploy-turbo-cache.yml`, from `/ci/turbo` `TURBO_TOKEN`). The static Worker has none.

## Tools

Pinned in `mise.toml` ([ADR-0027](/adr/0027-cli-tools-pinned-in-mise)): `node`, `pnpm`, `gitleaks`, `shfmt`, `actionlint`, `zizmor`, `osv-scanner`, `infisical`, `uv`, `maestro` (needs a JDK) and `specify`. Run `mise install` once.

Not pinned (no mise backend carries them; `mise.toml` says so): `opencode`, `encore`, `aws` and `claude`. `wrangler` runs from each Worker's dev dependencies (`pnpm exec wrangler`), and only CI deploys with it. `pnpm doctor` lists what is missing and how to install it.

## Ordered setup

<Steps>
  <Step title="Toolchain">
    Install mise, then `mise install` and `pnpm install`. Confirm with `pnpm verify`.
  </Step>
  <Step title="GitHub (owner)">
    Org `figentra`, repo `stackra`, branch protection on `main`, push protection and secret scanning
    on, squash merge only.
  </Step>
  <Step title="Linear">
    Team `STA` exists. Create a project per deliverable. Agents label their issues `agent`.
  </Step>
  <Step title="Infisical (owner)">
    Create the project in the EU region. Add `/agents` and `/ci`. Create a read-only machine
    identity for `/agents` and one OIDC-trusted identity per CI environment. Run `infisical login`,
    then `infisical init` to write the project id into the tracked `.infisical.yaml` (no secret in
    it).
  </Step>
  <Step title="Developer tokens (human)">
    Add the `/agents` names above in the Infisical UI. `tools/scripts/mcp.sh` reads them for MCP
    servers; nobody prints them.
  </Step>
  <Step title="AWS and Bedrock (owner)">
    Choose the AWS account. Create the profile named `bedrock`, then `aws sso login` with
    `AWS_PROFILE=bedrock`; OpenCode bills Bedrock through it. Create the monthly AWS Budget for
    Bedrock. The daily agent cap is $150 ([Agents](/agents/index)).
  </Step>
  <Step title="Cloudflare (owner)">
    Create the scoped API token and store it in `/ci` as `CLOUDFLARE_API_TOKEN`. Deploy the registry
    and the cache Workers by running "Deploy registry" and the cache deploy workflow (owner runbooks
    in `workers/registry/README.md` and `workers/turbo-cache/README.md`).
  </Step>
  <Step title="Remote cache and registry in CI">
    Set `TURBO_TOKEN` in `/ci/turbo` and `REGISTRY_SIGNING_KEY` in `/ci/registry`. Publishing needs
    no token (GitHub OIDC, [Release](/runbooks/release)); reading `@stackra` needs none either.
  </Step>
  <Step title="Encore Cloud (owner)">
    Create the org and app, connect the AWS account, create environments `staging` and `prod` (PR
    previews are automatic). Do this only once the deploy path (DP2) is decided.
  </Step>
  <Step title="Application secrets (human)">
    For each environment, `encore secret set` every declared name. Verify with `encore secret list`
    (names only).
  </Step>
  <Step title="Email (owner)">
    Add the sending domain in Resend. Add the SPF, DKIM and return-path records and a DMARC record
    in Cloudflare DNS. Create the API key and the webhook.
  </Step>
  <Step title="Observability">
    Sentry org and projects (backend, console, mobile, landing), Better Stack uptime and phone
    alerts, PostHog project.
  </Step>
  <Step title="Mobile (owner)">
    Apple team access, App Store Connect API key, Google Play Console forms and service account, EAS
    project and robot token. The first Play upload is by hand ([Mobile
    release](/runbooks/mobile-release)).
  </Step>
  <Step title="Payments and notifications (owner)">
    Stripe test keys first, live keys at launch. Slack app install and channels. Authorize
    connectors as needed.
  </Step>
</Steps>

## Owner-only steps

These cannot be done by an agent, whatever the brief says:

- Creating any account, accepting any vendor terms, any payment or billing setting.
- Setting, rotating or deleting any secret value, in any store.
- Apple and Google Play console forms, store credentials, the first store upload.
- DNS and Cloudflare token creation; AWS account, SSO and budget settings.
- Infisical identities and OIDC trust; Encore Cloud org and AWS linking.
- Authorizing connectors (Slack) and approving production promotions.

## Daily sign-in

```bash
infisical login
AWS_PROFILE=bedrock aws sso login
```

The first lets `mcp.sh` fetch developer tokens from `/agents`. The second gives OpenCode its Bedrock session. `mise.toml` `[env]` sets `AWS_PROFILE=bedrock`, so `aws sso login --profile bedrock` is enough inside the repository.
