تُستهلك الخدمة عبر عميل يكتبه `stackra gen` من بيان المنتِج الملتزَم به، لا عبر استدعاء `fetch` مكتوب باليد
([القرار 0260](/adr/0260-cross-service-calls-through-injected-clients-and-events)). والبيان نفسه يجعل كل إجراء
موجّه للمستخدم أداةَ MCP، مُرشَّحةً بصلاحيات المستدعي
([القرار 0155](/adr/0155-queries-are-mcp-tools-and-all-ai-code-is-free)).

## العميل المولَّد

يكتب gen مسارًا فرعيًا لكل خدمة مستهلَكة، `#stackra/clients/<service>`، كل صنف فيه باسم منتِجه:

```ts .stackra/gen/clients/commerce.ts (generated)
export class CancelOrderAction extends actionRef("orders.order.cancel@1", {
  input: CancelOrderInput,
  output: CancelOrderOutput,
  http: { method: HttpMethod.Put, path: "/orders/:orderId/cancel" },
  risk: Risk.L2,
  confirm: I18n.orders.actions.order.cancel.confirm,
}) {}
```

ثوابت المرجع هي الاستدعاء: المفتاح، والصلاحية المشتقّة، ومخططا المُدخل والمُخرج، ونقطة النهاية. ولا يُرفض
الاستدعاء إلا بـ`ClientError`: رفضٌ مفكوك أعلنه المنتِج، أو `InputInvalidError` بأخطاء الحقول، أو `TransportError`؛
لا باستجابة خام أبدًا. وعميل الخدمة لخدمة أخرى `ServiceClient` تحقنه الحاوية، فلا تعرف خدمةٌ عنوان خدمة أخرى.

## من مكوّن

```ts
const kpis = useQuery(OrderKpisQuery, { range: TimeRange.Today });
const cancel = useAction(CancelOrderAction, { invalidates: [GetOrderQuery, ListOrdersQuery] });
const result = await cancel.run({ orderId }); // { queued: false, data } أو { queued: true }
```

تحلّ خطّافات `@stackra/clients/react` النقلَ وذاكرة حالة الخادم من الحاوية. والاستعلام ذو `invalidateOn` حيٌّ
يُعاد جلبه مع كل بثّ؛ وذو `replica` متاح دون اتصال. ودون اتصال، يُصفّ الإجراء الذي تسمح به خريطة العمل دون اتصال
ويحلّ `run` بـ`{ queued: true }`؛ ثم يعيد الطابور تشغيله لاحقًا بترتيب الجهاز مع `Idempotency-Key` المسكوك وقت
الصفّ، فلا تُكرَّر كتابة بعد عودة الاتصال.

## الإجراءات أدواتِ MCP

gen هو من يقرّر ما يكون أداة: كل إجراء يستطيع المستخدم تنفيذه، ما لم يعلن `tool: false` مع سطر `// reason:`، وكل
استعلام ([القرار 0360](/adr/0360-the-ai-chain-four-layers-one-spine-approval-modes-and-the-never-bypass-floor)،
البند 4). وتبني البوابة المستضافة جدول أدواتها من البيانات الملتزَم بها بـ`toolTable` من `@stackra/mcp`، ويُسقط
`filterTools` أداةً يفتقر المستدعي إلى صلاحيتها على سجلّه، ويُسقط أداةً أطفأتها مصفوفة صلاحيات الذكاء الاصطناعي هناك،
ويعلّم أداةً لا تشملها خطة المستأجر مقفلةً. ويشغّل استدعاءُ الأداة خطَّ الأنابيب نفسه بصلاحيات المستدعي نفسه؛ ولا
يُضاف شيء باليد.

## الكتابات الخطرة والمعتمِد المسمّى

يحمل واصف الأداة خطورة الإجراء ووسوم أثره. والإجراء الذي تستدعي خطورته ذلك، أو الذي يعلن `approval: true`، لا يلتزم
حتى يصوّت معتمِده المسمّى: تنتظر خطوة الاعتماد في خط الأنابيب `ApprovalGate` المربوطة، ويفشل الإجراء الذي يعلن
الاعتماد مغلقًا من دونها. وكيف يُعلَن معتمِدٌ ثانٍ ومن يشغّل الاستدعاء بعد آخر صوت في [الاعتمادات](/build/approvals).

## MCP للمطوّرين

داخل المستودع يقدّم `stackra mcp` خادم MCP محليًا عبر stdio للمساعد: `manifest` يقرأ البيانات الملتزَم بها بحسب
العضو والقسم، و`new` و`gen` و`validate` و`verify` تشغّل أوامر سطر الأوامر نفسها عبر بواباته. وإعداده في
`.mcp.yaml`، يُصيَّر إلى `.mcp.json` بـ`stackra mcp sync`؛ والخادم الذي يحتاج سرًّا يُبدأ بـ`stackra mcp exec --`،
الذي يسلّم القيمة للعملية من دون أن يقرأها أحد
([القرار 0282](/adr/0282-developer-experience-skills-cli-mcp-and-vellum-as-the-sdlc)).
