## Context

The registry of `@stackra/ui` declares tier `free` for all 360 entries, and `ui-pro` is empty: there is no pro
component, in code or in the registry. The inventory of 2026-11-20 counts 383 distinct components (501 with
compound parts) in 16 packages: 327 in `@stackra/ui` and 56 kit components in the domain packages. 70 link to a
free HeroUI component, and the rest are ours.

Three accepted decisions bound the answer:

- [0469](/adr/0469-stackra-ships-no-heroui-pro-free-heroui-and-stackras-own-components-only) removed HeroUI Pro
  from Stackra. `@stackra/ui-pro` and `@stackra-pro/ui` are withdrawn, and a component that only HeroUI Pro offered
  is built clean-room on free HeroUI, React Aria and permissive libraries.
- [0461](/adr/0461-the-pro-line-for-0-1-0-runtime-free-behind-entitlements-paid-studios-and-advanced-drivers)
  decision 1: nothing moves out of a free package, and `@stackra-pro/*` holds new code only. Every `@stackra/ui`
  component is already published under MIT, and Academorix imports them.
- [0077](/adr/0077-open-core-free-and-pro-lists) decision 4 (a free package never imports a Pro package and works
  fully without one) is the rule any pro tier must keep.

The owner decided on 2026-11-20 that Stackra builds its own pro components on HeroUI community, and the lead's
order asks for a free and pro split by criteria: free is HeroUI pass-through and basic primitives, pro is our
composites (advanced data display, charts, date ranges, blocks, AI, editors).

## Decision

1. **Every component has one tier, `free` or `pro`.** The tier is a required field of the registry entry
   (`ComponentTier` in `packages/design-system/showcase`) and of the component's row in the package manifest. A new
   component is registered with its tier in the same change. Hooks and providers take the tier of their component.
2. **Free criteria.** A component is `free` when any one of these holds:
   - **F1**: it is a thin wrapper over, or a re-export of, a free HeroUI or HeroUI Native component (70 today).
     HeroUI pass-through is free even when the topic sounds advanced: `date-range-picker` and `range-calendar` are
     free for that reason.
   - **F2**: it is a basic primitive: one purpose, no domain logic, no heavy third-party dependency, and an app
     needs it to be a complete app (foundations, fields, selection, feedback, navigation and overlay basics, layout
     primitives, `ai-mark`). It includes the starter charts (`chart`, its legend, tooltip and crosshair, and line,
     bar, area, pie, donut and sparkline), so a free app can draw a dashboard.
   - **F4**: it is a domain kit component that lives in a domain package (`@stackra/identity`, `tenancy`, `iam`,
     `panel`, `payments`, `notifications` and the others). It follows its package, which is free runtime code
     under 0461 decision 1.
3. **Pro criteria.** A component that is none of F1, F2 or F4 is `pro`, in one of these classes:
   - **P1** advanced data display (grids, tables with state, filters, import and export, matrices, timelines);
   - **P2** the chart set beyond the starter charts;
   - **P3** date and time composites (scheduling, recurrence, periods, wheels);
   - **P4** marketing and composition blocks of `@stackra/experience`;
   - **P5** AI surfaces (chat, prompt, drafting, conversation);
   - **P6** editors and builders (rich text, rules, cropping, mentions);
   - **P7** showpiece and heavy interaction composites (morphing, holo and flip cards, command palette, transfer
     list, cascader, floating panels, dashboard grid).
4. **The classification is the attached table.** It lists all 383 components with package, platforms, tier and
   the rule that decided it: 249 free and 134 pro. A change to a row needs this ADR amended, or a later ADR.
5. **Where pro lives (recommended; the lead rules).** For 1.0 the tier is metadata. All 383 components stay in
   `@stackra/ui` and the domain packages, under MIT. The tier shows in the showcase (badge and filter), in each
   API page and in the manifest, and it decides how a new component is documented and where a future split
   would cut. No `@stackra/ui-pro` exists: that name is withdrawn by 0469, and a pro package is `@stackra-pro/*`
   by the scope rule. A physical split, if the owner sells the pro tier, is a new ADR that amends 0461 decision 1
   and picks `@stackra-pro/ui` in `figentra/stackra-pro`, served by the Stackra registry.
6. **A free component never imports a pro component.** A free app works fully without the pro tier, as 0077
   decision 4 requires. The check is a boundary rule between the two tiers inside `@stackra/ui`.
7. **No HeroUI Pro in any tier**, and no pro component derives from HeroUI Pro source
   ([0469](/adr/0469-stackra-ships-no-heroui-pro-free-heroui-and-stackras-own-components-only) decision 2).

## Consequences

- Every registry entry gets a tier and the 28 API docs, 3 code-only components and 12 unlisted exports in the gap
  list are registered with one (step 2 of the lane).
- Under decision 5 the label alone sells nothing. What the pro tier buys (support, entitlement, early access, a
  licence) is a commercial decision this ADR does not make.
- Academorix switches its imports to the published packages with no visual change, because no component moves.
- **Open ruling 1, the home.** Decision 5 (tier as a field, one MIT package) or a physical split now to
  `@stackra-pro/ui`. The split breaks 0461 decision 1, forces a deprecation path for 0.33.x imports and needs
  the private `stackra-pro` repository, which this lane does not touch.
- **Open ruling 2, domain kits.** The 38 domain kit components are free by F4 because 0461 makes runtime code
  free. The lead's wording lists blocks as pro. This table makes only the 17 `@stackra/experience` blocks and
  `chat-surface` pro.
- **Open ruling 3, starter charts.** Ten chart components are free so a free app can draw a dashboard. If
  charts are wholly pro, those ten move to P2.
- A component that needs a different tier is a one-row change plus a changelog line, and a free to pro move is
  a breaking change after publication.

## Enforcement

planned — the `ComponentTier` enum and the `tier` field already exist in
`packages/design-system/showcase/src/schemas/component-entry.schema.ts`; the work is a check that every
`@stackra/ui` export has an entry with a tier equal to this table, and an oxlint boundary rule that a free
component imports no pro component (decision 6). `HERO_LINK` and `PRO_DEPENDENCIES` already refuse HeroUI Pro.
