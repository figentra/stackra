## Context

The registry of `@stackra/ui` declares tier `free` for all 360 entries, and there is no pro component, in code
or in the registry. The inventory of 2026-11-20 counts 383 distinct components (501 with compound parts) in 16
packages: 327 in `@stackra/ui` and 56 kit components in the domain packages. 70 link to a free HeroUI component,
and the rest are ours.

Four accepted decisions bound the answer:

- [0469](/adr/0469-stackra-ships-no-heroui-pro-free-heroui-and-stackras-own-components-only) removed HeroUI Pro
  from Stackra and withdrew the `@stackra/ui-pro` and `@stackra-pro/ui` wrappers of HeroUI Pro. The folder
  `packages/design-system/ui-pro` no longer exists in this repository. A component that only HeroUI Pro offered is
  built clean-room on free HeroUI, React Aria and permissive libraries.
- [0461](/adr/0461-the-pro-line-for-0-1-0-runtime-free-behind-entitlements-paid-studios-and-advanced-drivers)
  decision 1: nothing moves out of a free package. Every `@stackra/ui` component is published today under MIT, and
  Academorix imports them.
- [0077](/adr/0077-open-core-free-and-pro-lists) decision 4: a free package never imports a Pro package and works
  fully without one.
- [0453](/adr/0453-the-stackra-registry-one-npm-compatible-store-on-cloudflare-and-our-own-licence-engine)
  decision 10: the Stackra registry serves a package under a read rule, and a per-name `internal` or licensed row
  can cover one package.

The owner decided on 2026-11-20 that Stackra builds its own pro components on HeroUI community. The lead's final
rulings of the same day: the pro tier is a separate package, the 38 domain-kit components are pro, and the
starter charts are free.

## Decision

1. **Every component has one tier, `free` or `pro`, and the tier follows the package.** A free component lives in
   `@stackra/ui` (MIT, public registry). A pro component lives in `@stackra/ui-pro` at
   `packages/design-system/ui-pro`, and nowhere else. **Pro code never ships in `@stackra/ui`.** The registry
   entry of the showcase gets its `tier` derived from the package that holds the component, not typed by hand;
   `ComponentTier` stays the enum. Hooks and providers take the tier of their component.
2. **No new scope.** The pro package is `@stackra/ui-pro`, not `@stackra-pro/ui`: this restores the folder and the
   name that 0469 withdrew, now for Stackra's own clean-room components only, with no HeroUI Pro in it.
3. **Private registry only.** `@stackra/ui-pro` publishes to the Stackra registry
   (`https://npm.stackra.figentra.com/`) and never to npmjs. The registry serves it under a licensed read rule as
   a per-name row (0453 decision 10), so a customer without a grant cannot install it. It carries its own
   `LICENSE` and a `"license"` field that names it.
4. **Free criteria.** A component is `free` when any one of these holds:
   - **F1**: it is a thin wrapper over, or a re-export of, a free HeroUI or HeroUI Native component (70 today).
     HeroUI pass-through is free even when the topic sounds advanced: `date-range-picker` and `range-calendar` are
     free for that reason.
   - **F2**: it is a generic primitive: one purpose, no product logic, no heavy third-party dependency, and an
     app needs it to be a complete app (foundations, fields, selection, feedback, navigation and overlay basics,
     layout primitives, `ai-mark`). It includes the starter charts: `bar-chart`, `line-chart`, `area-chart` and
     `pie-chart`, with the chart building blocks they stand on (`chart`, `chart-legend`, `chart-tooltip` and
     `chart-crosshair`), so a free app can draw a dashboard.
5. **Pro criteria.** A component that is neither F1 nor F2 is `pro`, composed and product-grade, in one of these
   classes:
   - **P1** advanced data display (grids, tables with state, filters, import and export, matrices, timelines);
   - **P2** every chart beyond the starter charts, including `donut-chart` and `sparkline`;
   - **P3** date and time composites (scheduling, recurrence, periods, wheels);
   - **P4** marketing and composition blocks of `@stackra/experience`;
   - **P5** AI surfaces (chat, prompt, drafting, conversation);
   - **P6** editors and builders (rich text, rules, cropping, mentions);
   - **P7** showpiece and heavy interaction composites (morphing, holo and flip cards, command palette, transfer
     list, cascader, floating panels, dashboard grid);
   - **P8** the 38 domain-kit components of the domain packages (identity, tenancy, iam, panel, payments,
     notifications, settings, ai and the others): composed product patterns over the free runtimes.
6. **The classification is the attached table.** It lists all 383 components with where each lives today, its
   platforms, its tier and the rule that decided it: 209 free and 174 pro (118 now in `@stackra/ui`, 56 now in
   domain packages). A change to a row needs this ADR amended, or a later ADR.
7. **A free package never imports `@stackra/ui-pro`.** `@stackra/ui` and every domain package work fully without
   it (0077 decision 4). A pro kit component is a view over the hooks and contracts that its free domain package
   keeps; the domain package imports nothing from `@stackra/ui-pro`. The check is a boundary rule in
   `packages/tooling/oxlint/src/boundaries.jsonc`.
8. **No HeroUI Pro in either tier**, and no pro component derives from HeroUI Pro source
   ([0469](/adr/0469-stackra-ships-no-heroui-pro-free-heroui-and-stackras-own-components-only) decision 2).
9. **Amendments on acceptance.** This ADR amends 0461 decision 1 (the 118 and 56 components above leave the free
   packages) and 0469 decision 1 for the folder and name `@stackra/ui-pro`, which now holds Stackra's own
   components only. 0469's ban on HeroUI Pro stands.

## Consequences

- **A breaking move, carried by the 1.0 major.** The 174 pro components leave `@stackra/ui` and the domain
  packages. A consumer imports them from `@stackra/ui-pro` and needs a registry grant. The 1.0 release ships a
  migration note with the old and new import for every moved component. Academorix switches its imports to the
  published packages with no visual change, and adds the pro package.
- Every registry entry gets its tier from its package. The 28 API docs, 3 code-only components and 12 unlisted
  exports of the gap list are registered in the right package (step 2 of the lane).
- Domain packages keep their runtime, hooks and contracts, and lose their components. A route page in a free
  package that needs a pro component takes it by prop or slot, never by import.
- **Open point, source visibility.** The lead's ruling keeps the pro source in this repository, whose licence is
  MIT, while 0077 decision 3 puts pro source in a private repository. The folder carries its own commercial
  `LICENSE` and the published `dist` is minified without source maps, as 0316 decision 2 describes. The owner
  confirms this, or the source moves to `figentra/stackra-pro`.
- **Open point, `@stackra/` under a licensed rule.** The registry rule of 0453 decision 10 is per scope today;
  a per-name licensed row inside `@stackra` is new work for the registry session.
- The label buys what the commercial ADR says it buys; this ADR makes no pricing claim.
- A free to pro move after publication is a breaking change, so a tier change is a one-row edit here plus a
  major or a changelog line.

## Enforcement

planned — a check that every `@stackra/ui` and `@stackra/ui-pro` export has a registry entry whose tier equals
the package and the table; the boundary rule of decision 7; the registry read rule of decision 3. Already in
force: `HERO_LINK` in `packages/design-system/showcase/src/schemas/component-entry.schema.ts` and
`PRO_DEPENDENCIES` in `@stackra/repo-checks` refuse HeroUI Pro.
