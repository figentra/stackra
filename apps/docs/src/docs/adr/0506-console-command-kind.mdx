## Context

The three CLIs of [0500](/adr/0500-four-clis-stackra-runway-vellum-and-figentra) (`stackra`, `runway`, `figentra`) are
hand-built: each parses its own arguments, prints its own help and errors, and styles its output its own way. There is
no shared command framework, and no declared shape for a command that a package could expose. ADR 0294 decision 23 says
"Command means a CLI command only", but the kind table has no row for one. ADR 0127's 2026-10-24 note folded a `console`
package into `cli` on that reading, which put every command inside one CLI package. The basalt port of
`@stackra/console` (Academorix spec 030) used a provider API (`defineConsoleCommand`, string tokens) that v3 retires
([0145](/adr/0145-tokens-are-define-token-values-and-global-helpers-are-banned), [0294](/adr/0294-programming-model-v3-grammar-folders-identities-and-naming)
decision 17). Commands need the v3 shape: a class, decorated fields, constructor collaborators, and a folder of their own.

## Decision

### The kind

1. **`Command` is a kind.** A CLI command is a class that extends `Command({ name, description, hidden?, aliases? })`
   from `@stackra/console`. Its name and aliases are written once, each made of `[a-z0-9]` segments joined by `-`, and
   the segments joined by `:` (`tenant:seed`). The kind options are read without constructing the class, as every kind's
   are. `hidden` keeps a command out of the list; it still runs by name.

   ```typescript
   export class SeedTenantCommand extends Command({
     name: "tenant:seed",
     description: "Seed a tenant",
   }) {
     constructor(private readonly tenants: TenantService) {
       super();
     }

     async handle(io: CommandIo) {
       io.output.success("Seeded");
       return 0;
     }
   }
   ```

2. **A command is a binding.** Its collaborators come in through its constructor, and gen (or the caller's container)
   builds it ([0294](/adr/0294-programming-model-v3-grammar-folders-identities-and-naming) decision 17). `handle(io)`
   runs it and returns an exit code from 0 to 255, nothing, or an object or array that becomes the `--json` data.

3. **Fields carry the arguments and options.** `@Argument(options?)` binds a field to the next positional token, in field
   order. `@Option(options?)` binds a field to `--<kebab-name>`, and to `-<short>` when `short` is given. Both are field
   decorators made with `createDecorator` that target the `command` kind only
   ([0294](/adr/0294-programming-model-v3-grammar-folders-identities-and-naming) decision 6). The value kind comes from
   `@Str`, `@Int`, `@Num` or `@List` of `@stackra/validation`, whose `SHAPE_KINDS` already includes `command`. A field
   with none of them is a boolean option, or a string argument. A field's default is its initialiser. An argument with
   no default is required unless it is `@Argument({ optional: true })`, because the runtime cannot see a `?` without
   gen. A `@List` argument comes last and takes the rest.

4. **The `commands/` group.** A command file sits in `commands/`: in a module (a service's `src/modules/<key>/commands/`),
   in a package's `src/node/commands/`, and in an app's `src/commands/`. The file is `<name>.command.ts`, its class is
   `PascalCase(stem) + Command` (`greet.command.ts` declares `GreetCommand`), one class per file, and its test sits
   beside it in `__tests__/` ([0022](/adr/0022-tests-live-in-tests-folders)).

### The framework and its look

5. **`@stackra/console` is the framework.** Its package is `packages/developer/console` (`@stackra/console`, `tier:lib`,
   category `developer`, runtimes `isomorphic` and `node`). It holds the `Command` kind, its two decorators, the kernel
   (`createConsole`), the output, the prompts, the testing harness and the themes. It is the framework and the terminal
   look of the three CLIs of 0500. It holds no module's commands: each package exposes its own, from its own `commands/`
   group (phase 2, STA-1731). It depends on `@stackra/container`, `@stackra/contracts` and `@stackra/validation`, and never
   on `@stackra/gen`. Its own bin, `stackra-console`, has one command, `create`, which writes a standalone console app.

6. **Registries.** A standalone app passes its commands to the kernel: `createConsole({ name, version, commands: [...] })`.
   A member that runs gen gets `#stackra/commands`, an explicit list of static imports that gen writes from the
   `commands/` groups it uses, with duplicate names and aliases refused at gen time, naming both classes. Nothing scans
   at runtime. gen is never a runtime or peer dependency of `@stackra/console` or of a package that ships commands.

7. **One presentation.** Every product shares one layout (the gutter, the symbol column, dotted task lines, rounded
   boxes, one error screen). A product changes only its theme: the name, the ASCII logo, the gradient, the accent, the
   glyph and the ASCII glyph. The rules below hold for every CLI:
   - Colour is off under `NO_COLOR`, `CI`, `--no-ansi`, a non-terminal stdout and `TERM=dumb`; `--ansi` and `FORCE_COLOR`
     turn it on against those. With colour off, nothing is written but text, and boxes are drawn in ASCII.
   - Prompts are asked only when stdin and stdout are terminals, `CI` is empty, and neither `--no-interaction` nor
     `--json` is given. Otherwise a prompt takes its default, and a prompt with no default fails the run with exit code 2
     and names the option that answers it.
   - `--json` writes exactly one document to stdout: `{ "ok": true, "data": ... }`, or
     `{ "ok": false, "error": { "code", "message" } }` where the code is the error's class name in snake case without
     `Error`.
   - Widths are measured by grapheme cluster. Characters are never reordered, and the components write no FSI/PDI
     isolates (many terminals draw them as boxes); `isolateBidi` is offered for callers. On a terminal without bidi or Arabic shaping (`TERM_PROGRAM` claude-desktop, vscode, iTerm.app, Hyper, Tabby), right-to-left runs are written shaped and in visual order; `STACKRA_BIDI=visual|logical` overrides the choice, and pipes and `--json` always get logical text.

8. **Prompts are ours.** The prompter runs on `node:readline` in raw mode, and colours come from `node:util`
   `styleText` with two escape helpers for 256 and true colour. No new dependency is added. Basalt's `@clack/prompts`
   is not carried over.

9. **Themes.** `ConsoleTheme` is `{ name, logo, gradient, accent, glyph, asciiGlyph }`. `@stackra/console` ships
   `STACKRA_THEME` only. `themeFromBrandTokens(tokens, choice)` builds a theme from a brand kit's colour tokens, so
   `runway` and `figentra` build theirs from brand tokens they already pull. The package depends on no brand package.

## Consequences

- A command lives in the package that owns its capability, and the framework adds no domain dependency.
- Two command shapes exist for a while. `@stackra/cli` keeps its `CliCommand` data shape until it moves onto
  `@stackra/console`, which `.agents/specs/sta-1730-console/adoption.md` plans. STA-1730 migrates no CLI, so
  [0500](/adr/0500-four-clis-stackra-runway-vellum-and-figentra) decision 7 (output is kept) holds.
- A command's constructor must only store its collaborators. The kernel builds a throwaway instance with no arguments to
  read the field defaults; if the constructor throws, the reader catches it and reads no defaults, so the options keep
  their `undefined` values silently.
- A standalone app has no `.stackra/` and passes its registry. A gen member gets its registry from gen. Both paths
  reach one kernel.
- `@stackra/console` is a new free package on the Stackra registry (ADR 0453).

## Enforcement

- `packages/developer/console/src/core/functions/read-command.function.ts` refuses a bad declaration (a name outside the
  form above, a required argument after an optional one, two fields with one flag, a global option's name) with
  `ConsoleDeclarationError`, when `createConsole` runs and before any command runs.
- `packages/developer/console/src/core/functions/build-registry.function.ts` refuses two commands that claim one name or
  alias, with `DuplicateCommandError`.
- planned — the unit tests of those refusals, under `packages/developer/console/src/core/**/__tests__/` (spec SC-002).
- planned — STA-1731: the gen collector `emit-commands` refuses duplicate names at gen time and writes
  `.stackra/gen/commands.ts`.
- planned — STA-338: the validator's `kind-path` check for `commands/` and `.command.ts`, and `base-matches-suffix`
  for the `Command` base.
- planned — oxlint `unicorn/filename-case`, for kebab-case command files.

## Amendment 2026-11-02 (owner decision): one CLI engine

The owner, 2026-11-02 (Linear STA-1966): "one package that all depend on, so we can guarantee the output and
everything", and on `fflow` 0.2.3, "very bad error handling; show it in a table, highlight stuff". The spec is
`.agents/specs/sta-1966-console-engine/` (approved by the leader 2026-11-02).

1. **Ports and drivers (amends decision 5).** The engine reaches its side effects through four ports, abstract classes
   in `src/contracts/ports/`, and a command or the kernel is unchanged when a driver is swapped:
   - `Renderer`: banner, messages, title, key-value, list, table (with a status column), checklist (grouped rows of ok,
     warn, fail, skip and info, with a summary line that sets the exit code), tree, box, problem (the error screen),
     help, command list, task, spinner, progress and live view. Drivers: `text` (the default) and `ink`, for live parts
     only, loaded by a dynamic import the first time a live part animates, with the `text` driver as its fallback.
   - `Prompter`: drivers `clack` (the interactive default), `terminal`, `defaults` and `scripted`.
   - `Completions`: bash, zsh and fish scripts and Tab answers from the registry. Driver: `tab`.
   - `ProcessRunner`: child processes with their output captured; a failed step shows its last 20 lines, the whole
     output only under `--verbose`; an interactive child inherits the terminal and is refused without one.
2. **Dependencies (amends decision 8).** `@clack/prompts`, `@bomb.sh/tab` and `ink` (with `react` from the `frontend`
   catalog) are allowed, pinned exactly in the catalog, and only behind the ports above (owner approval 2026-11-02,
   STA-1966). The `terminal` prompter stays as a driver. No other third-party dependency is added without the owner.
3. **Routing.** An argument vector routes to one intent (list, help, version, completion, run or unknown) before any
   container exists. `--help`, `-h` and `help <cmd>` never run the command. An unknown command names up to three
   closest commands and exits 2. Spaced names (`mcp sync`, `bot gh`) match the registered `:`-joined names, longest
   first. `help` and `completion` are built in.
4. **One error shape (amends decision 7).** Every failure renders as one boxed problem: what failed, why, the fix
   command and a docs link; the cause chain and raw child output only under `--verbose`. The `--json` error gains
   optional `why`, `fix` and `docs`. A run that ends with a non-zero code and no thrown error writes
   `{ "ok": false, "data": ... }`, so a command can emit its data and set its exit code together.
5. **Status is never colour alone.** A status cell always carries a symbol and a word (`✓ ok`, `⚠ warn`, `✗ fail`; in
   ASCII `+ ok`, `! warn`, `x fail`).
6. **One definition, three surfaces.** What `readCommand` reads (now with `group`, `docs`, `examples`, `tool` and a
   field's `prompt` and `choices`) gives the parser, the help, the completions and, for a command with `tool: true`, a
   local developer MCP tool: a JSON Schema of its fields and an invoke function that runs the same kernel with `--json`
   and returns its data as structured content. `@stackra/mcp`'s local tools come from these definitions
   ([0282](/adr/0282-developer-experience-skills-cli-mcp-and-vellum-as-the-sdlc) decision 5). A console command never
   reaches the tenant MCP gateway of [0155](/adr/0155-queries-are-mcp-tools-and-all-ai-code-is-free).
7. **Actions as commands.** An action or query opts in with a `command` option
   ([0305](/adr/0305-programming-model-v3-1-names-partners-files-and-class-components) rule 28); gen adds it to
   `#stackra/commands`, and `ActionCommand(ActionClass)` in `@stackra/actions/node` prompts for missing input fields from
   the input schema, runs the one pipeline and presents the typed output. The actor is the signed-in CLI identity, never
   a privileged operator by default; the operator and break-glass ports apply only where the action allows them, and
   every refusal of the pipeline renders as a problem. `@stackra/console` never depends on `@stackra/actions`.
8. **Every Figentra CLI depends on it.** `stackra`, `fflow` (Figentra Flow) and `figentra` run on `createConsole`.
   This reverses the STA-1730 rule that Figentra Flow never depends on `@stackra/console`
   (`.agents/specs/sta-1730-console/flow-visual-spec.md`); Flow is published on the Stackra registry, so its install
   path is unchanged. The CLI layers of Flow and `figentra` move to TypeScript, because Node runs no decorators.

Enforcement: the unit tests of `@stackra/console` (a snapshot of every renderer component with colour on and off, the
routing table, completion golden files, one command giving equal data through the CLI, the local MCP and the test
harness, and a module-load test that a non-live run never imports `ink`); `FORBIDDEN_DEPENDENCIES` is unchanged.

## Amendment 2026-11-03: frozen JSON, shared streams, routing (STA-2093)

The testbed of [0522](/adr/0522-testbed-own-repo) must print its frozen `--json` documents (decision 5) and stream a job's
output to the terminal. The engine of 2026-11-02 could do neither: `--json` wrote the envelope, and a child was either
captured or interactive. This amendment adds what the port needs, in four parts. Bare JSON, `inherit` and
`requireCommand` are opt-in, so an existing command, test and `--json` document keeps its output. Three changes reach
every console: `onOutput` receives redacted chunks (item 2), a child that shares the terminal is refused while the run
holds a secret (item 2), and a value option may come before the command name (item 4). The spec is
`.agents/specs/sta-1966-console-engine/`, where FR-007, FR-012, FR-015 and FR-028 each carry a dated note. The text
describes the code of `packages/developer/console` as of the STA-2093 pull request.

1. **Bare JSON (amends decision 7 and item 4 of the 2026-11-02 amendment).** `ConsoleConfig.json` is `"envelope"`
   (the default, decision 7) or `"bare"`. Under `--json` with `"bare"`:
   - a run that ends with an error writes nothing to stdout; the problem screen goes to stderr, and the exit code is the
     error's, as before;
   - a run that ends with no error writes its data alone, as one compact line, whatever the exit code. The data is the
     first that is set, in this order: the value given to `io.output.json`; else the value the handler returned (an
     object, an array or `null`, never an exit code); else the rows of a table or checklist. The intents that run no
     command set it themselves: `--version` the object `{ name, version }`, the list the visible command structures,
     help the command's structure, and `completion <shell>` the object `{ shell, script }`. An explicit `null` is
     written as `null`; a run with no data writes nothing;
   - human output (lines, tables, the problem screen, and the child output that `-v` echoes) goes to stderr, drawn as
     without `--json`: no colour and no animation.

   `bare` is for a CLI whose `--json` shape an ADR has frozen, and only testbed qualifies today (0522 decision 5). Every
   other CLI keeps the envelope; [0500](/adr/0500-four-clis-stackra-runway-vellum-and-figentra) decision 7 governs any
   move of its output.

2. **Shared standard streams (amends item 1 of the 2026-11-02 amendment).** `ProcessRunOptions.inherit` is
   `boolean | "stderr"`.
   - `inherit: true` shares the standard streams: the child's output is live, is not captured and is not redacted, and the
     child is never refused for want of a terminal. Under `--json` the console turns it into `"stderr"`.
   - `inherit: "stderr"` ignores standard input and sends both of the child's outputs to standard error.
   - `io.process` refuses an inherited or interactive run with a `CommandError`, before the child starts, while a secret
     option or argument of the run holds a non-empty value (each value of a list, and a number by its digits), because
     the child's output cannot be redacted. The same values are redacted from captured output.
   - `interactive` otherwise is unchanged: the child inherits the terminal and is refused without one (STA-1966
     FR-028). With both set, `inherit: "stderr"` wins, so stdout stays clean.
   - `onOutput` receives the redacted chunk. It received the raw chunk before.

   Known limit: redaction runs per chunk, so a secret split across two chunks escapes into the `-v` echo and into
   `onOutput`. The upgrade is to buffer whole lines before redaction.

3. **`secret: false` (amends STA-1731 FR-016).** `isSecret` lets an explicit `secret` decide. `secret: false` keeps an option
   or argument whose name ends in a `SECRET_FIELD_SUFFIXES` entry (`key`, `url`) out of the secret set. A field that declares
   no `secret` is still judged by its name, and `secret: true` still holds. The secret set decides the password prompt, the
   redacted tokens in an error and the redacted values in an audit entry, so `secret: false` changes all three for that
   field.

4. **Routing (amends item 3 of the 2026-11-02 amendment).**
   - `ConsoleConfig.requireCommand` (default `false`). When `true`, an invocation that names no command and asks no help
     (`help`, `--help`, `-h`) is a usage problem, "Name a command", and exits 2. `--version` is unchanged, and the default
     still lists the commands.
   - A registry value option may come before the command name in its separate-token form (`acme --box 2 ssh`). The console
     decides this from the registry: a flag takes a value there only when every command that declares it gives it a value.
     A flag that is boolean in any command takes none, so the next token is read as the name. `--box=2` is one token and was
     always accepted. A value option at the very end of argv takes no value, and the parser reports it.

5. **Consequences.**
   - ADR 0522 decision 5 holds byte for byte. This amendment writes no testbed document: the `run` and `status` documents
     come from testbed's own port, under its own frozen-interface tests.
   - Routing changes in two ways. A value option before the name, which previously failed, now runs. And the token after
     such a flag is now its value: `cli --out deploy ./dist` used to run `deploy` with `--out=./dist`, and now reads
     `deploy` as the value and `./dist` as the name. Every other invocation routes as before.
   - Whether other CLIs move their `--json` to the envelope is not decided here.

6. **Enforcement.** The unit tests of this amendment are the bare, `requireCommand`, value-option and `secret` cases of
   `packages/developer/console/src/core/functions/__tests__/` (`create-console`, `route`, `split-invocation`, `is-secret`
   and `create-process`), and the `inherit: "stderr"` case of
   `packages/developer/console/src/node/drivers/__tests__/node-process-runner.driver.test.ts`.
   - planned — in testbed's port (its own change, in figentra/testbed): the frozen-interface tests that `run --json` and
     `status --json` print the documents of [0522](/adr/0522-testbed-own-repo) decision 5.
   - planned — buffered line redaction, the upgrade named in item 2.
