## Context

The owner asked for a full code-conventions standard on 2026-10-20 and locked the first five rules (mem L378–381, conv Q1–Q5).
The rest of the proposal (constants, utilities, hooks, providers, contexts, JSDoc and no inline types) was not decided one
by one. Those rules are recorded here as assumed, so they are visible and not treated as in force.

## Decision

1. **Enums.** A const object plus a same-named union type, in `<name>.enum.ts`. The `enum` keyword is banned everywhere.
2. **Components.** Always a folder: `x/{x.tsx, index.ts, __tests__/x.test.tsx}`. `XProps` is exported from the component
   file, and it is the one allowed companion export. `*.stories.*` files are banned (no Storybook).
3. **Classes.** Use the `private` keyword. `#private` is banned. Injected dependencies are `private readonly`.
4. **Kind folders.** When a module has two or more files of one kind, they move into a kind folder: `interfaces/`, `types/`,
   `constants/`, `tokens/`, `errors/` or `decorators/`. The suffix vocabulary of audit 3.1 is frozen.
5. **Withdrawn 2026-10-21 (STA-219).** This decision was originally recorded as assumed, not in force. It is replaced by the
   numbered decision 5 of the amendment below (with decisions 6 and 7). There is one decision 5; this item is kept only so the
   record shows what changed.

## Consequences

- Existing components and enums move to the folder and const-object shapes when they are next touched. There is no
  mass rewrite.
- Test files for components sit under `__tests__/` next to the component (AGENTS.md test placement).
- The component, hook and context scaffolds in `tools/scaffold` must produce these shapes.

## Enforcement

planned — house oxlint rules `no-enum`, `no-hash-private`, `hook-file-name` and `member-order` (see
[0129](/adr/0129-house-lint-plugin-and-coding-standard)). The folder shapes are planned for the validator.

## Alternatives

- Keep TypeScript `enum`: rejected by the owner (Q1).
- Storybook for component review: rejected by the owner (Q3). A revival would need a new ADR.

## Amendment 2026-10-21: decision 5 numbered; hooks and utilities (STA-219)

**Context.** Decision 5 listed the code-conventions rules as assumed. [0268](/adr/0268-register-answers-thin-items-r1-to-r18)
(R1) put them in force, and the owner settled the two places that were still open: where a hook lives, and what `utils/` is.
The original decision 5 is withdrawn above. Its rules are now the numbered decisions 5 to 7 below, and these are the only
decisions 5 to 7 of this page.

**Decision.**

5. **Hooks.** Two kinds, two places, neither a shared `hooks/` folder for React hooks:
   - `hooks/` holds extension hook files only, named `<name>.hook.ts` ([0264](/adr/0264-declaration-vocabulary-module-keys-define-family-and-kind-folders)
     decision 7, [0265](/adr/0265-hook-points-transform-and-verify)).
   - A React hook is a file `use-<name>.ts` that exports `use<Name>`, placed beside the component that owns it. A hook used
     by more than one component of the same package is placed beside the first and imported by path, never copied.
     This replaces the shared `hooks/` folder of the proposal's section 4 for React hooks.
6. **Utilities.** There is no `utils/` folder. A shared helper moves to `@stackra/support`, as [0006](/adr/0006-naming-exports-and-imports)
   (amendment 2026-10-21) now says.
7. **The other rules in force.** Constants, providers, contexts, JSDoc and the no-inline-types rule stay as
   [0268](/adr/0268-register-answers-thin-items-r1-to-r18) put them in force. The hook placement in the proposal's section 4 is
   superseded by decision 5 above.

**Consequences.**

- An agent looking for a React hook opens the component's folder, not `hooks/`.
- The `hook-file-name` lint rule of [0129](/adr/0129-house-lint-plugin-and-coding-standard) matches this: a file that exports a
  `use*` function is `use-*.ts`, and a `.hook.ts` file exports an extension hook point.

**Enforcement.** planned — the house lint rule `hook-file-name` (oxlint plugin, ADR 0129) and the kind-folder checks named in
[0130](/adr/0130-module-layout-by-semantic-kind) (amendment 2026-10-21). Nothing checks this today.
