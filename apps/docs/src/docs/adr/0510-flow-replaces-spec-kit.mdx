## Context

ADR 0067 made GitHub spec-kit the SDLC, and ADR 0121 D15 pinned its CLI. ADRs 0282 and 0286 planned a
Stackra-owned SDLC tool to replace it only if spike STA-298 met a bar, for example at most 15 extra minutes per
issue. That spike measured the legacy tool's signed approvals and ledger, which are now dropped. Since then Figentra
Flow (`@figentra-oss/flow`, binary `figentra-flow`) wraps spec-kit: it installs `.specify/`, composes our preset into
spec-kit's command texts, renders them with the `specify` binary and polices the result with a tripwire. Our
templates already replace spec-kit's; the wrap mostly guards against an upstream we do not need. On 2026-11-01 the
owner decided that Flow replaces spec-kit entirely and that the name "Vellum" is removed everywhere, and accepted
every recommendation of the questionnaire (the owner's questionnaire).

## Decision

1. **The spike bar is waived.** The replacement keeps today's commands, documents and gates; only who owns the
   files changes, so there is nothing new to measure. STA-298 closes on this ADR.
2. **Flow owns the whole workflow.** Nothing runs the `specify` binary. Flow ships the templates, the presets
   (`neutral`, `stackra`), the eight command texts and the work the spec-kit scripts did, as CLI subcommands
   (`figentra-flow spec paths|setup-plan|setup-tasks|template`).
3. **Names.** `.specify/` becomes `.flow/`; the presets folder `speckit/` becomes `flow/` inside the package; the
   `speckit-*` skills and commands become `flow-*` (`/flow-specify`, `/flow-clarify`, `/flow-plan`, `/flow-tasks`,
   `/flow-analyze`, `/flow-checklist`, `/flow-implement`, `/flow-converge`), spelled with a hyphen in every tool.
   `taskstoissues` folds into `flow-tasks`; `constitution` is dropped. `.agents/specs/` stays. "Vellum" is retired
   as a name.
4. **`.flow/` holds only what the repository owns:** `README.md`, `constitution.md`, optional `overrides/`,
   `lock.json` (the Flow version, the preset and a hash of every rendered file) and the git-ignored `current.json`.
   Presets live only in the package; a repository chooses one with `preset` in `figentra-flow.config.json`.
5. **Bug specs** live in `.agents/specs/bugs/<key>-<slug>/` (configurable as `specs.bugsDir`).
6. **Rendering.** `figentra-flow sync` writes neutral skill and command documents for the repository's projector;
   `sync --direct` renders Claude Code skills and OpenCode commands itself. Rendered files are committed.
7. **The install check replaces the tripwire.** `figentra-flow gate ci` fails when a rendered file differs from
   `lock.json`, when `lock.json` names another Flow version than the installed one, or when `.specify/`,
   `.agents/speckit/` or a `speckit-*` file remains.
8. **Migration.** `figentra-flow migrate [--dry-run]` rewrites the mechanical files of a repository that used
   spec-kit. After it, nothing reads `.specify/`.
9. **Attribution.** spec-kit is MIT-licensed by GitHub. The package carries spec-kit's notice in
   `THIRD_PARTY_NOTICES.md`; every template or command derived from spec-kit carries
   `derived-from: github/spec-kit 1.0.10 (MIT)` until it is rewritten from scratch.
10. **Release and rollout.** The replacement ships as `@figentra-oss/flow` `0.2.0`, after the `0.1.0` wrap. Core
    switches on one train with waves W2 and W2b, then brand, os and the template follow; stackra-8a gates each step.

## Consequences

- No pinned Python tool (`pipx:specify-cli`) and no bash scripts in any repository; the spec workflow is one npm
  package.
- Flow's team owns texts that upstream used to maintain. Upstream improvements are no longer picked up
  automatically; that is the point.
- Core's 24 docs pages, live specs, hooks (`prompt-hints`, `_rules.mjs`) and the `spec-writer` agent change in the
  switch; open branches re-run `figentra-flow migrate` after a short freeze.
- ADR 0067's spec-kit and ADR 0121 D15's pin are history.

## Enforcement

- `figentra-flow gate ci` (the install check, decision 7) in every repository that runs the gate.
- planned — `@stackra/repo-checks`: `.flow/` replaces `.specify/` in the format rules (core phase 2).
- planned — `doctor.mjs` drops the `specify` pin check; `mise.toml` loses `pipx:specify-cli` (core phase 2).

## Amendment 2026-11-04: presets are packages, and questions use each tool's own UI (STA-2097, STA-2098)

The owner, 2026-11-04: Figentra Flow is sold to anyone, so Stackra's preset moves out of Flow into a package Stackra
owns; and Flow should ask the user its questions with each tool's own question UI and work the same in Claude Code,
OpenCode, VS Code and the rest. Today `/flow-clarify` asks in plain chat text everywhere. The plan is stackra-notes
`src/plans/flow-e2e/PLAN.md`, sections 9 (P0 to P6) and 10 (H0 to H6); this amendment is P0 and H0.

### Presets are packages (amends decisions 2 and 4)

1. **A preset is an npm package.** `flow.config.json` `"preset"` names a built-in preset (`neutral`) or a package
   (`"@stackra/flow-preset"`). Flow resolves the package from the repository root and reads the folder that its
   `package.json` names in `"flow": { "preset": "./preset" }`; the folder has the bundled presets' layout. A name
   resolves as a built-in, then an installed package, then a folder of the repository.
2. **No auto-patching on install.** A preset package has no postinstall: pnpm blocks lifecycle scripts by default,
   and a preset ships guard code (`guard/*.mjs`), so Flow loads code only from the preset the configuration names.
   `fflow preset add <pkg>` installs the package as a dev dependency and writes the configuration line in one step.
   An upgrade is a package upgrade, then `fflow update`, which shows the diff before it adopts the new content.
3. **Compatibility is declared and checked.** A preset declares the Flow versions it runs on in `peerDependencies`
   (`@figentra-oss/flow`) and in `preset.yml` `requires.flow`. `fflow doctor` fails its `preset` row, and `sync` and
   `update` refuse to render, when the installed Flow is outside either range. A preset's guard tables import only
   `node:` built-ins, their own folder and Flow's public `@figentra-oss/flow/guard` and
   `@figentra-oss/flow/guard/neutral` entries.
4. **Flow keeps only `neutral`.** Decision 2's bundled `stackra` preset moves to `@stackra/flow-preset`, a core
   package at `packages/developer/flow-preset` released with core's changesets. The Stackra repositories switch
   `"preset": "stackra"` to `"@stackra/flow-preset"` (P3); after that, Flow drops `presets/stackra` and bundles
   `neutral` alone.
5. **Third-party skills are not vendored** (owner default O9). A preset lists each one by source and licence
   (`third-party.yml`), and `sync` installs it pinned to a commit and a folder digest.
6. **A Claude Code marketplace comes later (P6).** figentra/flow will publish `.claude-plugin/marketplace.json` with
   the neutral `flow-*` skills for teams that do not use npm; the npm package stays the source of truth. This is the
   later plugin that [0500](/adr/0500-four-clis-stackra-runway-vellum-and-figentra) decision 11 left open.

### Questions through each tool's own UI (amends decision 6)

7. **Templates name capabilities, not tools.** A command text or template marks a step with a capability (`ask`,
   `todo`, `docs`, `subagent`) instead of naming a tool.
8. **A harness adapter per tool** fills each capability in when the commands are rendered, as the tracker adapters do
   for trackers. Claude Code renders `ask` as its question tool, AskUserQuestion (up to four questions of two to four
   options, the recommended option first). OpenCode uses its question tool where it has one, and the text table
   otherwise. VS Code (Copilot), Cursor and Codex get prompt files in their own folders, with the text table. The
   fallback in every tool is today's text table. What each tool supports is checked before its adapter is built.
9. **An `fflow mcp` server** carries what must behave the same in every tool. It has one writer, which records a
   clarification (an answer into the spec's Clarifications section); its other tools only read: the open questions
   and a lookup in the project's docs. It uses MCP elicitation, a form shown to the user, where the client supports it.
10. **Asynchronous questions go through the tracker.** For an agent that runs unattended, the question goes to the
    tracker issue (Linear or GitHub Issues), the spec gets a "needs clarification" marker, and work resumes on the
    answer.
11. **The spec is the record.** Every question and answer lives in the spec, never only in a chat tool.
12. **Flow owns the rendering into each tool's folders.** Decision 6's projector step goes: `sync` renders each
    tool's own files itself, and core's `.agents` sync script is deleted once it does (H6, after P3).

### Consequences

- Stackra's agents, rules, skills and guard tables change in core and reach a repository as a package release it
  adopts with `fflow update`; Flow releases no longer carry Stackra content.
- A Flow major needs a preset release that widens `requires.flow` and the peer range before repositories upgrade.
- The guard tables' tests have to move into core with the preset before Flow drops its copy (P3); until then Flow's
  tests cover the bundled copy only.
- A command reads the same in every tool; only the adapter differs, and the text table never goes away.

### Enforcement

- figentra/flow: preset resolution by package name, `fflow preset add` and the range checks of `doctor`, `sync` and
  `update`, with their tests (P1, figentra/flow #124).
- planned — the `@figentra-oss/flow/guard` entries (figentra/flow #130) and core's `packages/developer/flow-preset`
  (P2).
- planned — P3: the ten Stackra repositories name `@stackra/flow-preset`, then Flow drops `presets/stackra`.
- planned — H1 to H6 (STA-2098): the capability markers and adapter interface with the text fallback, the Claude Code,
  OpenCode, VS Code, Cursor and Codex adapters, `fflow mcp`, tracker questions, and the removal of core's `.agents`
  sync.
