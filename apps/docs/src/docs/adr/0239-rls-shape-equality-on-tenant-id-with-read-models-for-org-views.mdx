## Context

Each tenant owns its rows, and an organisation needs views across its children: consolidated billing, organisation reporting and parent operators. Row-level security could express the tree directly, but that puts tree logic in every policy and makes every query on a business table pay for it. The owner's answer (mem L931, 2026-10-20) keeps the policy simple.

## Decision

1. **Business tables.** Row-level security uses equality on `tenant_id` only. There is no tree logic in the policy.
2. **Organisation views.** Consolidated billing, organisation reporting and parent views come from read models. Audited jobs and events build them, under an audited service role.
3. **Operator grants.** A parent reads a child's rows only through an explicit, audited operator grant (ADR 0210). The bypass is one clause, named by an ADR (rule `tenancy`, point 5).
4. **Scope path.** The IAM scope path (ADR 0208) stays a predicate inside one tenant. It is not part of the row-level security policy of a business table.

## Consequences

- A business table's policy is the same for every table, so the isolation test is one pattern.
- An organisation's report is a read model, which can lag, and the lag is part of its contract.

## Enforcement

planned — the RLS catalogue audit: every table with `tenant_id` has enable, force and an equality policy (the rule `tenancy` and the constitution's tenancy page).

## Amendment 2026-11-07: platform tables and system readers (STA-2561)

The tenancy audit of 2026-11-07 found three kinds of table that decision 1 does not cover yet: tables that isolate rows
by `scope_path` ancestor logic, tables in `@stackra/database` that cannot name a tenant, and system tables with no
row-level security. This section records the owner's decision 12 (audit gap D), the leader's decisions of the same day,
and an answer for each other gap. Decisions 1 to 4 above stand.

Every row is in force: the items below, the group (c) dispositions and the gap answers were decided 2026-11-07 (leader, under owner decision 12).

### Decided

1. **One permissive policy (owner decision 12, audit gap D).** Equality on the tenant is the only permissive policy of
   a business table. Narrowing by scope path is a restrictive layer inside one tenant
   ([0347](/adr/0347-row-level-security-layering-one-permissive-tenant-policy-and-generated-restrictive-policies)
   decision 2). Organisation views are read models (decision 2). No policy reads the tree across tenants. The 22 tables
   with an `ancestor` policy take the tenant equality at their contract step and keep `scope_path` only as a
   restrictive policy or a query predicate.
2. **`scope.scope_nodes` is a platform table.** Its one reader outside the scope package is the isolation driver
   (`CallIsolationDriver`, `@stackra/tenancy`). That driver reads one node and its tenant, in a savepoint it always
   rolls back. No other package names the table, its model, its service or its Postgres driver, except the audit's
   `PLATFORM_TABLES` row, which names it with its reason and reads nothing. The system readers named below read the
   tree only through the `ScopeTree` port. The scope package still owns and writes it (0327 decision 3). The audit lists it as a platform table at its contract step, with this
   reason.
3. **The `@stackra/database` tables carry `isolation_scope_id`.**
   [0323](/adr/0323-tenant-vocabulary-lives-only-in-tenancy-and-scopes-use-the-scoperef-port) keeps the word
   "tenant" out of `@stackra/database`, so `sequence_counters`, `sequence_blocks`, `sequence_voids` and
   `projection_rows` name their tenant column `isolation_scope_id` (migration `database.0006_add_isolation_scope`,
   stackra#669). At the contract step it becomes NOT NULL, with one permissive policy
   `pol_<table>_isolation_scope_id`: equality with `app.tenant_id`. `scope_id` stays the caller's sub-scope, part of
   each table's key. The audit treats these four tables as group (b) by name; they get no platform entry. Precedent:
   core's `packages/commerce/payments` keeps the tenant in `scope_id` against `app.tenant_id` with `equalsOrUnset`.
   Payments' column is not renamed: the audit accepts it as group (b) by policy shape (2026-11-08, below).
4. **Tenant and TenantMove are a named exception.** The Figentra OS tenancy tables for tenants and tenant moves span
   tenants by nature, so they have no tenant equality policy. They are read and written only by the tenancy service.
   The exception covers no other table of that service.
5. **Proposed ADR [0411](/adr/0411-scope-subtree-move-re-paths-the-node-table-and-each-service-re-paths-its-own-rows-on-scope-moved)
   is superseded.** It relied on an ancestor policy to carry an organisation's grants across a move, which item 1
   removes. A scope move, if still needed, is proposed again on top of item 1.
6. **Search takes the platform form.** At their contract step, `search.vector_items` and `search.queries` take the
   platform form of gap C: a nullable `tenant_id`, where a tenant session reads its own rows and the NULL rows, and a
   platform session writes only NULL rows. `scope_path` stays a restrictive narrowing.
7. **The row-security audit has three groups.** `assertRowSecurity` (`@stackra/database/testing`, stackra#661,
   #662 and #668) names why a table without the owner column waits:

   | Group | Table shape                                                         | Until it is fixed                |
   | ----- | ------------------------------------------------------------------- | -------------------------------- |
   | (a)   | an `ancestor` `scope_path` policy                                   | the contract step adds the owner |
   | (b)   | equality on `scope_id` or `isolation_scope_id` with `app.tenant_id` | stays: by shape or by name       |
   | (c)   | a system table with no row-level security                           | the disposition below            |

   In 0.19 the audit warns. From 0.20 every unlisted table in any group is an error.

8. **Proposed ADR [0412](/adr/0412-inherited-row-policy-rows-on-the-path-above-the-session-are-read-only-to-it) is
   superseded in its row policy.** Its `ancestor` and select-only `inherited` policies show rows through the tree,
   which item 1 removes. A tenant still reads platform-seeded templates read-only, through the platform form of gap C.
   IAM grants that apply down the scope tree are authorization
   ([0208](/adr/0208-iam-model-scope-tree-roles-conditions-deny-delegation-and-permission-names)), not row-level
   security, and are not touched.

#### The rule, and its two mechanisms (2026-11-08, leader)

A table whose rows can be tied to a tenant takes the tenant form (`tenant_id` NOT NULL) or the platform form (a nullable
`tenant_id`, NULL for a platform row). The platform list is only for a table no row of which can ever be tied to a
tenant. Each table the audit names in core has this disposition and reason:

| Table                                                                           | Disposition                                  | Reason                                                                      |
| ------------------------------------------------------------------------------- | -------------------------------------------- | --------------------------------------------------------------------------- |
| `outbox.inbox`                                                                  | Platform list                                | Received event ids only.                                                    |
| `outbox.change_cursors`                                                         | Platform list                                | One row per consumer class; a global log position.                          |
| `queue.job_batches`                                                             | Platform list                                | Batch counters only.                                                        |
| `scheduler.watermarks`                                                          | Platform list                                | Tick bookkeeping.                                                           |
| `workflow.service_ack_sets`                                                     | Platform list, `Model.global`                | Service acks, no tenant payload.                                            |
| `rules.condition_fields`                                                        | Platform list, `Model.global`                | A field registry services publish.                                          |
| `database.seed_records`                                                         | Platform list                                | The ledger of product defaults only.                                        |
| `scope.scope_nodes`                                                             | Platform list, `Model.global`                | The scope tree, read outside its package only through `ScopeTree` (item 2). |
| `outbox.messages`, `outbox.deliveries`                                          | Platform form                                | An event of a tenant's call; the relays claim ids only (gap A).             |
| `outbox.changes` (and partitions), `outbox.replica_changes`                     | Platform form                                | A row change of a tenant's write.                                           |
| `outbox.device_sequences`, `outbox.offline_cap_uses`                            | Platform form                                | A device of a tenant user.                                                  |
| `queue.jobs`                                                                    | Platform form                                | A tenant's job; platform jobs keep NULL.                                    |
| `scheduler.schedules`                                                           | Platform form                                | A tenant's schedule; platform crons keep NULL.                              |
| `workflow.runs`, `workflow.steps`, `workflow.signals`                           | Platform form                                | A tenant's run, set from its scope; steps and signals from their run.       |
| `settings.stored_settings`, `settings.stored_setting_revisions`                 | Platform form                                | Tenant and user rows key by `(tenant_id, user_id)`; defaults keep NULL.     |
| `search.indexes`                                                                | Platform form                                | A tenant's index state; NULL replaces the `-` sentinel.                     |
| `webhooks.webhook_endpoints`, `webhooks.webhook_deliveries`                     | Tenant form (NOT NULL), `BelongsToTenant`    | A tenant's receivers and their attempts.                                    |
| `payments.payment_records`                                                      | Group (b) by shape: `scope_id`, no migration | The tenant in `scope_id`, `equalsOrUnset` on `app.tenant_id`.               |
| `identity.account_deletions`                                                    | Group (b) by shape: `scope_id`, no migration | The tenant in `scope_id`, `equalsOrUnset` on `app.tenant_id`.               |
| `payments.connected_account_limits`, `payments.connected_account_limit_changes` | Group (b) by shape: `scope_id`, no migration | The tenant in `scope_id`, `equalsOrUnset` on `app.tenant_id`.               |

1. **Group (b) by shape.** The audit owns a table by `scope_id` when its one permissive `pol_<table>_scope_id` is
   exactly the `equals` or `equalsOrUnset` policy `Blueprint.rowLevelSecurity` writes on `app.tenant_id`. It compares
   the catalogue's text of the table's policy with the text of that generated policy, created on the table in a
   transaction it rolls back, so a looser variant (`... or true`) or a second permissive policy is still refused. The
   table then gets every owner check and the two-tenant probe, by `scope_id`.
2. **`t.platformTable(reason)` and `t.reviewedPolicy(reason, policies)`.** A product table that no row ties to a
   tenant declares it in its migration; one whose policies have a reviewed shape the audit cannot derive (a pre-tenant
   route read through a setting) names them. The reason is required and one line. The compiled migration carries a
   `-- stackra:platform-table` or `-- stackra:reviewed-policy` comment line with the table, the policies and the
   reason, and gen's isolation test passes its migrations to the audit, which reads them. A platform table is refused
   at compile time with a scope id, an isolation scope id, a column filled from a setting or a policy, and in the
   audit once it holds the owner column, a scope id or an isolation scope id. A reviewed table must still enable and
   force row-level security and hold every policy it names; only the owner-policy checks and the probe are left out.
   `stackra row-security-declarations` lists every declaration with its reason, and `validate --repository` fails one
   that is not in the reviewed list `tools/scripts/row-security-declarations.yaml` with that reason. The framework's
   own platform tables stay `PLATFORM_TABLES` rows, one way: every host's audit sees them without reading migrations,
   and none needs a migration only to declare it.

### Allowed system readers of the scope tree

Besides the isolation driver, these files are allowed system readers. They read the tree only through the `ScopeTree`
port, to resolve placement, ancestry and `tenantOf`:

| File                                                                                        | Reads the tree for                       |
| ------------------------------------------------------------------------------------------- | ---------------------------------------- |
| `packages/security/tenancy/src/core/drivers/region-guard.driver.ts`                         | the call's tenant, for its region        |
| `packages/security/tenancy/src/core/drivers/tenancy-cron-scopes.driver.ts`                  | the nodes a per-scope cron runs in       |
| `packages/security/tenancy/src/core/drivers/tenant-placement-connection-resolver.driver.ts` | the tenant's database placement          |
| `packages/security/tenancy/src/core/drivers/tenant-scope-ownership.driver.ts`               | whether a scope is in the actor's tenant |
| `packages/security/tenancy/src/core/drivers/tenant-scope-resolver.driver.ts`                | the requested scope's node               |
| `packages/security/tenancy/src/core/functions/tenant-of.function.ts`                        | a scope's tenant (`tenantOf`)            |
| `packages/security/iam/src/core/drivers/iam-access-control.driver.ts`                       | a grant's node and its ancestors         |
| `packages/security/identity/src/node/actions/bootstrap-operator.action.ts`                  | the platform node (the exception below)  |

The rules:

1. No file outside the scope package reads the node table except through the port.
2. The port is injected only into drivers and services, never into actions, queries or listeners.
3. The check below pins this exact list. A new reader needs a review and a row here.

One named exception: identity's `bootstrap-operator` action takes the port to find the platform node by its path. It
runs only for the environment's bootstrap service principal. No identity service or driver owns operator grants
today, so moving the read means a new service. TODO: move that read into an identity service and drop this exception.
