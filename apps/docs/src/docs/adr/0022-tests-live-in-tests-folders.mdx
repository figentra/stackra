## Context

[0008](/adr/0008-test-placement) let a test sit either in `src/**/__tests__/` or as `<name>.test.ts` next to its
subject. Both layouts appeared, outside members too (agent hooks, repository scripts, scaffold templates), and nothing
checked either. One layout is easier to glob, exclude from builds and coverage, and spot in review.

## Decision

1. **Every test file in the repository sits directly inside a `__tests__/` directory** beside its subject. This covers
   apps, packages, services, `tools/`, `.agents/hooks/`, scaffold templates — every tracked path. Inside a member that
   means `src/**/__tests__/`.
2. **A test file is named `<subject>.test.<ext>`** (`.ts`, `.tsx`, `.mts`, `.mjs`, `.js`, …). `.spec.*` is not used.
3. **No root `tests/` directory in any member.** App end-to-end suites live in their app (`apps/<app>/e2e/__tests__/`).
4. **Shared fixtures and doubles are an explicit `testing` entry of the package that owns the contract**, not a shared
   folder. Fixtures used by one suite sit in `__tests__/` or `__fixtures__/` beside it.
5. **Tests need zero secrets.** Provider fakes replace credentials ([0009](/adr/0009-secrets-two-mechanisms)).
6. **A green `pnpm verify` proves less than it seems.** What it does not prove is stated in `/standards/testing`.

## Consequences

- One glob finds every test: `**/__tests__/**/*.test.*`. Vitest presets, coverage excludes and `node --test` scripts use it.
- Moving a file moves its `__tests__/` neighbour with it. A test imports its subject with `../<subject>`.
- Hook and script tests run from `__tests__/` too, so `.agents/hooks/__tests__/` and `tools/scripts/__tests__/`.

## Enforcement

`tools/scripts/validate-repository.mjs` (`checkTestPlacement`, run by `pnpm validate` and CI) fails on any tracked
or untracked, non-ignored file named `*.test.*` or `*.spec.*` whose parent directory is not `__tests__`, and on any
`*.spec.*` file. `.old/` is excluded.

## Amendment: decision 4 names the shared package (0269)

Decision 4 is amended by [0269](/adr/0269-stackra-testing-package-entries-and-helper-placement). Shared fixtures and doubles
that are generic (factories, fakes for the clock and ids, matchers with no domain type) live in `@stackra/testing`. Domain
helpers stay in the `./testing` entry of the package that owns the contract. Decisions 1 to 3 and 5 to 6 are unchanged.

## Amendment of 2026-11-09: a package may have an end-to-end tier

A UI package may run end-to-end tests in a real browser, through one harness in `@stackra/testing/e2e`. App e2e stays in
the app (decision 3); this adds the package case and changes nothing else.

- **Two files, both directly in `__tests__/`.** `<name>.e2e.page.tsx` default-exports the React component to render (the
  component in its providers, with the package's testing fakes). `<name>.e2e.test.ts` is a Playwright spec that imports
  `test` and `expect` from `@stackra/testing/e2e`, opens `/<name>` and checks the page. A page outside `__tests__/` is
  refused like a misplaced test.
- **Gen writes the rest.** For a package with at least one `.e2e.page.tsx`, `stackra gen` writes `.stackra/e2e/` (a small
  Vite app that renders the page named by the URL path) and `.stackra/playwright.e2e.config.ts`. `stackra test --tier e2e`
  runs it. A service or a worker still has no e2e tier.
- **Console errors fail a spec by default.** A page that logs `console.error` or throws is not live, so the `test` of
  `@stackra/testing/e2e` fails the test. A file opts out with `test.use({ consoleErrors: "allow" })`. This applies to app
  e2e specs too.
- **Two locales.** Every spec runs in Chromium and in Chromium with the `ar-SA` locale, which renders the page right to
  left. Firefox and WebKit are opt-in.
