## Context

figentra's GitHub Actions is billing-locked, so the CI deploy workflows (deploy-registry.yml, deploy-static.yml,
deploy-turbo-cache.yml, each behind the `production` Environment approval of
[0468](/adr/0468-agents-deploy-dev-and-staging-production-waits-on-one-environment-approval)) cannot run. The owner
chose on 2026-11-25 a recorded exception: box 1 deploys Encore staging and the Cloudflare Workers when a Worker
changes (STA-2783). Asked how production promotion works for those box deploys, the owner answered the CTO: **"All
automatic"**. With no person clicking, the gates have to carry the whole weight, so they are part of this decision.

## Decision

1. Box deploys of the registry, static, turbo-cache and edge Workers promote to production automatically when every
   gate below passes (`STACKRA_DEPLOY_PROMOTION` defaults to `auto` for all four). This replaces 0468 decision 2's
   per-deploy Environment approval **for these four Workers' box deploys only**; CI deploys, Encore production and
   package releases keep 0468 unchanged.
2. Every gate is mandatory; none has a setting that skips it:
   1. **Main and verify.** Only a commit of origin/main, with a green `stackra/verify` check run from the
      stackra-verify App at that exact SHA. Until stackra/verify is live, a box-green record at that SHA stands in,
      only while `STACKRA_DEPLOY_ACCEPT_BOX_GREEN` is on, and only when written by its owner (never the deploy user).
   2. **No traffic before the smoke.** `wrangler versions upload`, the version joins the deployment at 0%, and the
      smoke suite runs on it through the version override: runway.yaml's uptime and member checks plus each Worker's
      own. The registry's is the strongest: per release group and `@stackra/cli`, the newest version's packument
      (full and abbreviated), its tarball with sha512 equal to `dist.integrity` and to what production served before,
      its registry signature, the signing keys, the refusals of a publish without a token and of an unpublish, and
      the 404 of an unknown package.
   3. **Additive D1 only.** Pending migrations run before any version ships, and only when every statement is
      `CREATE TABLE`, `CREATE INDEX`, `ALTER TABLE … ADD COLUMN` or `INSERT`; anything else stops and is recorded as
      needing the owner.
   4. **Gradual promotion with automatic rollback.** 10% then 100%, held, with the whole smoke again at each step and
      on the live hosts at the end; any failure puts the previous version back at 100%.
   5. **A bounded token.** The Cloudflare API token is the owner's, restricted to box 1's egress IP, with an expiry,
      held 0400 by a dedicated deploy user (the account also holds Agent Desk / Figentra Flow's and the tax-practice
      Workers, which is why the IP filter and the expiry are not optional).
   6. **The ledger.** Every attempt is one JSON line: SHA, trigger, verify evidence, migrations, old and new version
      ids, every step and smoke result, rollback, and times. No secret reaches it.
3. Everything is built OFF. The path switches on only after the strict reads, with the owner's token in place and the
   first deploy of each Worker run by hand, watched by Lukas and recorded in the ledger.
4. `approve` stays in code (per Worker, tested): it stops after the 0% smoke until the approver user's file names the
   SHA and the version. Choosing it for a Worker is a setting change, not a new decision.

## Consequences

A Worker change on main reaches production without a person in the loop, so a gap in the smoke is a production gap:
adding a route or a failure mode to a Worker means adding it to its suite in `stackra-deploy-smoke.mjs`. A destructive
migration always waits for the owner. When Actions returns, the box path is switched off and CI resumes under 0468.

## Enforcement

`tools/scripts/stackra-deploy.mjs` with `tools/scripts/stackra-deploy-smoke.mjs` and
`tools/scripts/stackra-deploy-sql.mjs`; their tests in `tools/scripts/__tests__/stackra-deploy*.test.mjs` cover each
gate (non-main and unverified SHAs refused, destructive migrations stopped, the smoke failure and its rollback at 0%
and at 10%, the promotion steps, approve mode, the ledger, no secret in argv or output, Encore production refused).
