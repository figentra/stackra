## Context

Every docs site is on Mintlify ([0002](/adr/0002-docs-on-mintlify), [0299](/adr/0299-docs-runway)): Stackra core's
`apps/docs` at docs.stackra.figentra.com, and each product's own `apps/docs`. Mintlify is a hosted product. It ships no
self-hosted export, so its build sits outside our Workers and its deploy needs its own Runway provider, branch and
GitHub app. It also gives each repository its own site, while Figentra's readers want one place with a tab per product.
The product repositories are private, so a hub that checked them out at build time would need read access to all of
them, and would publish whatever sat on their main branch rather than what was released.

## Decision

1. **Fumadocs, self-hosted and open source.** Every Figentra docs site is built with Fumadocs and served by a Cloudflare
   Worker with static assets ([0284](/adr/0284-hosted-static-files-one-cloudflare-static-assets-worker)). Fumadocs runs on
   Vite with React Router 7, prerendered to static files, because Next.js is rejected
   ([0165](/adr/0165-web-client-stack-ui-contract-form-adapters-and-no-nextjs)). This replaces Mintlify everywhere:
   Stackra core, Figentra and every product.
2. **Runway deploys every site.** A docs site is deployed through Runway, by its Cloudflare Workers provider
   ([0289](/adr/0289-runway-and-environments-workers-one-encore-app-previews-and-publishing)), never by a direct Cloudflare
   call. Dev and staging deploys run without the owner; production waits on the owner's Environment approval
   ([0468](/adr/0468-agents-deploy-dev-and-staging-production-waits-on-one-environment-approval)).
3. **Each repository writes its docs in its own `docs/`.** The pages sit in `docs/` at the repository root and are
   reviewed in the same pull request as the code they describe.
4. **Each product release publishes a docs package.** The product's existing Release also publishes
   `@figentra/<product>-docs`: the MDX pages of `docs/` plus their navigation. It goes to our own registry
   ([0453](/adr/0453-the-stackra-registry-one-npm-compatible-store-on-cloudflare-and-our-own-licence-engine)), never to
   npmjs.
5. **The API reference is generated.** It comes from the `openapi.json` already inside the product's contract packages,
   `@figentra/<service-package>-contract` ([0511](/adr/0511-cross-repo-service-contracts-and-cross-app-events)). Nobody
   writes API reference pages by hand.
6. **One hub at docs.figentra.com.** The hub depends on every product docs package. Its product switcher has one tab per
   product: os, pay, billing, invoicing, commerce, tamo, organza and each product that follows.
7. **A release rebuilds the hub.** A product release triggers a hub rebuild, and Runway deploys it.
8. **Packages, not a cross-repository checkout.** The hub reads released packages, so its docs match the released code,
   and it needs no read access to the private product repositories.
9. **Stackra and Flow keep their own sites.** Their readers are different. Stackra's stays at docs.stackra.figentra.com,
   and Flow's is open source. Both move to Fumadocs under decisions 1 to 3, and either can become a hub tab later.

## Consequences

- Mintlify leaves every repository: the `mint` tasks, the `mintlify` Runway provider, the deploy branches, the Mintlify
  GitHub app and the "Mintlify Deployment" checks. Gen's docs-site target (the 2026-10-27 note on 0002) stops writing a
  Mintlify site. Core's own pages move from `apps/docs/src/docs` to `docs/`, and the tools that name the old path
  (`pnpm adr:reserve`, the ADR links) move with them in the same pull request.
- The checks of 0299 stay, run on the Fumadocs build: the build, broken links, accessibility, and a smoke test after
  each deploy.
- Each product's Release grows one package, and its CI builds the docs on every pull request that touches `docs/`.
- The hub is one more member, deployed like any Worker; its content changes only when a product releases.
- Rolling back a product's docs is rolling back its docs package version in the hub.

## Enforcement

planned — the Runway Cloudflare Workers provider (STA-1921, stackra#227) as the only deploy path; the hub member and its
release trigger; one migration pull request per repository under STA-1920 that adds `docs/`, adds the docs package to
the Release, moves the Mintlify content and removes Mintlify and its checks; a `FORBIDDEN_DEPENDENCIES` row for `mint`
and `mintlify` in `@stackra/repo-checks` once the last repository has moved. Until then nothing checks this rule.
