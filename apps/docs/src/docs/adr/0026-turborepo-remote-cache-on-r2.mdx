## Context

`turbo.jsonc` already enables the remote cache with `"signature": true`, but there is no server: it is a no-op until
`TURBO_TOKEN` and `TURBO_TEAM` are set. CI rebuilds everything on every run. Turborepo's remote-cache HTTP API is open, so
any server that implements it works. Vercel Remote Cache was weighed and rejected: it ties builds to a Vercel account the
repository does not otherwise use.

## Decision

1. **A small Cloudflare Worker implements Turborepo's remote-cache API**, storing artifacts in an R2 bucket, on the same
   Cloudflare account and platform as `npm.figentra.com` ([0025](/adr/0025-packages-publish-to-private-registry)).
2. **Artifacts are signed.** `remoteCache.signature` stays `true`; the signature key and the cache token live in Infisical
   `/ci` and reach CI over OIDC ([0009](/adr/0009-secrets-two-mechanisms)).
3. **No lock-in.** Switching provider changes only the URL and the token; no repository file names a vendor beyond the URL.
4. **Vercel Remote Cache is not used.**

## Consequences

- CI and developers skip tasks whose inputs did not change.
- The Worker, its bucket lifecycle (`cacheMaxAge` is 7 days locally; R2 needs a matching expiry rule) and its token are a chore for the maintainer.
- A poisoned artifact is rejected by signature check rather than served.

## Enforcement

Planned — the Worker itself, the CI step that sets `TURBO_API`, `TURBO_TOKEN` and `TURBO_TEAM` from `/ci`, and an R2 lifecycle rule.
Today only `turbo.jsonc` (`remoteCache.signature: true`) exists; nothing uses a remote cache.

## Amendment 2026-11-05 (owner decision): figentra-turbo-cache

The owner decided on 2026-11-05 that one Figentra-owned cache serves every repository. STA-2112.

- **Decision 1, as amended.** The Worker is `figentra-turbo-cache`, built by `workers/turbo-cache`
  (`@figentra/worker-turbo-cache`) in figentra/figentra, moved there with its history, on `turbo.figentra.com`. It
  replaces `stackra-turbo-cache` (`turbo.stackra.figentra.com`).
- **No data copy.** Both Workers bind the same R2 bucket `turbo-cache` (7-day lifecycle) with the same key prefix and
  token, so a job hits the same artifacts through either host. Only Infisical `ci-build` `/ci/turbo` `TURBO_API`
  changes.
- **The switch.** `turbo.stackra.figentra.com` stays as an alias on the new Worker during the switch, for any job
  that still names it. It is retired, and `stackra-turbo-cache` deleted, on the owner's go.
- **Deploy.** `figentra/figentra` `.github/workflows/deploy-turbo-cache.yml` deploys, by the owner's dispatch only, in
  the GitHub environment `workers`. A custom domain that another Worker holds moves only on a dispatch with the dry run
  off. The Worker's `TURBO_CACHE_TOKEN` is CI's `TURBO_TOKEN`, as before.

Decisions 2 to 4 are unchanged: signed artifacts, no lock-in, no Vercel.
