## Context

[0047](/adr/0047-audit-service-via-events) (Proposed) routed audit through events without a tamper-evidence rule or a retention rule. The owner's audit answers AU1 to AU8 and SC8 (mem L644–653, L552, 2026-10-20) fix them.

## Decision

1. **What is audited (AU1).** Every action, every data change (a redacted diff through `@Auditable`), security events, and sensitive reads.
2. **Envelope (AU2).** A rich envelope on each record.
3. **Tamper evidence (AU3).** Storage is append-only. Each tenant has a hash chain. A KMS-signed checkpoint is written daily. S3 Object Lock holds the records. `stackra audit:verify` checks the chain.
4. **Same transaction (AU4).** Evidence goes to the outbox in the same transaction as the change. Operator, break-glass and impersonation paths fail closed.
5. **Reads.** `@AccessLogged` writes application-level access logs. pgaudit records direct database sessions in production. There is no CDC (change-data-capture) tool.
6. **Retention (AU5 and SC8).** Thirteen months hot, in partitioned Postgres. Cold storage is S3 Parquet. Money events are kept seven years.
7. **Tenant access (AU6).** A tenant can view and export its own audit log. A SIEM stream is a Pro entitlement tier.

## Consequences

- An audit gap is detectable, because a broken chain fails verification.
- Audit is written with the change, so a change without its audit record cannot commit.

## Enforcement

planned — `stackra audit:verify` in CI against a sample tenant; the outbox test covers the same-transaction rule.

## Open questions

1. Volume budget and batching window for read audits, and whether a failed read audit blocks the read (register D-11). The owner decides.

## Note 2026-11-02: the code constant

Decision 6's thirteen months is the code constant `AUDIT_HOT_RETENTION` in `@stackra/contracts`, `Duration.days(397)`
(`Duration` refuses months; 397 days is the longest any thirteen consecutive calendar months can run, so nothing is
pruned early). The approval binding prune (ADR 0509) reads it. The access log's `auditRetentionDays` stays the owner's
stated number with no code default.

## Note 2026-11-26: no action unaudited outside dev and test (STA-1571)

Decisions 1 and 4 hold in code: the action pipeline treats a missing `AuditTrail` the way it treats a missing
`AccessControl`. Outside `dev` and `test` an action with no trail bound is an error before any step runs, never an
unaudited write. The environment is `AuditConfig.environment` of `@stackra/actions` (key `actions.audit`), read from
`STACKRA_ENVIRONMENT`: refused at boot when it is empty, and any name but `dev` or `test` (`preview`, `staging`,
`production`, a typo) needs a trail. Unset means `dev`, where the trail is optional. A deployment does not depend on an
operator setting it: gen writes `stackra-encore/<member>/environment.ts`, which hands Encore's `appMeta().environment`
to `@stackra/app/server`, and the server `createApp` derives the variable from it (`runningEnvironment`). A local
runtime (`encore run`, `encore test`, cloud `local`) is `dev` or `test`; a deployed one is its Encore environment's
name when that is `preview`, `staging` or `production`, else `production`, `preview` or `staging` by its type, never
`dev` or `test`; a deployed runtime set to `dev`, `test` or nothing fails boot. Unset therefore means `dev` only under
`stackra dev`, vitest, `encore run` and `encore test`, and in a self-hosted image whose infra config leaves
`metadata.cloud` at `local`. Gen binds `AuditConfig` in every service that runs an action. Queries are not audited by
this step.
