## Context

[0077](/adr/0077-open-core-free-and-pro-lists) listed whole areas as Pro. Later accepted ADRs moved most of them back
to free code: [0202](/adr/0202-stackra-pro-is-developer-side-os-capability-is-free-code) (editors, AI, settings and
search parity are free code gated by entitlements), [0240](/adr/0240-scope-tree-is-free-code-with-depth-by-plan) and
[0327](/adr/0327-scope-package-owns-the-scope-tree-tenancy-is-a-consumer) (the scope tree is free code in
`@stackra/scope`), and [0310](/adr/0310-stackra-ui-pro-private-heroui-pro-wrappers) (the HeroUI Pro wrappers are not
for sale). Decision D5 (2026-10-27) then said "the 0077 list is paid" for 0.1.0, and the stackra-186 audit
(`notes/handover/batches/pro-split-audit.md`) filed sixteen split batches (stackra-187 to 202) with an owner gate on
each conflict. Several splits were impossible or harmful as written: free `@stackra/builder/react`,
`@stackra/loyalty-kit`, `@stackra/tenancy`, OS and Commerce import the code that would have moved. The owner settled
the line in D6 (2026-10-27): the 0202 model.

## Decision

1. **Runtime code is free, behind plan entitlements.** Every runtime, kernel, port, kind, driver and React hook that
   exists in `@stackra/*` today stays there, MIT. What a customer pays for at runtime is an entitlement checked by the
   pipeline ([0202](/adr/0202-stackra-pro-is-developer-side-os-capability-is-free-code) decision 5,
   [0242](/adr/0242-commercial-model-plan-ladder-add-ons-metric-and-trial) limits), never a package tier. Nothing moves out of a free package to Pro.
2. **`@stackra-pro/*` holds new code only, of two kinds.**
   - **Paid UIs and studios**, new packages over free runtimes:
     `@stackra-pro/builder-studio` (dashboard, page, form, experience-block and automation editor UIs over the free
     builder kernel and `@stackra/builder/react` hooks; stackra-188), `@stackra-pro/ai-studio` (agent builder,
     registry UI and eval workspace over the free `@stackra/ai` runtime and `runEvals`; stackra-197),
     `@stackra-pro/devtools` (the web and native floating panel and the service dev console of [0246](/adr/0246-devtools-dev-only-for-apps-and-services) over the free
     `@stackra/devtools-kit`; stackra-198) and `@stackra-pro/notifications-studio` (the visual template editor and
     the delivery analytics dashboard over the free template cascade and channel ports; stackra-199).
   - **Advanced drivers** behind free ports: `@stackra-pro/search-meilisearch` and `@stackra-pro/search-opensearch`
     (`SearchDriver`, each passing the free conformance suite published from `@stackra/search/testing`;
     stackra-195), and `@stackra-pro/analytics-destinations` (further `AnalyticsDriver` destinations behind the
     consent-gated queue; PostHog stays free; stackra-196).

   This amends [0202](/adr/0202-stackra-pro-is-developer-side-os-capability-is-free-code) decision 1 (as amended by
   [0270](/adr/0270-builder-architecture-one-editor-kernel-document-kinds-and-collaboration-levels)) for the studio
   editor UIs, none of which exists today: they are new Pro code, and the editor kernel and hooks they sit on stay
   free. Its decision 2 list (on-prem stack, advanced drivers, devtools UI) stands and gains the studios.

3. **`@stackra-pro/ui` is internal-only and never sold.** The HeroUI Pro wrapper package keeps the name
   `@stackra-pro/ui` (its `package.json` name today), moves to `figentra/stackra-pro` (stackra-189) and is served
   by our registry under the `internal` read rule of
   [0453](/adr/0453-the-stackra-registry-one-npm-compatible-store-on-cloudflare-and-our-own-licence-engine)
   decision 10, as a per-name row inside the `@stackra-pro` scope: only Figentra's own internal tokens read it, and a
   customer licence grant, `names: "*"` included, never covers it. Its Keygen `publishConfig` is dropped. HeroUI Pro
   stays an external peer that each consuming repository installs with its own HeroUI Pro token
   ([0310](/adr/0310-stackra-ui-pro-private-heroui-pro-wrappers) decisions 3 and 7 stand). Kiosk stays free code in
   `@stackra/ui`; embeds and broadcast dashboards are out of scope for 0.1.0.
4. **`@stackra/licensing` stays free.** It keeps the `LicenceIssuer` and `LicenceVerifier` ports, the `registry`
   own-issuer driver (default) and the optional `keygen` driver of
   [0453](/adr/0453-the-stackra-registry-one-npm-compatible-store-on-cloudflare-and-our-own-licence-engine)
   decision 15, in `figentra/stackra`.

7. **The rules of 0077 decision 4 and 0202 decision 4 stand.** A Pro package plugs in behind a free contract, depends
   on released `@stackra/*` versions, and no member of `figentra/stackra` imports `@stackra-pro/*`. Figentra's own
   products take Pro packages under the internal licence.

## Consequences

- Free installs get every runtime; a customer's plan, not a package, switches a feature on.
- No free package loses code, so OS, Commerce and the products need no change for 0.1.0.
- `figentra/stackra-pro` starts with eight members, all new or moved code with no free dependent.
- The registry needs a per-name `internal` row inside `@stackra-pro` before stackra-189 publishes (stackra-182 and
  stackra-183 own the Worker and grant logic).
- Core `apps/mobile` and `apps/playground` stop depending on `@stackra-pro/ui` (stackra-189).

## Enforcement

- `tools/scripts/validate-repository.mjs` (with `PRO_DEPENDENCIES` from `@stackra/repo-checks`) keeps refusing a
  non-app member that depends on `@stackra-pro/ui` or HeroUI Pro.
- planned — the same validator refuses any member of this repository that depends on any `@stackra-pro/*` name
  (0077 Enforcement), once stackra-189 has removed the app dependencies.
- planned — `workers/registry` refuses a read of an `internal` name with a customer licence token, with its test
  beside the read-rule code (stackra-182, stackra-183).
