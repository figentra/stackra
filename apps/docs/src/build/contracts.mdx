Each package publishes its public types through a types-only `./contracts` entry
([ADR 0117](/adr/0117-contracts-placement-and-decorator-ownership) decision 2): request and response shapes, event names
and versioned payloads ([0141](/adr/0141-integration-event-names-and-envelope),
[0260](/adr/0260-cross-service-calls-through-injected-clients-and-events)), config keys with their value types (0044, 0146) and DI tokens ([0042](/adr/0042-di-first-with-one-container-per-service),
[0263](/adr/0263-di-stays-and-gen-writes-the-wiring)). `src/contracts/` is a leaf: it imports nothing from the
package's other folders, and no symbol is exported from two entries (ADR 0294).

**A dependency is met when its contract exists.** Import the declared name and keep going; a missing name is added as
a new file in the producer's `src/contracts/` and listed in your report. Existing contract names are never renamed or
removed.

## Members without a `./contracts` entry

Their public types are exported from `.` today. Copying them into `src/contracts/` would export one symbol from two
entries, so the contracts batch does not; the package's owner moves them (types, enums and ports from `src/core/` into
`src/contracts/`, `core` re-imports through `#contracts/*`) and adds the `./contracts` export. Until then, import
these names from `.`.

## Services

`services/example` and `services/health` are reference services with no published events or API shapes of their own;
a service gains `src/contracts/` (its events, request and response shapes) when it publishes one
([ADR 0260](/adr/0260-cross-service-calls-through-injected-clients-and-events)).
