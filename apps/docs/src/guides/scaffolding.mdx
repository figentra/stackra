Never copy an existing member to start a new one. `pnpm new` picks the right directory, package scope, tier tag and script set, copies the root `LICENSE` and formats the result.

```bash
pnpm new <kind> <name> [--category <c>] [--description "<text>"] [--title "<Title>"] [--port <n>] [--dry-run]
```

Run it with `--dry-run` first to see what it would write. Then run `pnpm install` and `pnpm verify`.

## Kinds

| Kind | Template | Lands in | Pick it for |
| --- | --- | --- | --- |
| `domain` | `templates/packages/domain` | `packages/<category>/<name>` | A business capability: entities, use cases, adapters, a delivery surface |
| `platform` | `templates/packages/platform` | `packages/<category>/<name>` | A technical capability other packages build on, runtime-neutral core |
| `lib` | `templates/packages/lib` | `packages/<category>/<name>` | A small flat utility with one entry and no layers |
| `tooling` | `templates/packages/tooling` | `packages/tooling/<name>` | A shared config preset, data only |
| `app-vite` | `templates/apps/vite` | `apps/<name>` | A client-only SPA behind login; port from 3710 |
| `app-next` | `templates/apps/next` | `apps/<name>` | Server rendering or public pages; port from 3710 |
| `app-expo` | `templates/apps/expo` | `apps/<name>` | An iOS and Android app; no hyphens in the name |
| `app-docs` | `templates/apps/docs` | `apps/<name>` | A Mintlify site; port from 3334 |
| `service` | `templates/services/encore` | see the note | A backend service |

`--category` is required for `domain`, `platform` and `lib` and must be one of: foundation, application, communication, cross-cutting, data, developer, experience, runtime, security, state. Names are kebab-case.

<Warning>
  A service is its own workspace member at `services/<name>` (`@figentra/service-<name>`, like `services/example` and `services/health`), and holds no Encore files: `stackra gen` generates the Encore app ([0124](/adr/0124-encore-is-the-generated-runtime-target)). The `service` template and `tools/scripts/scaffold.mjs` still target the older layout, `services/src/<name>` as a unit of one Encore app, which is not a workspace member. Until the template is updated, scaffold a service by hand from `services/example`, or run `pnpm new service` and move the result, then run `pnpm validate`.
</Warning>

Which package kind: would the code need renaming to make sense in a different product? Then `domain`. Does it serve other packages with no business meaning of its own? Then `platform`, or `lib` when it is flat. Rules for each shape are in [Packages](/guides/packages).

## Tokens

The scaffold replaces exactly six tokens in file contents **and** path names. Other double-brace text (JSX style objects) is left alone.

| Token | Value |
| --- | --- |
| `{{NAME}}` | kebab-case short name |
| `{{PASCAL}}` | PascalCase of the name |
| `{{TITLE}}` | Title Case name, or `--title` |
| `{{DESCRIPTION}}` | the `--description` sentence; becomes `description` in `package.json` and opens the README and AGENTS |
| `{{PORT}}` | dev port, the next free one in the kind's range (or `--port`) |
| `{{CATEGORY}}` | the `packages/` folder |

`TITLE` and `DESCRIPTION` are JSON-escaped when written into `.json` and `.jsonc` files.

## What you get

Every member gets `package.json`, `turbo.jsonc` with its one tier tag, `README.md`, `AGENTS.md` with a `## PII` table, `CHANGELOG.md` and the byte-for-byte root `LICENSE`, with code in `src/`. Library templates ship passing tests, because the vitest preset fails an empty suite, and their `exports` point at `src`. After scaffolding:

1. Replace the placeholder README and AGENTS text with the member's real purpose and its PII table.
2. `pnpm install` to link the new member, then `pnpm verify`.
3. Add a changeset (`pnpm changeset`).

## Changing a template

Edit the template under `tools/scaffold/templates/`, then run `node --test tools/scripts/scaffold.test.mjs` (or `pnpm test`). The test renders every kind into a temporary directory and fails if a token is left in a path or a file, or if a rendered `.json` file does not parse. It also covers the JSON escaping, the byte-exact `LICENSE`, port allocation and `--dry-run`. Rendering the output through `pnpm validate` is a target extension: a template that no longer produces a conforming member should fail the suite, not surprise the next person who scaffolds.

When you add a kind, add a row to the test's case list and to the template folder's `README.md`. Add a template for a new shape only when its recorded trigger fires; a template for a shape nobody has adopted manufactures non-conformant members.

## Moves are scripted, never hand edits

Moving or renaming a file or folder means rewriting every import and link that points at it. Do that with a codemod, not an editor: a script `git mv`s each path, rewrites every relative specifier and link from the file's new location, prints what it changed and can run with `--dry-run`.

<Note>
  Status: target. Stackra has no move codemod yet. Port one before the first large restructuring. Until then, move in small steps, run `pnpm typecheck` and `pnpm verify` after each, and never mix a move with a behaviour change in one commit.
</Note>

| Rule | Check | State |
