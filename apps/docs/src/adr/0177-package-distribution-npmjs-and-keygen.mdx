## Context

[0025](/adr/0025-packages-publish-to-private-registry) (Accepted) published packages to a private registry. The owner's registry answers PK1–PK7 (mem L455–473, L396, 2026-10-20) moved the free packages to
npmjs with provenance and the Pro packages to Keygen Cloud. Railway is no longer used (ops L31), and the Railway registry trial was dropped.

## Decision

1. **Free packages (PK1).** `@stackra/*` publishes openly to npmjs with provenance, from CI with the bot token through OIDC. The changesets `access` setting is `public`.
2. **Pro packages (PK2 and PK3).** Keygen Cloud serves the `@stackra-pro` packages and images. The Cloudflare Worker `npm-registry` is retired after `@figentra/cli` and vellum have migrated. `npm.figentra.com` stays up until then.
3. **Migration.** Delete `npm.figentra.com` only after Academorix and the release job have switched, and after the tarballs have migrated.
4. **Release checks (PK4).** A full verify, `publint`, `attw`, and a packed-tarball smoke test in Node, Vite and Metro. A changeset is required. The owner merges the version pull request.
5. **Versions (PK5 and PK7).** One fixed version for all `@stackra/*`. Pro follows the same major and minor, and ships within a week.
6. **Deprecation (PK6).** A deprecation lasts one minor before 1.0 and one major after. LTS starts at the first on-prem contract.
7. **Canaries (DX7).** Canary snapshot releases are published.
8. **Carried forward from 0025.** Decision 3 (`dist` and the `@stackra/source` condition) and decision 4 stay.

## Consequences

- A free package is installable from npmjs with no account, and the provenance shows where it was built.
- Pro packages need a Keygen token, so their distribution follows the licence (ADR 0178).

## Enforcement

planned — the release workflow publishes with provenance, and `publint` and `attw` run in the release job.

## Open questions

1. The day `npm.figentra.com` is switched off. The owner decides after the migration in decision 3.

## Alternatives

- One private registry for everything: superseded; free packages go to npmjs.
- Verdaccio on Railway: dropped; Railway is gone (ops L31).

## Amendment 2026-10-21: trusted publishing and provenance enforced (STA-155)

**Context.** Decision 1 said "from CI with the bot token through OIDC". The release workflow still published to
`npm.figentra.com` with an Infisical token.

**Decision.** This amendment replaces decision 1's mechanism; the rest stands.

1. **Registry.** `@stackra/*` publishes to `https://registry.npmjs.org/`, public. `npm.figentra.com` is no longer the
   `@stackra` registry; the Worker keeps serving `@figentra/cli` and vellum until decision 3 is done.
2. **No long-lived npm token.** The release job uses npm trusted publishing: GitHub OIDC (`id-token: write`). Changesets runs
   pnpm 12's native publish, which does the OIDC exchange and provenance itself; the npm CLI is not the publisher. No `NPM_FIGENTRA_TOKEN`, no Infisical step for npm.
3. **Provenance.** The workflow sets `NPM_CONFIG_PROVENANCE=true`; every `tier:lib` package carries a `repository` field (npm provenance needs it to match this
   repository) and
   `publishConfig: { access: "public", provenance: true, registry: "https://registry.npmjs.org/" }`; changesets `access` is `public`.

**Enforcement.** `validate-repository.mjs` requires that `repository` and `publishConfig` on every `tier:lib` package; the package scaffold
template carries it. Apps and services stay private and UNLICENSED. Owner steps: `/runbooks/release`.

## Amendment 2026-10-21: package paths (STA-219)

**Context.** Decision 8 carries decision 3 of [0025](/adr/0025-packages-publish-to-private-registry) forward. That decision
put a package's config in `config/` outside `src/` and its static files in `resources/`. Every member keeps its code in
`src/`, and `resources/` is the name the `@Resource` declarations of [0130](/adr/0130-module-layout-by-semantic-kind) use.
[0025](/adr/0025-packages-publish-to-private-registry) is superseded, so this ADR is the live home of the path rules. The
owner settled the paths on 2026-10-21.

**Decision.**

1. **Config is inside `src/`.** A package's config is `src/config/<pkg>.config.ts`. It is compiled with the rest of `src/`
   and exported under the same `./config` entry as before. The `config/` path in decision 3 of 0025 is withdrawn.
2. **Static files are `assets/`.** A package's shipped static files sit in an `assets/` folder at the package root and are
   exported as `./assets/*`. The `resources/` path in decision 3 of 0025 is withdrawn. Static files are not code, so the
   `assets/` folder is outside `src/`, as [0234](/adr/0234-module-assets-and-storage) describes.
3. **Nothing else changes.** The registry, the publish flow, the `dist` build, the `@stackra/source` condition and the
   versioning decisions are untouched by this amendment. The registry part of this ADR is amended separately, by the
   change that owns it, and this section does not change it.

**Consequences.**

- A reader looks for a package's config in `src/config/` and its static files in `assets/`.
- The `exports` rule in `tools/scripts/validate-repository.mjs` must accept `./config` and `./assets/*`. That is the rule
  already planned in decision 3 of 0025, and it is unchanged in intent.

**Enforcement.** planned — the `exports` rule in `tools/scripts/validate-repository.mjs` and the packed-artifact smoke test
named in Enforcement above. Nothing checks the `src/config/` or `assets/` paths yet.
