<Note>
  Amended by [0294](/adr/0294-programming-model-v3-grammar-folders-identities-and-naming), the
  programming model v3: `@Link` and the `links/` folder are retired. A relation to a model of
  another module is a relation decorator with a thunk, such as `@ManyToOne(() => Variant)`, typed
  `Link<T>` (0294 decision 28). Gen derives the link mode from module ownership. The relation stores
  the target's public id in an indexed column with no foreign key and no join, `line.variant.id`
  needs no load, and `line.variant.load()` runs the owning module's generated query to read the
  target. A relation inside one module stays an ordinary relation with cascade rules, as decision 5
  says, typed `Ref<T>` for one target and `Collection<T>` for many. Decision 1 (a pivot owned by a link) is
  superseded, because no link object exists. The new model does not address decision 2
  (`query.graph`), so this note does not settle the form of cross-module reads beyond `load()`.
  Decision 3 is unchanged.

Enforcement of this note: planned — STA-340 (gen checks: a cross-module relation not typed
`Link<T>`, or a `Link<T>` inside one module; a link that points up the module graph or forms a
cycle; a foreign key or a cascade across modules).

</Note>

## Context

Modules own their data ([0014](/adr/0014-data-ownership-and-orm)), so one module's model cannot hold a foreign key into
another's tables. Products still need "orders with their customer and product". Medusa solves this with `defineLink` (a pivot
owned by a link module) and `query.graph`, which fans out to each owning module and stitches the result; its index module is
a Postgres read model for the hot cases.

## Decision

1. **A relation across modules is a `@Link`** between two models, declared in a module that depends on both. The pivot table
   belongs to that link, not to either model.
2. **`query.graph({ entity, fields, filters })` reads across links**, calling each owning module's query and joining in
   memory, with batching through the DataLoader of [0097](/adr/0097-model-and-database-packages).
3. **Tenancy and iam apply per owning module**: each fan-out call goes through that module's `@Query` pipeline.
4. **Hot read paths use an index read model** fed by events, which is the job of `@stackra/search`
   ([0089](/adr/0089-search-fresh-with-pro-engine-drivers)), not a second index package.
5. **Within one module, ordinary relations** of 0097 apply; `@Link` is only for crossing a module boundary.

## Consequences

- Module boundaries hold without giving up joined reads.
- `query.graph` is slower than a SQL join; the read model is the answer when that matters.
- Links appear in the gen manifest, so the registry can show the relation graph.

## Enforcement

Planned: the gen validation pass fails a model relation that targets another module's model without a `@Link`. Nothing
checks this today.
