## Context

[0040](/adr/0040-ddd-feature-modules-in-services) organised services as DDD layers. Accepted [0091](/adr/0091-generated-encore-app-in-stackra-folder)
and [0126](/adr/0126-member-shapes-and-scaffold-templates) already removed the generated folder and set the feature-module
path. The owner's intent-map item P9 and the audit's module-layout answer (audit Q9) replace the DDD layers with kind folders,
organised around what each file does.

## Decision

1. A feature module lives at `src/modules/<feature>/`. Its code sits in kind folders:
   `models/`, `actions/`, `queries/`, `services/`, `events/`, `listeners/`, `workflows/`, `policies/`, `permissions/`,
   `settings/` and `contracts/`.
2. `interfaces/`, `types/`, `constants/`, `tokens/`, `errors/` and `decorators/` appear once a module has two or more
   files of that kind ([0128](/adr/0128-code-conventions-enums-classes-components-and-kind-folders) decision 4).
3. `raw/` holds only `@Controller` raw endpoints (webhooks, streaming, `/api/auth/*`). Actions never use it.
4. There are no `controllers/`, `dtos/`, `repositories/` or `presentation/` folders.
5. Dependencies point inward. Actions, listeners and workflows depend on services and models. Models import from no other
   folder.
6. Where the sources disagree, the later one wins. P9 names a `permissions.ts` file; the audit (L547) names a
   `permissions/` folder, and the folder wins.

## Consequences

- Services are organised by what they do, and an agent finds an action in `actions/`.
- The `services/encore` scaffold template, which still uses the old shape, is replaced with plain TypeScript (gap D).
- The validator's `checkServiceUnit` must describe this shape. Until it does, the validator and this ADR disagree.

## Enforcement

planned — `checkServiceUnit` in `tools/scripts/validate-repository.mjs` checks the kind-folder set and forbids the
`controllers/`, `dtos/`, `repositories/` and `presentation/` folders. Dependency direction is planned for the
`packages/tooling/oxlint/boundaries.jsonc` rules.

## Alternatives

- Keep DDD layers (0040): superseded by this ADR, per the owner's audit answer.
- One flat `modules/<feature>/` folder with no kinds: rejected, because it hides the action-first shape.

## Amendment 2026-10-21: one kind-folder list (STA-219)

**Context.** The kind-folder lists of [0126](/adr/0126-member-shapes-and-scaffold-templates) (decision 3),
[0130](/adr/0130-module-layout-by-semantic-kind) (decision 1) and [0264](/adr/0264-declaration-vocabulary-module-keys-define-family-and-kind-folders)
(decision 7) differ, and [0128](/adr/0128-code-conventions-enums-classes-components-and-kind-folders) assumed two more folders. The
owner settled one list on 2026-10-21. This amendment is the only list; the others point here.

**Decision.**

1. **Kind folders, each created with its first file** (in a feature module, in services and packages alike): `models/`,
   `actions/`, `queries/`, `services/`, `events/`, `listeners/`, `workflows/`, `policies/`, `permissions/`, `settings/`,
   `contracts/`, `resources/` (`@Resource` declarations only), `hooks/` (extension hook files `*.hook.ts` only, see
   [0128](/adr/0128-code-conventions-enums-classes-components-and-kind-folders) decision 5), `widgets/`, `pages/`,
   `links/`, `drivers/` and `ai/`. Five more are backed by their own ADRs and are carried by `tools/scripts/structure.mjs`:
   `migrations/` and `seeds/` ([0014](/adr/0014-data-ownership-and-orm)), `factories/` ([0022](/adr/0022-tests-live-in-tests-folders)),
   `schemas/` ([0095](/adr/0095-zod-inside-field-decorators)) and `components/` ([0128](/adr/0128-code-conventions-enums-classes-components-and-kind-folders)
   decision 2). `config/` holds typed configuration inside `src/` ([0126](/adr/0126-member-shapes-and-scaffold-templates) and
   [0177](/adr/0177-package-distribution-npmjs-and-keygen) amendments of 2026-10-21).
2. **Kind folders created once a module has two or more files of that kind:** `interfaces/`, `types/`, `constants/`,
   `tokens/`, `errors/`, `decorators/`, `enums/` and `internal/`. `internal/` holds a helper shared by two or more files of one
   package, not exported from any barrel ([0006](/adr/0006-naming-exports-and-imports) amendment 2026-10-21, decision 2).
   `enums/` holds const-object enums, one `<name>.enum.ts` per file, as
   [0128](/adr/0128-code-conventions-enums-classes-components-and-kind-folders) decision 1 names the file. The folder is
   named here for the first time; its threshold is the same as its neighbours' (two or more files). PR #84 (`tools/scripts/structure.mjs`)
   already uses `enums/` and cites 0128 decision 1; this decision makes that folder official.
3. **`raw/`** holds only `@Controller` raw endpoints (decision 3 above stands).
4. **Banned folders:** `controllers/`, `dtos/`, `repositories/`, `helpers/`, `utils/` and `presentation/`. A shared helper goes
   to `@stackra/support`, as [0006](/adr/0006-naming-exports-and-imports) now says.
5. **`assets/` is not a kind folder.** Static files sit in `assets/` at the package root, as [0126](/adr/0126-member-shapes-and-scaffold-templates)
   decision 2 now says. `resources/` is the `@Resource` folder above, and never a static-file folder.
6. **The service module path is `src/modules/<feature>/`.** A service's feature modules live under its `src/` folder. The DDD layer path
   `services/<svc>/modules/<feature>/{core,application,…}` that [0040](/adr/0040-ddd-feature-modules-in-services) described
   is not adopted.

**Consequences.**

- One list means one check. The validator and the scaffold read the same list, from `tools/scripts/structure.mjs` (STA-220).
- `presentation/` is now banned in every home, not only in services.

**Enforcement.** planned — `checkFileKinds` and `checkKindFolders` in `tools/scripts/validate-repository.mjs`, reading the list in
`tools/scripts/structure.mjs` (STA-220). Until they land, `checkServiceUnit` (decision 1 of the original page) is the only check, and it
does not know the banned list above.
