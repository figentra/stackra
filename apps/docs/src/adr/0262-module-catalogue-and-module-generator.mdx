## Context

A new feature starts as a blank folder that each author fills differently. An agent that adds a module has no machine-readable
statement of what the module contributes, so its files drift from the intent. The owner decided on 2026-10-21 that the intent is
written once, as data, and the files are emitted from it.

## Decision

1. **Catalogue per service.** Each service has a machine-readable catalogue, `docs/catalogue/<svc>.yaml`, in the figentra-os repository.
   A Markdown rendering is generated from it for review. Stackra packages have a package catalogue in this repository, with the same shape.
2. **The generator.** `pnpm new module <svc> <feature>` reads the module's catalogue entry and emits files:
   - the module file, its README, `definePermissions`, `defineEvents`, settings and `contracts`;
   - `@Model` stubs with TODO fields;
   - `@Action` and `@Query` stubs with a `key@1`, Zod placeholders, a permission and a risk level;
   - an `@Resource` stub;
   - an action body that throws `not_implemented`;
   - a module boot test.
3. **Contract docblocks.** Every emitted file opens with a contract block ([0007](/adr/0007-source-documentation-standard)) taken from
   the catalogue, so a file says what it is for before anyone edits it.
4. **Idempotent.** A re-run adds the files that are missing and never overwrites a file that exists. A re-run that finds nothing
   missing changes nothing.
5. **No empty folders.** A kind folder is created with its first file ([0126](/adr/0126-member-shapes-and-scaffold-templates)
   decision 3).
6. **The catalogue is the review surface.** A change to a module's contributions starts in its catalogue entry, then the files follow.

## Consequences

- A module starts in a shape that passes the validator, and each stub fails loudly until it is implemented.
- The catalogue becomes a second source of truth beside the code. Drift between them is a finding, so the check in Enforcement is required.
- Authors who edit the code without updating the catalogue leave the catalogue wrong; the generator never rewrites the code to match it.

## Enforcement

planned — `tools/scripts/__tests__/scaffold.test.mjs` renders a module twice and asserts that the second run creates no file and changes none,
and that every emitted file opens with a contract block. Planned: `pnpm validate` checks each catalogue against its schema.
