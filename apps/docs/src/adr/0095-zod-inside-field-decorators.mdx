## Context

With decorators as the only authoring style ([0094](/adr/0094-decorators-only-authoring)), fields on models and action inputs
need validation declared on the class. The Nest ecosystem uses class-validator and class-transformer, which depend on
`reflect-metadata` ([0011](/adr/0011-rejected-and-deferred-technologies)) and duplicate what Zod already does for forms and the
API client ([0055](/adr/0055-forms-react-hook-form-zod-heroui-adapters)). The IR already converts schemas to Zod
([0092](/adr/0092-ir-ported-definition-package-dropped)).

## Decision

1. **`@Field` takes a Zod schema**, and Zod is the only validation engine.
2. **Shorthand decorators** (for example `@Email()`, `@Uuid()`, `@Min()`) are sugar that build the same Zod schema. They are not a second engine.
3. **The class's Zod schema is derived from its fields** and is the schema used by actions, forms, the API client and the IR.
4. **class-validator and class-transformer are rejected.**

## Consequences

- One schema per shape, shared from database model to form.
- Every shorthand must map exactly to a Zod construct, and the set needs a maintainer.
- When confirmed, a row for class-validator and class-transformer is added to [0011](/adr/0011-rejected-and-deferred-technologies) by a superseding change.

## Enforcement

Planned: `FORBIDDEN_DEPENDENCIES` in `tools/scripts/validate-repository.mjs` gains `class-validator` and `class-transformer`.
Nothing checks this today.
