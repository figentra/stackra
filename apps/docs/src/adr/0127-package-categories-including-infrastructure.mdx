## Context

Package categories were fixed in the framework round as the FW2 table. The owner accepted it on 2026-10-20 (FW2 a). The
infrastructure category came later, for Pulumi-based infrastructure packages (ADR 0171, not yet on this branch). The owner then
added a `commerce` category for money, ledger and pricing primitives, which closes the placement that was open. Several other
placements were answered question by question. This ADR records the table and the placements, and marks the one open item.

## Decision

1. The package categories are:
   - **foundation:** contracts, validation, errors (ADR 0232, wave 1 part 5);
   - **data:** model, database, content, media, search, state-machine;
   - **application:** actions, ai, ir, registry;
   - **runtime:** outbox, queue, scheduler, workflow, realtime, locking, cache;
   - **communication:** webhooks, notifications, versioning, integrations (assumed, see 5);
   - **security:** connections, entitlements, licensing;
   - **experience:** ui, experience, navigation, console, panel;
   - **developer:** cli, gen, coding-standard, vite-plugin, skills, mcp [0282], renderers [0286];
   - **cross-cutting:** brand;
   - **commerce:** money, ledger and pricing primitives (owner answer, 2026-10-20). The pricing service and its
     building blocks are placed here as primitives; the service itself is an OS item;
   - **infrastructure:** new. It holds the `@stackra/infra-*` packages defined by 0171.
2. `state` stays a category, because existing packages (settings, feature flags, theming) use it and `AGENTS.md` lists it.
   The FW2 table did not name it. The owner should confirm it (open question 1).
3. The placements the owner set later are fixed: state-machine in data (SM1 placement, mem L405); panel in experience
   (mem L737); coding-standard in developer (mem L566); the Vite plugin is `@stackra/vite-plugin` in developer
   (DX10, mem L567); money and ledger in commerce (owner answer, 2026-10-20).
4. Errors sit in foundation, with `@stackra/errors` (ADR 0232).
5. Integrations sit in communication. This is **assumed**, pending the owner (register Thin list item 6, mem L753).

## Consequences

- The scaffold's category list, the `AGENTS.md` table and the packages guide must match this table. The
  `.agents/rules/workspace-layout.md` rule describes an "infrastructure" category that does not yet exist. That rule
  becomes true with this ADR, and it must add `commerce` and `errors` too. It belongs to `docs-governance`.
- A new package needs one category from this list. A package that fits none is a new ADR, not a new folder.

## Enforcement

planned — `tools/scripts/scaffold.mjs` (`CATEGORIES`) and `tools/scripts/validate-repository.mjs` rejecting a
`packages/<category>` folder that is not in this table.

## Alternatives

- No infrastructure category: the Pulumi packages would sit in developer. The owner chose the separate category (mem L437).
- Money and ledger in data or security: not chosen; the owner chose commerce.

## Amendment 2026-10-21: every member has one category (STA-219)

**Context.** Several packages on the roadmap and in the ADRs had no category in decision 1, so a new package had nowhere to go.
The rule of this ADR is one category per package, and a package that fits none is a new ADR. The owner settled that every
member gets a category on 2026-10-21. This amendment records the placement of each package named in the ADRs and the roadmap.

**Decision.**

1. **Every member has exactly one category.** A package outside a category folder is not allowed. A package that a category does not
   fit needs an ADR that adds the category.
2. **The placement table.** Each row names the category; the source of the placement is the ADR or roadmap row given in brackets.

   | Category       | Packages                                                                                                                                                                               |
   | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | foundation     | support, container, config, logger, events, transport, query, network, router, i18n [roadmap]; contracts, validation, errors [0232]                                                    |
   | data           | model, database, content, media, search, state-machine, assets, filesystem [0234 amends this table: assets and filesystem are data, not foundation], storage [structure.mjs, ADR 0256] |
   | application    | actions, ai, ir, registry                                                                                                                                                              |
   | runtime        | outbox, queue, scheduler, workflow, realtime, locking, cache, app, devices [roadmap; devices by owner settlement, 2026-10-21]                                                          |
   | communication  | webhooks, versioning, integrations, mail [0270; the registry places it here]                                                                                                           |
   | security       | connections, entitlements, licensing, identity, iam, tenancy, consent, csp [roadmap]                                                                                                   |
   | experience     | ui, experience, navigation, console, panel, kbd, pwa, platform [0250], peripherals [0253], builder, collaboration [0270; forms dropped]                                                |
   | developer      | cli, gen, coding-standard, vite-plugin, devtools-kit, testing [roadmap; testing per the build plan's Phase T], skills, mcp [0282], renderers [0286]                                    |
   | cross-cutting  | brand (moved from experience), analytics, seo [roadmap]                                                                                                                                |
   | state          | settings, feature-flags, theming, coordinator [roadmap]                                                                                                                                |
   | commerce       | money, ledger, pricing primitives (decision 1 above)                                                                                                                                   |
   | infrastructure | the `@stackra/infra-*` packages (ADR 0171)                                                                                                                                             |

3. **Brand moves to `cross-cutting`.** The package is at `packages/experience/brand` today. The folder move is a separate code change,
   not part of this ADR.
4. **A package in the preview repository without a category is not followed.** A flat placement such as the preview's
   `packages/loyalty-kit` takes a category when it is ported to this repository. Its category is not decided here.

**Consequences.**

- `tools/scripts/scaffold.mjs` (`CATEGORIES`), `AGENTS.md`, `.agents/rules/workspace-layout.md` and the packages guide must
  list the same twelve categories as decision 1 and this table. Each of them is out of step today, and the lead owns the rule and
  the guide.
- `@stackra/assets` and `@stackra/filesystem` are data. The roadmap's `foundation/filesystem` row is stale.

**Enforcement.** planned — `tools/scripts/validate-repository.mjs` `tierFor` rejects a `packages/<category>` folder that is not in
decision 1, and a package with no category fails the check. Nothing checks the table yet.
