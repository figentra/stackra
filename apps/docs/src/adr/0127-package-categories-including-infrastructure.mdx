## Context

Package categories were fixed in the framework round as the FW2 table. The owner accepted it on 2026-10-20 (FW2 a). The
infrastructure category came later, for Pulumi-based infrastructure packages (ADR 0171, not yet on this branch). Several placements were answered question by question, and two were not answered at all. This ADR records
the table and the placements, and marks the two open ones.

## Decision

1. The package categories are:
   - **foundation:** contracts, validation;
   - **data:** model, database, content, media, search, state-machine;
   - **application:** actions, ai, ir, registry;
   - **runtime:** outbox, queue, scheduler, workflow, realtime, locking, cache;
   - **communication:** webhooks, notifications, versioning, integrations (assumed, see 4);
   - **security:** connections, entitlements, licensing;
   - **experience:** ui, experience, navigation, console, panel;
   - **developer:** cli, gen, coding-standard, vite-plugin;
   - **cross-cutting:** brand;
   - **infrastructure:** new. It holds the `@stackra/infra-*` packages defined by 0171.
2. `state` stays a category, because existing packages (settings, feature flags, theming) use it and `AGENTS.md` lists it.
   The FW2 table did not name it. The owner should confirm it (open question 1).
3. The placements the owner set later are fixed: state-machine in data (SM1 placement, mem L405); panel in experience
   (mem L737); coding-standard in developer (mem L566); the Vite plugin is `@stackra/vite-plugin` in developer
   (DX10, mem L567).
4. Integrations sit in communication. This is **assumed**, pending the owner (register Thin list item 6, mem L753).
5. Money and ledger have **no category yet**. The owner did not state one (mem L517). Do not create the packages until this
   is answered (open question 2).

## Consequences

- The scaffold's category list, the `AGENTS.md` table and the packages guide must match this table. The
  `.agents/rules/workspace-layout.md` rule describes an "infrastructure" category that does not yet exist. That rule
  becomes true with this ADR. It belongs to `docs-governance`.
- A new package needs one category from this list. A package that fits none is a new ADR, not a new folder.

## Enforcement

planned — `tools/scripts/scaffold.mjs` (`CATEGORIES`) and `tools/scripts/validate-repository.mjs` rejecting a
`packages/<category>` folder that is not in this table.

## Alternatives

- No infrastructure category: the Pulumi packages would sit in developer. The owner chose the separate category (mem L437).
- Other placements for money, ledger and integrations are not recorded in the sources. Only the owner can choose them.
