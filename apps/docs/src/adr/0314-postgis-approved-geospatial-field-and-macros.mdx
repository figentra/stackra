## Context

Location and tracking data, such as fleet positions, service areas and delivery zones, need geospatial column types and spatial indexes. [0160](/adr/0160-raw-sql-at-runtime-and-the-approved-postgres-extensions) approved five Postgres extensions and left PostGIS out until an ADR approved it. The geography work belongs to the geography service, which is a layer 2 platform core service ([0201](/adr/0201-the-app-split-framework-platform-core-and-first-party-apps)). The owner approved PostGIS on 2026-10-24, with the field types, the macros and the index type below.

## Decision

1. **PostGIS is approved.** It joins the approved extensions of [0160](/adr/0160-raw-sql-at-runtime-and-the-approved-postgres-extensions), decision 2. It is enabled only by the built-in `schema.createExtension()` migration step, and not by a raw `schema.sql` file or a raw query.
2. **The geospatial field types, their macros and their index.**
   - Geospatial values are field types, not decorators, as the v3 Note of [0133](/adr/0133-field-semantics-model-keys-rename-safe-fields-and-lifecycle-events) gives money and JSON. The types are `GeoPoint`, `GeoPolygon` and `GeoLine`.
   - Each type is stored as a PostGIS column with SRID 4326 (WGS 84): `GeoPoint` is `geography(Point, 4326)`, `GeoPolygon` is `geography(Polygon, 4326)` and `GeoLine` is `geography(LineString, 4326)`.
   - The migration blueprint gains three macros: `t.point()` for a `GeoPoint` column, `t.polygon()` for a `GeoPolygon` column and `t.line()` for a `GeoLine` column.
   - Each geospatial column has a GiST index by default. The index is named with the `idx_` prefix of [0231](/adr/0231-naming-and-casing-standard).
   - `HasLocation` is a trait, named under [0096](/adr/0096-trait-naming-grammar), that adds `location: GeoPoint` to a model.
3. **Ownership.** The geography service's package owns the three field types, the macros, the GiST index support and the `HasLocation` trait. No other package defines its own geospatial field type, macro or location trait.

## Consequences

- A location feature uses one approved extension, and it does not need a new service.
- Each environment that runs the geography package needs PostGIS installed in its Postgres, including on-prem and air-gapped deliveries ([0179](/adr/0179-on-prem-and-air-gapped-delivery)). [0160](/adr/0160-raw-sql-at-runtime-and-the-approved-postgres-extensions) already makes every approved extension a dependency of every environment.
- The deferral of the geospatial field in [0133](/adr/0133-field-semantics-model-keys-rename-safe-fields-and-lifecycle-events) is lifted, so no revival trigger is needed.

## Enforcement

planned — gen rejects a `schema.createExtension()` call that names an extension outside the approved list of [0160](/adr/0160-raw-sql-at-runtime-and-the-approved-postgres-extensions), and rejects a `GeoPoint`, `GeoPolygon` or `GeoLine` column that has no GiST index. Nothing checks either rule yet.
