## Context

[0171](/adr/0171-infrastructure-as-code-pulumi-typescript-owned-by-stackra) and [0172](/adr/0172-aws-accounts-primary-region-and-cloud-cost-controls) assumed one cloud, AWS, with one account per product. The `me` region runs in the UAE ([0353](/adr/0353-data-residency-three-regions-fixed-at-sign-up-a-global-login-directory-and-copies-within-a-jurisdiction)), but KSA customers that must be hosted in the kingdom cannot be served there, and AWS has no Saudi region until later this year. GCP has a region in Dammam today. The owner decided on 2026-10-25 (OS rounds 1 and 2) that Stackra supports both AWS and GCP, and that accounts are split per product and region.

## Decision

1. **Two clouds.** Stackra deploys to AWS and GCP. No other cloud is supported without a new ADR (OS-3, round 2).
2. **One AWS account per product-region.** Each product gets one AWS account in each region it runs in, plus the one shared and tooling account (OS-1). This replaces "one AWS account per product" in [0172](/adr/0172-aws-accounts-primary-region-and-cloud-cost-controls) decision 1; the rest of that decision (environments by IAM roles, tags and service control policies, Identity Center, no IAM users) stands.
3. **Where each cloud runs.**
   - AWS: the UAE (`me-central-1`) for `me` now, Frankfurt (`eu-central-1`) for `eu`, and the AWS Saudi region when it opens (OS-3, round 2).
   - GCP: Dammam, for KSA in-country hosting now (OS-3, round 2).
4. **`@stackra/infra-gcp`.** A new package in the infrastructure category holds the GCP Pulumi components, beside `@stackra/infra-aws` ([0171](/adr/0171-infrastructure-as-code-pulumi-typescript-owned-by-stackra) decision 2). Its licensing follows 0171 decision 5: the foundation is free, an own-cloud runtime stack is `@stackra-pro`.
5. **A cloud dimension in `runway.yaml`.** Each region or deployment in `runway.yaml` names its cloud (AWS or GCP) and its cloud region. The field names are set by the Runway schema, not here.
6. **Runway drives both clouds.** `stackra runway infra preview|up` drives the `@stackra/infra-aws` and `@stackra/infra-gcp` components through the Pulumi Automation API ([0352](/adr/0352-runway-is-the-one-deployment-tool-pulumi-is-its-infrastructure-engine-gen-is-its-build-step) decision 4). A GCP target is a Runway provider behind the same port (plan, apply, verify, rollback, 0352 decision 3). There is no second tool.

## Consequences

- Budgets, blast radius and residency evidence are separate per product and jurisdiction; there are more AWS accounts to create and watch ([0172](/adr/0172-aws-accounts-primary-region-and-cloud-cost-controls) decision 5 applies per account).
- Every service that touches the cloud needs a driver for both clouds where it differs: object storage, queues, secrets sync and malware scanning (ClamAV where GuardDuty is not offered, OS-142).
- `figentra/infra` holds GCP stack state and config as well as AWS ([0289](/adr/0289-runway-and-environments-workers-one-encore-app-previews-and-publishing) decision 9).

## Enforcement

planned — the Runway schema refuses a region or deployment without a cloud; `@stackra/infra-aws` creates one account per product-region through Organizations; `@stackra/infra-gcp` conformance tests run against the same provider port (STA-72, STA-607).

## Open questions

1. **Shape of KSA on GCP.** Round 2 says "GCP (Dammam for KSA in-country now)". It does not say whether this is one shared KSA stack for every KSA tenant who needs in-country hosting, or a dedicated deployment per customer, as the 2026-10-24 Note on [0186](/adr/0186-backups-and-disaster-recovery) describes. It also does not say whether KSA in-country is a fourth region key beside `eu`, `me` and `us` or a kind of deployment.
2. **Egypt.** Where Egypt tenants are served is not decided. In round 1 the owner wrote that Egypt was unclear ("owner thinks Google"); round 2 named no Egypt location. The OS-3 recommended option, Egypt tenants as `me` tenants served from the UAE, was not taken by the owner. Counsel must also check the Law 151 transfer licence.
3. **KSA and AWS Saudi.** Whether KSA tenants hosted on GCP move to AWS Saudi when it opens, how and when they move, and whether GCP is then retired, is not decided. The owner said only "AWS ... Saudi when it opens" and "GCP (Dammam for KSA in-country now)".
4. **Runtime on GCP.** [0170](/adr/0170-deployment-what-deploys-where-and-how-a-release-is-promoted) decision 3 runs the OS on Encore Cloud on our AWS. Whether the GCP stack runs on Encore Cloud on our GCP or on another runtime is not decided.
5. **Vendors in KSA.** Which ZITADEL, AI model and email setup a GCP KSA stack uses is not decided beyond the rules of [0353](/adr/0353-data-residency-three-regions-fixed-at-sign-up-a-global-login-directory-and-copies-within-a-jurisdiction) decision 9.
