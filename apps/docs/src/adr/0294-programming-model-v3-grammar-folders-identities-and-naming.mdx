## Context

Stackra's authoring rules grew one record at a time. A class stated its kind twice, once in a decorator and once in
its base class. The same word meant several things (guard, hook, provider, command). The folder a file lived in was a
judgement call, and identities such as module keys, permission names and event names were typed by hand, so they could
drift from the folder or file that held them. Zod schemas repeated types that TypeScript already stated. This record
sets one grammar for every member, one home for every suffix, identities derived from names and locked in
`stackra.manifest.json`, and one meaning for each word. Build and entry shape, runway and the web runtime are decided
in the separate records of this wave: [0295](/adr/0295-build-and-entry-stackra-config-generated-tool-configs-and-entries)
(build and entry), [0296](/adr/0296-runway-v3-member-requires-and-root-topology-groups) (runway) and
[0297](/adr/0297-web-runtime-on-workers-prerender-caching-locale-urls-and-forwarding) (web runtime).

## Decision

### Grammar

1. **The path says the kind (R1).** A file is `<scope>/<group>/<name>.<kind>.ts(x)`. A folder kind (routes, blocks,
   components) is `<scope>/<group>/<name>/<name>.<kind>.ts(x)`. The scope is a module folder (`src/modules/<key>/` in a
   service, `src/node/` in a package) or the member's `src/`. Each suffix has exactly one home group per tier, and a
   group may hold several related suffixes. The one exception is `.change.ts`, which sits beside its subject: in
   `events/` for an event version, in `schemas/` for a dated response change. Tests sit in
   `__tests__/<name>.<kind>.test.ts` beside their subject ([0022](/adr/0022-tests-live-in-tests-folders)).

2. **One primary export per file, named from the file (R2).** The class is `PascalCase(stem) + PascalCase(kind)`, so
   `cancel-order.action.ts` exports `CancelOrderAction`. Noun kinds (model, schema, enum, event, signal, analytics
   event, type) take no suffix in the class name, and their files keep the file suffix. Error classes end in `Error`.
   These companions may share the file: `<Name>Input` and `<Name>Output` in an action, query or prompt; `<Name>Props`
   in a component; `<Name>Data` in a notification.

3. **The base class is the kind; its options are the argument (R3).** Examples: `extends Action({ key })`,
   `extends Workflow({ timeout })`, or the bare `extends Signal` when there are no options. A class extends exactly one
   kind base exported by a `@stackra/*` package, and that base's identifier is `PascalCase(kind)`, with these aliases:
   `.event.ts` takes `DomainEvent`, `IntegrationEvent` or `WebhookEvent`; `.error.ts` takes `Refusal`; `.service.ts`
   takes `Service` or `CrudService`; `.model.ts` takes `Model.with(...)`. An override or a placement extends the class it
   overrides, as in `Widget.place(...)`. Options never hold a fact that gen derives. A member that replaces a base
   member with a default, such as a resource's `table()` or a route's `meta`, is marked `override`; only an abstract
   member (`handle`, `definition`, `check`) goes without it, because the presets keep `noImplicitOverride` on.

   ```ts
   // orders/actions/cancel-order.action.ts
   export class CancelOrderAction extends Action({ key: "order.cancel" }) {
     async handle(input: CancelOrderInput, ctx: ActionContext): Promise<CancelOrderOutput> {
       // ...
     }
   }
   ```

4. **The TypeScript type gives the shape (R4).** A field's type is its rule, its column type and its wire type. The
   initializer is the default; `?:` means optional and `| null` means nullable. A `number` field carries `@Int` or
   `@Num`. A literal union, `any` or an unknown alias fails gen with a message that asks for an enum or a schema class.
   Gen compiles each shape class to one Zod schema in `#stackra/schemas` and each model to MikroORM `EntitySchema`
   metadata, so authors do not write Zod. A listener and a notification react to the type of their event parameter. A
   workflow starts on an event only through `startOn:`. A driver choice is a config field typed `DriverName<Port>`.
   Decisions 25 to 28 say how kind bases, the shape compiler, models and tables work in detail.

5. **Names give identity (R5).** An author writes each wire name once: an action or query `key`, an event `name`, an
   analytics event `name`, a route `path` and a custom endpoint path. Every other identity is derived (decision 20).
   `stackra.manifest.json` locks every identity, derived or written, and a change fails `stackra gen --check` unless the
   class or field carries `@Renamed(old)`.

6. **Decorators are of three categories, and nothing else (R6).**
   - **Field:** constraints (`@Str`, `@Int`, `@Num`, `@List`), transforms (`@Trim`, `@Lowercase`), serializers (`@Hidden`,
     `@Visible`), relations (`@ManyToOne`, `@OneToMany`, `@ManyToMany`, `@OneToOne`), sources (`@Env`, `@Secret`),
     `@Setting(options)`, `@Renamed(old)` and the escape hatch `@Field(zod)`. A field decorator constrains, disambiguates,
     transforms, serializes, relates or adds a source. It never restates a type. It records metadata only and never
     installs an accessor, because a class field defined on the instance hides a prototype accessor. Each field
     decorator is typed against its field, so the type checker refuses `@Int` on a string, `@List` on a field that is
     not an array, and a `@Field(zod)` whose output type differs from the field.
   - **Method:** `@Step(options)` and `@Transition(options)`, for workflow steps and state transitions only.
   - **Class facet:** `@Index`, `@Searchable`, `@Auditable`, `@AccessLogged`, `@Lifetime`, `@Replaces` and `@Renamed`, for a
     table fact or a capability another package reads.

   Banned: kind decorators of every name, parameter decorators, empty decorators and string tokens. The retired kind
   decorators are `@Model @Action @Query @Resource @Module @App @Service @Settings @Config @Event @Listener @OnEvent
@Workflow @Widget @Route @Layout @Panel @Menu @Block @Document @Flag @Store @Shortcut @Bridge @Policy @Permissions
@Permission @Guard @Link @Hook @HookPoint @Override @Provider @ContextProvider @Injectable @Inject @Crud @Mail
@Migration @Seeder @Factory @AsEndpoint @AsTool @AsJob @Cron @DriverOf @Driver @MoneyColumn @HasState @Json
@Controller @Projection`. A raw endpoint and a read model are base-class kinds like every other: `Controller` and
   `Projection` in the kind table (decision 16).
   Every decorator is made with `createDecorator` from `@stackra/container` and is registered with the kinds it may
   target. The decorator test: if the folder, the suffix, the base class, a field type, a method name or a derived name
   already says it, write no decorator.

7. **Function kinds are never classes (R7).** Components (`.tsx`), React hooks (`use-<name>.ts`), plain functions
   (`functions/<name>.function.ts`), server-only helpers (`<name>.server.ts`) and mail templates (`.mail.tsx`) are
   functions. There are no class components: a route's class is its page class.

8. **Companion types (R8).** A type that serves one declaration stays in its file under a fixed suffix (Props, State,
   Options, Input, Output, Data). When a second file imports it, it moves to `types/<name>.type.ts`, or to
   `src/contracts/types/` when it is a package's public type. Enums always get their own file. An exported signature has
   no anonymous object type with two or more members.

9. **Formatting (R9).** Lint autofixes one blank line between class members, and one property per line for an object
   literal with two or more properties inside decorator or base-factory arguments. Every file starts with the
   four-field header (Purpose, Boundary, Runtime, Governing contract), and every member carries a one-line TSDoc.

10. **Generated output is never authored (R10).** `.stackra/` is fully gitignored. The committed generated contracts sit
    at the member root: `stackra.manifest.json` and `openapi.json`. A tool that reads only the member root reads a
    gitignored shim there.

11. **Model references are thunks (R11).** Inside a decorator a model is a thunk, as in `@ManyToOne(() => Variant)`. A
    model is passed directly only as the first argument of a base factory: `Resource(Order)`, `Factory(Order)`,
    `CrudService(Order)`, `StateMachine(Order)` and `Facts(Order)`. A relation to a model of the same module is typed
    `Ref<T>` for one target or `Collection<T>` for many, and has a foreign key. A relation to a model of another
    module is typed `Link<T>` (decision 28).

12. **One member shape (R12).** Every member authors `stackra.config.ts` and one root module, `src/<key>.module.ts`
    (`src/node/<key>.module.ts` in a package). Nobody writes `main.ts` or an entry barrel; the generated entries are
    described in [0295](/adr/0295-build-and-entry-stackra-config-generated-tool-configs-and-entries). Two kinds of
    member are exempt and have neither file: the docs app (`apps/docs`, a Mintlify site with no TypeScript runtime)
    and the `tier:config` presets in `packages/tooling/`, which are tool configuration and hold no module.

### Group folders and the kind table

13. **Module groups.** A module (`src/modules/<key>/` in a service, `src/node/` in a package) holds the groups below. A
    group folder appears with its first file.

    | Group                                | Holds                                                                                                        |
    | ------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
    | (root)                               | `<key>.module.ts`, `<key>.settings.ts` (one settings group per module), `README.md`                          |
    | `models/`                            | `.model.ts`, `.state-machine.ts`, `.bucket.ts`, `.projection.ts`                                             |
    | `actions/`                           | `.action.ts`                                                                                                 |
    | `queries/`                           | `.query.ts`                                                                                                  |
    | `schemas/`                           | `.schema.ts` (shapes shared by two or more files), `.change.ts` (dated response changes beside their schema) |
    | `enums/`                             | `.enum.ts`                                                                                                   |
    | `errors/`                            | `.error.ts`                                                                                                  |
    | `events/`                            | `.event.ts`, `.change.ts` (event versions beside their event)                                                |
    | `listeners/`                         | `.listener.ts`                                                                                               |
    | `workflows/`                         | `.workflow.ts`, `.signal.ts`                                                                                 |
    | `access/`                            | `.permissions.ts`, `.policy.ts`, `.role.ts`, `.entitlement.ts`, `.precondition.ts`, `.flag.ts`               |
    | `services/`                          | `.service.ts`, `.repository.ts` (only for named reads beyond `CrudService`)                                  |
    | `drivers/`                           | `.driver.ts`                                                                                                 |
    | `extensions/`                        | `.extension-point.ts`, `.extension.ts`, `.interceptor.ts`                                                    |
    | `raw/`                               | `.controller.ts`, in a service only ([0130](/adr/0130-module-layout-by-semantic-kind) decision 3)            |
    | `resources/<model>/`                 | `.resource.ts`, `.widget.ts`, `.document.ts`, `.notification.ts`, `.mail.tsx`                                |
    | `database/migrations/`               | `NNNN-<name>.migration.ts`, numbered per module                                                              |
    | `database/factories/`                | `<model>.factory.ts`                                                                                         |
    | `database/seeders/`                  | `minimal.seeder.ts`, `demo.seeder.ts`, `test.seeder.ts`                                                      |
    | `ai/`                                | `.prompt.ts`, `.skill.ts`, `.facts.ts`                                                                       |
    | `functions/`, `constants/`, `types/` | `.function.ts`, `.constant.ts`, `.type.ts`                                                                   |

    `resources/<model>/` names a model the module owns or may reference. Only an owned model has a `<model>.resource.ts`.

    `database/` belongs to the module, like every other group: a service has one per module
    (`src/modules/<key>/database/`) and a package has one in `src/node/`. Migrations are numbered per module, from
    `0001` with no gaps, and a module's migrations change only its own Postgres schema (decision 20). Gen merges the
    modules' streams, and those of the packages a host uses, into the ordered SQL of
    [0159](/adr/0159-migrations-gen-ordered-sql-and-safety-rules) decision 2: modules in dependency order, then each
    module's migrations by number.

14. **App groups.** An app's `src/` holds the groups below.

    | Group                                                                                          | Holds                                                                                                                                                           |
    | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
    | (root)                                                                                         | `<key>.module.ts`; `app.error.tsx` (the root error boundary)                                                                                                    |
    | `config/`                                                                                      | `.config.ts`, including the overrides `desktop.config.ts` and `chrome.config.ts`                                                                                |
    | `panels/`, `menus/`, `shortcuts/`, `documents/`, `stores/`, `flags/`, `analytics/`, `bridges/` | `.panel.ts`, `.menu.ts`, `.shortcut.ts`, `.document.ts`, `.store.ts`, `.flag.ts`, `.analytics-event.ts`, `.bridge.ts`                                           |
    | `routes/<name>/`                                                                               | `<name>.route.ts` or `<name>.layout.ts`, `<name>.tsx`, optional `<name>.error.tsx` and `<name>.fallback.tsx`, `<name>.server.ts`, `use-<name>.ts`, `__tests__/` |
    | `blocks/<name>/`                                                                               | `<name>.block.ts`, `<name>.tsx`, optional `<name>.native.tsx`, `__tests__/`                                                                                     |
    | `components/<name>/`                                                                           | `<name>.tsx`, optional `<name>-<part>.tsx` and `use-<name>.ts`, `index.ts` (the component and its Props only), `__tests__/`                                     |
    | `hooks/`                                                                                       | `use-<name>.ts`, only with two or more importers                                                                                                                |
    | `overrides/<owner>/`                                                                           | `<block-or-widget>.override.tsx`                                                                                                                                |
    | `providers/<name>/`                                                                            | only for the `Module({ wrap })` escape hatch                                                                                                                    |
    | `enums/`, `types/`, `styles/`                                                                  | `.enum.ts`, `.type.ts`, `.css`                                                                                                                                  |

15. **Package entry folders.** A package's `src/` holds `contracts/` (the leaf: `ports/`, `enums/`, `types/`), `config/`
    (the config classes), `core/` (isomorphic code: services, drivers, errors, functions, schemas and blocks), `node/`
    (the module folder, with the module groups above), `react/<name>/` and `native/<name>/` (renderers), `testing/`
    (`fakes/` and `matchers/`), and `<entry>/<pkg>.explorer.ts` only in a package that ships decorators. Dependencies run
    one way: core imports contracts, node, react and native import core, and testing imports them all. No symbol is
    exported from two entries, and the entry barrels are generated, never authored.

16. **The kind table.** Every kind is declared by its base class. The last column says whether the class is a binding in
    the container (`yes`), a value (`no`), an abstract port (`token`), or depends on the kind (`per kind`).

    | Kind                                                         | Declared as                                                                                                                                                    | Binding  |
    | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |
    | Module                                                       | `extends Module` or `Module({ exports, imports, wrap })`; `imports` on roots only, `wrap` on app roots only                                                    | no       |
    | Settings                                                     | `extends Settings({ scopes })`, one per module                                                                                                                 | no       |
    | Model                                                        | `extends Model.with(...traits)`                                                                                                                                | no       |

17. **Classes are the only tokens.** A constructor parameter names its token by its type, so there is no `@Inject`,
    `@Injectable` or string token. `@Lifetime(Lifetime.Request)` and `@Lifetime(Lifetime.Transient)` are the only scope
    markers; a class without one is a singleton, and the word "scope" is kept for settings and IAM. A named instance is
    the type `Named<Port, "x">`.

18. **Steps, actions and jobs.** A workflow's steps are its public async methods, run in declaration order. `@Step` takes
    only options: `after` (for a graph that is not a line), `when`, `heartbeat`, `retry`, `waitFor`, `correlate` and
    `timeout`. `undo<Step>` compensates a step, and `output()` returns the run's result. The run's type is `Run<W>`,
    whose conditional types test the bare workflow type `W`, not `this`, so `run.results.<step>` resolves inside a
    subclass and includes inherited steps. A job is an action run from a queue or a cron schedule through its `job:`
    option; it is not a kind.

19. **Configuration is a class.** A configuration is `class X extends Config` in `src/config/<name>.config.ts`, with its
    key derived. A new configuration class extends a picked, omitted, partial or intersected class, or stands alone.
    A host overrides a package's configuration with a `<Host><Base>` subclass that declares `override` members only and
    no new field. An override of a field typed as a literal union, such as `DriverName<Port>` or an enum, restates the
    base type (`override ledger: DriverName<LoyaltyLedger> = "memory"`), because a bare literal does not type-check
    against the base, and `as const` is not used on an override. A custom driver class is bound with `@Replaces(Port)`.
    An environment value is an `@Env("NAME")` field and a secret is a `@Secret("NAME")` field; the environment and
    runway layers apply after the class is constructed. A nested object is replaced whole by an override, and a host
    merges it explicitly. Retired: `defineConfig`, `registerAs`, `extendConfig`, the `override()` and `hostConfig(...)`
    helpers, `@Config(key)` and `@DriverOf`.

### Derived identities

20. **Identities are derived from names.** Gen derives every identity below and locks it in `stackra.manifest.json`.

    | Identity                | Formula                                                                                                                        | Example                                             |
    | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------- |
    | Member key              | Package name without its scope, snake_case                                                                                     | `commerce`, `loyalty_kit`                           |
    | Module key              | Folder name, snake_case                                                                                                        | `orders`                                            |
    | Model key, table        | `<module>.<snake(Class)>`; the table is snake_case and plural, in the module's Postgres schema                                 | `orders.order_line`, `orders.order_lines`           |
    | Permission              | `<module>.<snake(class minus "Permissions")>.<snake(static)>`                                                                  | `orders.order.cancel`                               |
    | Role, flag              | `<module>.<snake(class minus suffix)>`                                                                                         | `orders.order_clerk`, `orders.quick_order`          |
    | Settings group, field   | The module key; the field is the property name                                                                                 | `orders.autoCancelAfterMinutes`                     |
    | Config key              | The member or package key for the file named after it; otherwise `<member>.<snake(stem)>`; an override inherits its base's key | `loyalty_kit`, `commerce.rate_limit`                |
    | Error code              | `snake(class minus "Error")`                                                                                                   | `order_not_payable`                                 |
    | Action or query key     | `<module>.` + the written `key` + `@<major>` (1 unless `version:` is given)                                                    | `orders.order.cancel@1`                             |
    | Integration event       | `<module>.` + the written `name` + `.v<n>`                                                                                     | `orders.order.paid.v1`                              |
    | Endpoint                | The convention of decision 21                                                                                                  | `PUT /orders/:orderId/cancel`                       |
    | Notification, templates | `<module>.<snake(class minus "Notification")>`; `<module>::<notification>.<channel>`                                           | `orders.order_receipt`, `orders::order_receipt.sms` |
    | Widget, block, route    | `<module>.<snake(stem)>`, `<member>.<snake(folder)>`, `Routes.<snake(folder)>`                                                 | `orders.revenue_today`, `web.cta_banner`            |
    | Seeder                  | `<module>.<profile>`                                                                                                           | `orders.demo`                                       |
    | i18n default keys       | `<module>::<kind>.<name>.<part>`                                                                                               | `orders::actions.order.cancel.confirm`              |

    Each module's tables live in a Postgres schema named after the module key, inside the service's one logical
    database ([0238](/adr/0238-database-and-connection-model)). Two modules of one service may therefore each own
    a `Tag` model: their tables are `orders.tags` and `catalogue.tags`, where a table name derived from the class alone
    would collide. Constraint names follow [0231](/adr/0231-naming-and-casing-standard): `idx_` for indexes, `fk_` for
    foreign keys and `ck_` for check constraints.

21. **Endpoints follow a convention.** Gen maps a key to a route the way Rails resource routing does.

    | Key                                             | Route                       |
    | ----------------------------------------------- | --------------------------- |
    | `x.list`                                        | `GET /xs`                   |
    | `x.get`                                         | `GET /xs/:xId`              |
    | `x.create`                                      | `POST /xs`                  |
    | `x.update`                                      | `PATCH /xs/:xId`            |
    | `x.delete`                                      | `DELETE /xs/:xId`           |
    | Any other action verb, when the input has `xId` | `PUT /xs/:xId/<verb-kebab>` |
    | Any other action verb, otherwise                | `POST /xs/<verb-kebab>`     |
    | Any other query name                            | `GET /xs/<name-kebab>`      |

    `endpoint: { method, path }` overrides the route, and `endpoint: false` removes it. An action whose actors include
    neither a user nor an agent gets no public endpoint.

22. **The manifest lock.** `stackra.manifest.json` records every identity. A changed identity fails `stackra gen --check`
    unless the class or field carries `@Renamed(old)`. Gen also fails when a derived i18n key is missing in any locale;
    `stackra gen --fix-lang` adds missing keys to the default locale.

### Kind bases, the shape compiler and models

Three spikes (STA-335) built a kind base usable both bare and called, the type-to-schema compiler on template shapes,
and MikroORM `EntitySchema` emission from model classes. All three worked once the rules below were added.

25. **The kind-package contract.** A kind package builds each kind base so that it works both as `extends X` and as
    `extends X({ ... })`, and the declared type decides which forms a kind allows.
    - Each factory returns an exported, named class type (`ActionClass`, `WorkflowClass<I>`, `ResourceClass<M>`), and
      each instance base carries a type-only `~kind` brand, so one kind cannot stand in for another and a consumer's
      declaration emit works. A parameter that takes a class of some kind, such as `operations.create` or `startOn`, is
      typed `abstract new (...args: any[]) => XBase`, because a class with injected constructor parameters does not fit
      a zero-argument constructor type.
    - A kind base assigns no fields in its constructor and keeps no state made there. The presets set
      `useDefineForClassFields: true` ([0300](/adr/0300-published-tooling-presets-and-enforced-spell-checking)
      decision 6), and under that setting a subclass field declaration resets what a base constructor assigned.
    - Declaration files erase kind options, decorators and initializers. Gen therefore reads a kind's options from source
      for its own member, and from a dependency's committed `stackra.manifest.json` or generated output, never from the
      dependency's `.d.ts`. A member that authors kinds never turns on `isolatedDeclarations`, which refuses an
      expression such as `Action({ ... })` in an `extends` clause.

26. **The shape compiler.** Gen compiles shape classes to Zod on the TypeScript 7 compiler API behind a small host seam,
    with a TypeScript 6 host as the fallback; it does not use ts-morph. The rules are these:
    - Gen sorts source files by path before it reads them, so its output does not change when the import graph does.
    - `?:` compiles to `.exactOptional()`, because the presets set `exactOptionalPropertyTypes`. A `Date` field compiles
      to a codec: ISO 8601 with an offset on the wire, a `Date` in code.
    - A `number[]` or a map of numbers carries `@Int({ each: true })` or `@Num({ each: true })`.
    - A default is a constant: a literal, an enum case, a literal-typed constant, or a value built by one of a closed set
      of platform constructors that gen evaluates (`Duration.*`, `Money.of`). Any other initializer fails gen. A field
      initialized with an enum case states the enum type (`status: OrderStatus = OrderStatus.PendingPayment`), or gen
      sees only one literal and refuses it with the fix. Decorator arguments are literals or literal-typed constants.
    - A union of schema classes compiles to a discriminated union, with an enum case as the discriminant. Any other union
      beyond `T | null` needs the `@Field(zod)` hatch, which carries a reason.
    - For each shape, gen also emits a type `X$Check` that asserts the compiled schema's output type equals the class's
      fields, so the type checker proves the compiler right at no runtime cost.
    - Generated schema names are qualified by module, so a class name used in two modules does not collide.
    - A package ships its own generated schemas (its `X$`) and manifest entries. A host builds on them, with
      `Base$.extend(...)` for a configuration override, `CursorInput` and `Page.of(...)`, and never compiles a
      dependency's shapes again.
    - The registry behind `DriverName<Port>` is keyed by the port's key, so two ports with the same members never share
      driver names.
    - The generated code uses zod 4 (4.1 or later is needed for codecs and `.exactOptional()`), pinned exactly at 4.6.7
      in this repository's catalog and the template's.

27. **Models hold no constructor-made state.** The ORM builds a loaded row without running its constructor, so a model
    or trait has no `#private` field and no transient initializer, and a domain event that `order.record()` collects is
    kept outside the instance. A model that narrows a trait field uses `declare`, because a redeclared field would
    reset the trait's initializer. Models are built through `em.create`, factories or `CrudService`, never with `new`.
    Gen's `EntitySchema` output indexes every many-to-one and link column (the Postgres platform does not index foreign
    keys), maps a `string` with no `@Str({ max })` to `text`, writes defaults and enum items explicitly, emits the
    optional-properties augmentation the ORM's `create` typing needs, and turns off the ORM's default-value inference.
    `Money` is stored in minor units in a Postgres `bigint` column, read as a JavaScript `number`; the money type
    refuses a value above `Number.MAX_SAFE_INTEGER`.

28. **A cross-module relation is a `Link<T>`.** A relation to a model of another module is typed `Link<T>`. Gen stores
    the target's public id in an indexed `<name>_id` column with no foreign key, no join and no target metadata.
    `link.id` needs no load, a filter takes a raw id, and `link.load()` runs the owning module's generated query. A
    `Link` has no `unwrap()`, so the ORM never treats it as a loadable reference. Gen derives whether a relation is a
    link from module ownership, and fails with a fix when the annotation disagrees (`Ref<T>` across modules, `Link<T>`
    inside one).

## Consequences

- A class states its kind once, in its `extends` clause, and a file's kind is read from its path. A reader and an agent
  find the kind of any file without reading its body.
- Placement needs no judgement, because each suffix has one home group. A file in the wrong group fails the check that
  STA-338 adds.
- A rename is a `@Renamed` and a reviewable manifest diff. A folder move no longer changes a wire name, but a changed key
  or name does, and the manifest shows it.
- Gen does more work: it compiles types to Zod and MikroORM metadata, and it writes the manifest and the wiring. The
  spikes of STA-335 showed that the kind bases, the type compiler and the `EntitySchema` emission work, with the rules
  of decisions 25 to 28; the spike code stays outside this repository and is not a package.
- Kind authors give up a few TypeScript shortcuts: no `isolatedDeclarations`, `override` on every member that
  replaces a default, and no constructor-made state in models or kind bases.
- The template and the members of this repository still use the pre-v3 shapes until STA-337 (the template) and
  STA-344 (this repository) convert them, and the new checks of STA-338 do not fail on them until those checks land.
- Authors write `@Int` or `@Num` on every `number`. A plain `number` fails gen.
- Derived names are less visible in source. `stackra ls <kind>`, which lists declarations from the manifest, is the way
  to see them; it is planned.

wrongly. Each item names the decision or rule it changes. Everything else stands.

**Decision.**

1. **Integration and Connection are kinds (decisions 13 and 16).** _Superseded in part by ADR 0305 (rule 5) and ADR 0308 (rule 2): a connection is `extends Connection<SomeIntegration>`, with the subject as a type argument._ An integration is `extends Integration({ provider })`
   in `integrations/`, and a connection is `extends Connection(SomeIntegration, { ... })` in `connections/`. Both
   groups join the module groups of decision 13, holding `.integration.ts` and `.connection.ts`.
2. **`@Secret` names its secret (R6, decision 19).** A secret field is always `@Secret("NAME")`, on a config class and
   on a connection alike. A bare `@Secret` fails gen with `secret_name_missing`.
3. **`@Classified` is a field decorator (R6).** `@Classified(DataClassification.X)` joins the serializers (`@Hidden`,
   `@Visible`) as the privacy and serialisation category: it records the class of data a field holds.
4. **The app groups gain `schemas/` and `errors/` (decision 14).** _The root error boundary part is superseded by ADR 0305 (rule 35): `app.error.tsx` leaves the root, and `@stackra/navigation` owns the boundary. The `schemas/` and `errors/` groups stand._ They hold `.schema.ts` and `.error.ts` in an app as
   in a module. The `.error.tsx` error boundaries stay at the root and in route folders.
5. **A kind without options is written bare (R3, decision 16).** `extends Prompt` is the form when a prompt sets no
   options. Where a kind's options are optional, its kind table row allows both forms, as the Module and Listener
   rows already show; the prompt row reads `extends Prompt` or `extends Prompt({...})`.
6. **Electron menu roles are desktop config (decision 16).** The closed set of menu item verbs covers web and native
   menus only. Electron's menu roles are set in `desktop.config.ts`, the surface of
   [0281](/adr/0281-desktop-surfaces-targets-desktop-modes-and-overlay-styles).
7. **Broadcast has an audience (decision 16).** The `broadcast` option of `IntegrationEvent` is
   `{ permission, audience }`, where `audience` is `"principal"` or `"tenant"` and defaults to `"principal"`. The note
   of 2026-10-23 on [0225](/adr/0225-realtime-drivers-co-editing-and-the-commentable-trait) says what each reaches.
8. **A sibling may import an extension point (decision 24).** The public groups a sibling module may import gain
   `extensions/*.extension-point.ts`, so a module can extend a point that its sibling declares.
9. **Config files follow R2.** `src/config/env.config.ts` exports `<App>EnvConfig`, such as `MobileEnvConfig`. The
   note of 2026-10-23 on [0295](/adr/0295-build-and-entry-stackra-config-generated-tool-configs-and-entries) corrects
   that record's example.
10. **`refreshOn` takes integration events only (decision 16).** A widget's `refreshOn` lists integration events. A
    domain event there fails gen with `refresh_on_domain_event`.
11. **Kind base names are reserved (R3).** No model takes the name of a kind base, because a noun kind's class has no
    suffix and would hide the base. A model for a user's stored messages is `InboxMessage`, not `Notification`.
12. **Test helpers are named by kind (R2, decision 15).** A package's `testing/` holds `<name>.fake.ts`,
    `<name>.matcher.ts` and `<name>.fixture.ts` files, in place of the `fakes/` and `matchers/` folders of decision 15.
    A `.factory.ts` file is only the Factory kind, in `database/factories/`
    ([0269](/adr/0269-stackra-testing-package-entries-and-helper-placement) carries the same note).
13. **A shape may extend a shape (decision 26).** A schema may extend another schema, and the `PickType`, `OmitType`
    and `PartialType` helpers derive one shape from another. As with an override (R3), the class then extends a class
    of its own kind rather than the kind base. Gen compiles the inherited fields as it compiles declared ones.
14. **The member key is the folder name (decision 20).** The member key is the member's folder name in snake_case:
    `commerce` for `services/commerce`, `loyalty_kit` for `packages/commerce/loyalty-kit`. It replaces the
    package-name formula, which would give `service_commerce` for a service. Each module's Postgres schema is still
    the module key, inside the service's database. The 0294 note on
    [0264](/adr/0264-declaration-vocabulary-module-keys-define-family-and-kind-folders) and decision 1 of 0295, which
    derive the member key from the package name, read the folder name.
