## 0.1.0

### Minor Changes

- 9fc14fd: Put `@stackra/rules`, `@stackra/access-log`, `@stackra/scope`, `@stackra/market-packs`, `@stackra/devices`,
  `@stackra/collaboration` and `@stackra/payments` on the framework version line beside the packages the OS catalog
  already lists, with `@stackra/segments`, which `@stackra/iam` depends on and the catalog also lacks (STA-819).
- 67aa168: Segments becomes an add-on above `@stackra/iam` and `@stackra/rules` (ADR 0462 decision 1): `SegmentPermissions` with
  the system-held `recompute` permission that `RecomputeSegmentsAction` derives (STA-1365 item 9), the `SEGMENT_FACTS`
  fact source (`segments.ids`) and `SegmentFactProviderDriver`, which plugs membership into the rules engine. Lang keys
  for the fact label in the seven locales.
- 2787c1e: Add `@stackra/segments`: named audiences over any subject model, dynamic (a `@stackra/rules` rule set) or manual, with
  membership materialised per segment and subject, recomputed on the subject's row changes through the outbox, hourly per
  scope and on a newly published revision, `MembershipEntered` and `MembershipLeft` integration events for every change,
  and `SegmentMembershipService` for the consumers that read it.

### Patch Changes

- abb1d69: Lint: rule-gap B-4 (stackra-232, owner D11). `@stackra/oxlint-config` turns on
  `typescript/method-signature-style` with `"property"` at `error`. A method signature in an interface or type literal is
  checked bivariantly even under `strictFunctionTypes`, so a driver could accept a narrower argument than its port
  promises. Every port, type and augmentation in the packages listed now spells its members as properties
  (`find: (id: string) => Promise<T>`), which TypeScript checks strictly.
  
  No runtime change. The type surface is stricter: an implementation, fake or object literal whose parameter is narrower
  than the port's now fails to typecheck, as it always should have. Module augmentations (`Matchers<R>`, `Blueprint`,
  `TestingModuleBuilder`, `TestingApp`) use the same property form.
- ca44233: Breaking renames for unique public names (STA-1383): `@stackra/rules` `Decision` is `RuleDecision` (iam's `Decision`
  is the allow or deny enum) and `Facts` is `RuleFacts` (ai's `Facts` is the facts kind base). Importers are updated.
- e756399: Publish to the Stackra registry (ADR 0453): every free `@stackra/*` package is `"private": false` (ADR 0461) with `publishConfig` `{ access: public, provenance: true }` and no registry of its own; the release workflow's `registry` input, `https://npm.stackra.figentra.com/`, is the one place it is set. The packed manifest drops the repo-only `@stackra/source` export condition. `@stackra/runway` types `providers.npm` (`registry`, `scope`); `@stackra/repo-checks` refuses a member `publishConfig.registry`; `stackra new` writes none.
