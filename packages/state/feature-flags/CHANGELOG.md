# @stackra/feature-flags

## 0.1.0

### Minor Changes

- 76f882d: Add the `./lint` entry: the `feature-flags` oxlint plugin with the `no-plan-targeting` rule, which refuses a flag named
  after a plan, tier, edition, entitlement or subscription, or a `Flag({...})` option keyed by one (flags are not
  entitlements, ADR 0213 decision 7).
- 2787c1e: Add `@stackra/feature-flags`, the feature flags of the programming model v3.1. It ships the `Flag({ default, expires,
  removalIssue, scopes })` kind, which checks the expiry and the scopes when a class is declared and defaults the scopes
  to platform and tenant, and `flagRefs`, which builds the typed `Flags.<module>.<name>` references of `#stackra/flags`
  from declared classes or from written-out consumed flags. The `FlagProvider` port (`./contracts`) comes with two
  drivers: `ConfigFlagProviderDriver`, which answers from build-time and runway values, and `PosthogFlagProviderDriver`,
  which calls PostHog's flags endpoint and never sends an anonymous subject. `FlagReader` loads the subject that the
  targeting names, keeps the last values when a load fails, applies only the newest load and refreshes on
  `refreshEvery`. The package also adds the `FeatureFlagsConfig` configuration (`feature_flags`) with its shipped schema
  `FeatureFlagsConfig$`, `FlagTargeting`, `useFlag` (`./react`) and `fakeFlags` (`./testing`).
- 396e384: Packages ship their `stackra.manifest.json` (listed in `files`), and the manifest gains a `config` section that gen
  reads for package config rows instead of the `*Config` name suffix. `stackra gen --check` refuses an unshipped manifest
  (`manifest_unshipped`). New memory drivers: `ConnectionStore` (integrations), `ScopeResolver` (scope),
  `RealtimeFanout` (realtime), `ErrorReporter` (errors), `SecretStore` (config) and `FlagProvider` (feature-flags).
  Generated file headers keep ` *` on continuation lines, so every generated header changes on the next regeneration.

### Patch Changes

- 9771f30: Turn on `feature-flags/no-plan-targeting` in the oxlint base preset, loading the plugin from its source file so lint
  needs no build (ADR 0421).
- 038966e: Rule-gap B-1, B-2 and B-5 (stackra-230, owner D11). `base.jsonc` now has no warn level left: the `suspicious`
  category and `react/exhaustive-deps` are `error`, and every warning they raised (81) is fixed or carries a reasoned
  disable. `unicorn/no-array-sort` is on (a bare `x.sort();` statement passes; tests are off), with
  `no-promise-executor-return`, `unicorn/prefer-code-point`, `unicorn/prefer-structured-clone` and `unicorn/prefer-spread`.
  
  The packages listed change no API. toSorted and toReversed are ES2023 and the base lib is ES2022, so a TypeScript site
  that sorts or reverses an array it just built carries a reasoned disable; the Node-only `.mjs` tools use toSorted.
  Promise executors have block bodies; `String.fromCharCode` is `String.fromCodePoint`; byte-level `charCodeAt`, hashes
  and deliberate JSON round trips keep their form with a reason; typed-array `.slice()` copies are `new Uint8Array(x)`.
- abb1d69: Lint: rule-gap B-4 (stackra-232, owner D11). `@stackra/oxlint-config` turns on
  `typescript/method-signature-style` with `"property"` at `error`. A method signature in an interface or type literal is
  checked bivariantly even under `strictFunctionTypes`, so a driver could accept a narrower argument than its port
  promises. Every port, type and augmentation in the packages listed now spells its members as properties
  (`find: (id: string) => Promise<T>`), which TypeScript checks strictly.
  
  No runtime change. The type surface is stricter: an implementation, fake or object literal whose parameter is narrower
  than the port's now fails to typecheck, as it always should have. Module augmentations (`Matchers<R>`, `Blueprint`,
  `TestingModuleBuilder`, `TestingApp`) use the same property form.
- e756399: Publish to the Stackra registry (ADR 0453): every free `@stackra/*` package is `"private": false` (ADR 0461) with `publishConfig` `{ access: public, provenance: true }` and no registry of its own; the release workflow's `registry` input, `https://npm.stackra.figentra.com/`, is the one place it is set. The packed manifest drops the repo-only `@stackra/source` export condition. `@stackra/runway` types `providers.npm` (`registry`, `scope`); `@stackra/repo-checks` refuses a member `publishConfig.registry`; `stackra new` writes none.
