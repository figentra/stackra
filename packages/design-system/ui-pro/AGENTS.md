# AGENTS — @stackra/ui-pro

Stackra Design System Pro components for Stackra's own apps only: the @stackra/ui props vocabulary over HeroUI Pro on web and HeroUI Native Pro on native. Private, never published. Member at `packages/design-system/ui-pro` (`tier:lib`), in the programming model v3 shape
(ADR 0294, 0295).

## Where code goes

| You are writing…                                            | It goes in…                                             |
| ----------------------------------------------------------- | ------------------------------------------------------- |
| The member definition (static data)                         | `stackra.config.ts`                                     |
| Deploy-time configuration                                   | `src/config/<name>.config.ts`, a class                  |
| A static file: image, font, language file, template, stub   | `assets/{public,lang,templates,stubs,data}/` (ADR 0234) |
| A port, a public enum or type other members need            | `src/contracts/{ports,enums,types}/`                    |
| Isomorphic code: services, drivers, errors, schemas, blocks | `src/core/<group>/`                                     |
| The module: actions, queries, models, listeners, …          | `src/node/<group>/`, beside `src/node/ui-pro.module.ts` |
| Migrations, factories, seeders                              | `src/node/database/{migrations,factories,seeders}/`     |
| Web or native renderers                                     | `src/react/<name>/`, `src/native/<name>/`               |
| Fakes and matchers for consumers' tests                     | `src/testing/{fakes,matchers}/`                         |
| A test                                                      | `__tests__/<name>.<kind>.test.ts` beside its subject    |

A file is `<name>.<kind>.ts` in its kind's one home group, and its class is `PascalCase(name) + PascalCase(kind)`
extending the kind's base class. The group table is the docs page `standards/structure`.

## Entries and barrels

- Entries: `.` (core and the config classes, so a host can subclass them), `./contracts`, `./node`, `./react`,
  `./native`, `./testing`, and `./assets/*` for static files. An entry is exported once its folder holds a file: its
  `package.json` `exports` key and its `tsdown.config.ts` entry are added together.
- Entry barrels are generated by `stackra gen`, never authored (ADR 0294 decision 15). Until gen ships (STA-339), an
  export names its entry's one public file. When an entry gets a second public file before then, add
  `src/<entry>/index.ts` as a stand-in whose header `Purpose:` starts with `Stand-in barrel:`; gen replaces every such
  file.
- Never write `main.ts`, a `providers` list or `imports` on a non-root module.

## This package (ADR 0310)

- **Private, never published.** `"private": true` and no `publishConfig`; `pnpm validate` refuses either change and any
  non-app member that depends on this package, `@heroui-pro/react` or `heroui-native-pro`. Only our own apps import it
  (console, docs, playground, Figentra OS); `@stackra/ui` never does (ADR 0165 decision 5, ADR 0197).
- A component is a contract in `src/contracts/types/<name>-contract-props.type.ts` (`<Name>ContractProps`, built on
  `@stackra/ui/contracts`' `Size`, `Tone`, `Variant`; never `@stackra/ui`'s `src/`) plus a thin wrapper in
  `src/react/<name>/` over `@heroui-pro/react` or `src/native/<name>/` over `heroui-native-pro`, each with
  `__tests__/`. The `@stackra/ui` props vocabulary (ADR 0303 decision 7) maps onto HeroUI Pro's names; every other prop
  passes through. Compound parts are HeroUI Pro's own, typed in a parts interface.
- Names follow the grammar: Pro `Command` is `ActionPalette` (ADR 0294 decision 23).
- Verify every HeroUI Pro and HeroUI Native Pro API against the installed `.d.ts` or the Pro MCP before using it; never
  guess a compound structure. Prefer the subpath imports (`@heroui-pro/react/<name>`, `heroui-native-pro/<name>`).
- Installing needs the HeroUI Pro build: locally a `heroui-pro login` session, in CI `HEROUI_AUTH_TOKEN` from Infisical
  `/ci`. Without it the package is an empty shell and nothing here typechecks.
- Web tests render the real HeroUI Pro in jsdom (`@vitest-environment jsdom`); native tests replace `heroui-native-pro`
  with recording stand-ins and check what reaches it. Each web component has a playground route under the "Pro" group.

## Rules that fail the build

- `contracts/` imports nothing else from the package; core imports contracts; node, react and native import core;
  testing may import them all.
- A package never imports an app, a service, `encore.dev`/`~encore/*`, or another package's `src/`.
- Versions are `catalog:<name>` or `workspace:*` only. Imports leaving a folder use the `#` aliases in `package.json`.
- No `enum`, no `#private` fields, no `app()`/`config()`/`logger()` helpers, no `*.stories.*`.
- A package that defines decorators ships an Explorer at `src/<entry>/ui-pro.explorer.ts`.
- Coverage meets the shared gate (lines/functions 80, branches 70).
