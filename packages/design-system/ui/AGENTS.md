# AGENTS — @stackra/ui

Stackra Design System components: one component API, contracts shared, HeroUI v3 on web, HeroUI Native and Uniwind on native. Member at `packages/design-system/ui` (`tier:lib`), in the programming model v3 shape
(ADR 0294, 0295).

## Where code goes

| You are writing…                                            | It goes in…                                             |
| ----------------------------------------------------------- | ------------------------------------------------------- |
| The member definition (static data)                         | `stackra.config.ts`                                     |
| Deploy-time configuration                                   | `src/config/<name>.config.ts`, a class                  |
| A static file: image, font, language file, template, stub   | `assets/{public,lang,templates,stubs,data}/` (ADR 0234) |
| A port, a public enum or type other members need            | `src/contracts/{ports,enums,types}/`                    |
| Isomorphic code: services, drivers, errors, schemas, blocks | `src/core/<group>/`                                     |
| The module: actions, queries, models, listeners, …          | `src/node/<group>/`, beside `src/node/ui.module.ts`     |
| Migrations, factories, seeders                              | `src/node/database/{migrations,factories,seeders}/`     |
| The platform-neutral form engine (`./form`)                 | `src/form/{functions,types,schema-form}/`               |
| Web or native renderers                                     | `src/react/<name>/`, `src/native/<name>/`               |
| Fakes and matchers for consumers' tests                     | `src/testing/{fakes,matchers}/`                         |
| A test                                                      | `__tests__/<name>.<kind>.test.ts` beside its subject    |

A file is `<name>.<kind>.ts` in its kind's one home group, and its class is `PascalCase(name) + PascalCase(kind)`
extending the kind's base class. The group table is the docs page `standards/structure`.

## Entries and barrels

- Entries: `.` (core and the config classes, so a host can subclass them), `./contracts`, `./form`, `./node`,
  `./react`, `./native`, `./testing`, and `./assets/*` for static files. An entry is exported once its folder holds a file: its
  `package.json` `exports` key and its `tsdown.config.ts` entry are added together.
- Entry barrels are generated by `stackra gen`, never authored (ADR 0294 decision 15). Until gen ships (STA-339), an
  export names its entry's one public file. When an entry gets a second public file before then, add
  `src/<entry>/index.ts` as a stand-in whose header `Purpose:` starts with `Stand-in barrel:`; gen replaces every such
  file.
- Never write `main.ts`, a `providers` list or `imports` on a non-root module.

## This package

- A component is a contract in `src/contracts/` (its props type, built on `Size`, `Tone`, `Variant`) plus one
  implementation in `src/react/<name>/` on HeroUI v3 and one in `src/native/<name>/` on HeroUI Native, each with
  `__tests__/`. The code is not shared between them (ADR 0302 decision 3, ADR 0227). Add it to the stand-in barrels
  `src/contracts/index.ts`, `src/react/index.ts` and `src/native/index.ts`, and give it a route in `apps/playground`.
- Verify every HeroUI, HeroUI Native and Uniwind API against the installed package or the HeroUI MCP before using it;
  never guess a compound structure. Free code never imports HeroUI Pro (ADR 0165, 0197).
- `react/` never imports `native/` and the other way round; both import `contracts/` and `core/`.
- React Native does not render in vitest: native tests replace `heroui-native` and `uniwind` with recording stand-ins
  and check what reaches them. Provider tests run in jsdom through a `@vitest-environment jsdom` comment.

## Rules that fail the build

- `contracts/` imports nothing else from the package; core imports contracts; form imports contracts and core, and
  nothing React DOM or React Native; node, react and native import core (react and native also form); testing may
  import them all.
- A package never imports an app, a service, `encore.dev`/`~encore/*`, or another package's `src/`.
- Versions are `catalog:<name>` or `workspace:*` only. Imports leaving a folder use the `#` aliases in `package.json`.
- No `enum`, no `#private` fields, no `app()`/`config()`/`logger()` helpers, no `*.stories.*`.
- A package that defines decorators ships an Explorer at `src/<entry>/ui.explorer.ts`.
- Coverage meets the shared gate (lines/functions 80, branches 70).
- Annotate every export whose inferred type would reach an unexported or deep-path type (`ExtensionBase`, `ActionBase`,
  `PassBase`, a provider's `bin/` class, `@types/react`'s `Element`): the declaration build fails with TS2883 (STA-1220).
