## 0.9.0

### Minor Changes

- be4a198: Engine additions for CLIs moving onto the console engine (ADR 0506 amendment of 2026-11-03, STA-2093). Three are
  opt-in: `createConsole({ json: "bare" })` makes `--json` write the command's data alone as one line, with stdout empty
  on an error and human output, the problem screen and the `-v` echo on stderr (only for JSON an ADR froze, as
  testbed's); `io.process.run(..., { inherit: true })` lets a child share the standard streams without a terminal
  (stderr only under `--json`); and `requireCommand: true` makes an invocation that names no command exit 2.
  
  Changes for every console: a registry value option may come before the command name (`testbed --box 2 ssh`), so the
  token after such a flag is now its value, not the name (`cli --out deploy ./dist` used to run `deploy` with
  `--out=./dist`); `io.process` refuses an `inherit` or `interactive` child while the run holds a secret value, list and
  number values included; the output listener receives redacted chunks; and an explicit `secret: false` overrides the
  secret-like name guess.

### Patch Changes

- 9bb5d55: A text prompt's default can be accepted with Enter when the field has a constraint: the Clack prompter checks the
  default rather than the empty input (`--name must be at least 3 characters, got ""` no longer blocks it).

## 0.6.0

### Minor Changes

- 1677615: Clack (`@clack/prompts` 1.8.1) is the interactive prompter: `nodePorts()` asks through `clackPrompter`, and
  `terminalPrompter` stays as a driver (STA-1966, owner approval 2026-11-02).
  
  `@Argument` and `@Option` take `prompt` and `choices`.
  
  - **Prompted fields:** a prompted field the invocation leaves out is asked for while interactive. A flag is a confirm,
    a field with choices is a select (a multiselect for a `@List`), a secret is a password, and anything else is text
    checked like a command-line token.
  - **Without a terminal:** a prompted field takes its default, or the run exits 2 naming the option.
  - **Arguments:** a prompted argument is no longer required on the command line.
  - **Choices:** a value outside a field's `choices` is a usage error.
- 1677615: Live screens:
  
  - **`io.output.live({ title, rows })`** redraws rows that are pending, running or settled, then writes their final
    checklist. A row still running is written as skipped, a failed row exits 1, and the settled rows are the `--json`
    data (STA-1966).
  - **`InkRendererDriver`** (in `@stackra/console/node`, bound by `nodePorts()`) draws live views, spinners, progress bars
    and running tasks through Ink 8 while output animates, and ends each one in the text driver's static lines.
    - Ink and React are imported only the first time a live part animates.
    - If they cannot load, the text output stands.
    - Off a colour terminal, the driver is the text driver.
- 1677615: One command definition serves the CLI, `--json` and the local developer MCP (STA-1966, ADR 0282 decision 5 as
  amended).
  
  - **Marking a tool:** `Command({ tool: true | { readOnly } })` marks a command for the local MCP.
  - **`toolsOf(config, ports)`** gives each such command:
    - an MCP-safe name (`spec:status` becomes `spec_status`);
    - a JSON Schema derived from its fields (kinds, bounds, patterns, choices, required arguments);
    - an `invoke` that runs it through the same kernel with `--json` and no prompts. Values never read as flags.
  - **`serveLocalMcp({ tools })`** serves these with the command's own document as `structuredContent`. One that is named
    like a built-in tool replaces it.
  
  Tenant tools stay on the action's own path through the `ai` service (ADR 0155).
- 1677615: `Command({ passthrough: true })` is for migration only (ADR 0500 decision 7, STA-1966).
  
  - **Raw tokens:** a ported command that still parses its own flags gets every token after its name in `io.rest`,
    `-n` and `--json` included.
  - **Still the kernel's:** routing, `--help`, `help <cmd>` and the error screen.
  - **No fields:** a passthrough command declares no fields.
  - **Tracking:** `passthroughCommands(commands)` in `@stackra/console/testing` lists the commands still in this
    state, so a CLI's test pins the list until it is empty.
  
  `io.stdout` and `io.stderr`, also migration only, are the run's raw streams, for a ported command whose output must
  stay byte for byte as it was.
- 1677615: Commands run child processes through `io.process.run(command, args, options)`, over a new `ProcessRunner` port
  (STA-1966).
  
  - **Output:** a child's output is captured and shown only under `--verbose`, with the command's secret values
    redacted.
  - **Failure:** a non-zero exit throws a `CommandError` carrying the output. A failed `io.output.task` line shows the
    last 20 lines under it, and the whole output appears only under `--verbose`.
  - **Interactive children:** `interactive: true` hands the terminal to the child, and is refused, naming the command,
    when the run is not interactive.
  - **Working directory:** `io.cwd` is the run's working directory, from `ConsolePorts.cwd`, which is now required.
    `nodePorts()` sets it and binds `NodeProcessRunnerDriver`.
  - **Testing:** `@stackra/console/testing` adds `MemoryProcessRunnerDriver`, and `runCommandForTest` takes `process` and
    `cwd`.
- 1677615: Output goes through a `Renderer` port, and the new `TextRendererDriver` is the default (STA-1966). A command and the
  kernel are unchanged when a driver is swapped (`ConsolePorts.renderer`, and `runCommandForTest`'s `renderer` option).
  
  New components:
  
  - **Status tables:** `io.output.table({ columns, rows, groupBy })`. Status cells read `✓ ok`, `⚠ warn` and `✗ fail`,
    and the widest text column is cut to fit the width.
  - **Checklists:** `io.output.checklist({ rows })`, grouped, with fix lines and a summary. A failed row exits 1.
  - **Trees:** `io.output.tree(nodes)`.
  - **Problems:** `io.output.problem(...)` and `io.output.present(data)`.
  - **`CommandError`:** carries `why`, `fix`, `docs` and `detail`.
  
  Output changes:
  
  - Every failure now renders as one boxed problem. The stack, causes and raw detail show only under `--verbose`.
  - The `--json` error gains `why`, `fix` and `docs`.
  - Table and checklist rows are the `--json` data, extra fields kept.
  - A non-zero exit without an error writes `{ "ok": false, "data": ... }`.
  - Data a command returns without writing is presented.
  - Warning and error lines use `⚠` and `✗`.
  - `displayWidth` counts a text-presentation pictograph (`⚠`) as one column.
  
  `CommandStructure`, `CommandField`, `ValueKind`, `NoteTone`, `Spinner` and `Progress` move to
  `@stackra/console/contracts`.
- 2256bf6: The kernel routes every invocation to one intent (the list, the version, a command's help, a run or a usage
  problem) before any container exists (STA-1966).
  
  - `help <command>` prints the command's help and never runs it, as `--help` and `-h` already did. A command can no
    longer be named `help`.
  - Spaced names run `:`-joined commands, longest match first, so `acme mcp sync` runs `mcp:sync`.
  - `Command({ group, docs, examples })` is new:
    - the command list shows a command under its `group` (its namespace when it has none);
    - help ends with the examples and the docs link.
  - Off a terminal, the command list starts with the name and version.
- 1677615: Tab completion for every console (STA-1966):
  
  - **The script:** `<bin> completion bash|zsh|fish` prints a script; source it in the shell's profile.
  - **The callback:** the script's hidden `<bin> complete -- <words>` answers with:
    - command names and spaced subcommands (`mcp sync`);
    - each command's options and the global options;
    - choice values.
  
    Hidden commands are left out.
  
  - **Behind a port:** the `Completions` port (`@stackra/console/contracts`) carries this. `TabCompletionsDriver`
    (Bombshell Tab, `@bomb.sh/tab` 0.0.22) is bound by `nodePorts()`, and `runCommandForTest` takes `completions`.
  - **Reserved names:** `completion` and `complete` are built in, like `help`; no command may take their names.

### Patch Changes

- 1677615: `stackra validate` findings in `@stackra/console` (STA-1966):
  
  - `CommandClass` takes `never[]` collaborators, so the `no-explicit-any` disable is gone.
  - `AGENTS.md` gains its PII section.
  - The `create` template's NodeNext imports keep their `.ts` extension without tripping ADR 0233's rule.
  - knip sees the `stackra-console` bin entry (STA-1985).
  - `@stackra/cli`'s duplicate-export check allows console's `Spinner`, `STACKRA_THEME`, `findCommand`, `runCommand` and
    `shapeArabic`, each with its reason.
- 4fcb66d: `stackra create <directory>` makes a new Stackra app in an empty folder: the banner, then the name, npm scope, edition
  and package manager (each also a flag; `--yes` takes the defaults), the `@stackra/starter` profile from the Stackra
  registry (or `--starter <dir|tgz>`), the doctor's checks for what the profile needs, then install, `stackra gen` shown
  as a tree of what it wrote, type-check, tests and the first commit. `@stackra/console/node` exports `tarballSpecs`.

## 0.4.0

### Minor Changes

- 9c8d108: Packages contribute console commands, and gen collects them per member (STA-1731). `@stackra/console` audits a
  command declared `audit: true` through the `CommandAudit` port (refused before it runs when no sink is ready; secret
  values redacted). gen records commands in the manifest, merges hosted packages' commands, refuses
  `command_collision`, and writes `#stackra/commands` and a console entry that `stackra console <member>` runs. First
  commands: `db:migrate`, `db:rollback`, `db:status`, `db:seed`, `tenant:list`, `tenant:create` (with a
  `TenantDirectory` port), `cache:clear` (the `Cache` port gains `flush`), `queue:work`, `queue:failed` and
  `queue:retry`; `@stackra/access-log` stores command audit entries (`STACKRA_COMMAND_AUDIT_SCOPE`).
- 3c30885: Add `@stackra/console`: the `Command` kind with `@Argument` and `@Option` fields, `createConsole`, themed output
  (gradient banner, notes, tasks, spinners, progress, tables), prompts on `node:readline`, plain and `--json` modes,
  right-to-left-safe widths, the `runCommandForTest` harness and the `stackra-console create` scaffolder.
  `@stackra/validation` lets its field decorators mark commands.
