### Minor Changes

- dba420f: Add the `MobileHealthIndicatorDriver`, this package's driver of the contracts `HealthIndicator` port (ADR 0402).
- 58d9f32: Add `@stackra/infra-mobile` (ADR 0171): `mobileInfraPlan` reads the mobile release plan from the root and mobile
  runways (the EAS account and project, the Apple team and App Store record, the Play account and app-signing
  fingerprint, EAS-managed signing, and one profile, channel and EAS environment per environment that ships through EAS)
  and lists the owner steps no API takes (`MobileOwnerStep`); `./node` adds `mobileStack`, the Pulumi slice that
  resolves every `ref:` fact from the stack config and checks its shape.
- 29c2d3e: `storeAccountsOf(app, connected?)` resolves the account each store of a mobile app publishes under for the mobile job
  (ADR 0439, app-shells D14): a scope's connected store-account Connection (App Store Connect API key, Google Play
  service account) for its store, else the platform account in `mobile.<app>.stores`. New type `StoreConnection`; new
  dependency `@stackra/integrations` (its `./contracts` `MobileStore`).

### Patch Changes

  category and `react/exhaustive-deps` are `error`, and every warning they raised (81) is fixed or carries a reasoned
  disable. `unicorn/no-array-sort` is on (a bare `x.sort();` statement passes; tests are off), with
  `no-promise-executor-return`, `unicorn/prefer-code-point`, `unicorn/prefer-structured-clone` and `unicorn/prefer-spread`.
  
  The packages listed change no API. toSorted and toReversed are ES2023 and the base lib is ES2022, so a TypeScript site
  that sorts or reverses an array it just built carries a reasoned disable; the Node-only `.mjs` tools use toSorted.
  Promise executors have block bodies; `String.fromCharCode` is `String.fromCodePoint`; byte-level `charCodeAt`, hashes
  and deliberate JSON round trips keep their form with a reason; typed-array `.slice()` copies are `new Uint8Array(x)`.
