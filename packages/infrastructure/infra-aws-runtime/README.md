# @stackra/infra-aws-runtime

Pulumi programs for the AWS runtime resources that service members declare in their `runway.yaml`: for one
environment, the SQS queues, the SNS topics in front of them, the Valkey caches and the S3 buckets. Every name, size
and switch comes from the root and member runways through `@stackra/runway`; nothing is typed twice.

**Tier:** `tier:lib` (`packages/infrastructure/infra-aws-runtime`, ADR 0127). Entries `.` (the plan, pure) and
`./node` (the runway file reader and the Pulumi program part). Depends on `@stackra/runway`, `@stackra/contracts` and
`@pulumi/aws`; `@pulumi/pulumi` is a peer, so a program loads one copy.

## What is here

| Entry    | Symbol                                                                | Use                                                                   |
| -------- | --------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `.`      | `runtimePlan(root, services, environment)`                            | one environment's queues, caches and buckets, from parsed runways     |
| `.`      | `RuntimePlan`, `QueuePlan`, `CachePlan`, `BucketPlan`                 | the plan: plain data, testable without a cloud                        |
| `.`      | `planForMembers`, `runtimeNetwork`, `AwsRuntimeHealthIndicatorDriver` | one service's slice of the plan; the cache network; the health driver |
| `./node` | `readRuntimePlan(directory, environment)`                             | read `runway.yaml` and `services/*/runway.yaml`, then plan            |
| `./node` | `awsRuntime(plan, options)`                                           | declare the plan's resources in a Pulumi program; returns their ids   |
| `./node` | `awsRuntimeStack({ directory, environment, members })`                | the stack one service deploys through: its slice, the runway network  |
| `./node` | `AwsRuntimeOptions`, `AwsRuntime`                                     | the cache network and extra tags in; queue, topic, cache, bucket ids  |

```ts
// .stackra/infra/index.ts (generated by `stackra infra gen`)
import { awsRuntime, readRuntimePlan } from "@stackra/infra-aws-runtime/node";

const runtime = awsRuntime(readRuntimePlan(repositoryRoot, "staging"), {
  network: { subnetIds: privateSubnetIds, securityGroupIds: [runtimeSecurityGroupId] },
});
export const queues = runtime.queues;
```

One service deploys through its own runtime stack before the others move (ADR 0402); the cache network is the root
runway's `environments.<env>.shared.network` (`subnetIds`, `securityGroupIds`, ids or `ref:` values):

```ts
// figentra/infra, os/staging-runtime-commerce/index.ts
import { awsRuntimeStack } from "@stackra/infra-aws-runtime/node";

export const runtime = awsRuntimeStack({
  directory: "../os",
  environment: "staging",
  members: ["commerce"],
});
```

## What the runways decide

| Runway fact                                                        | Resource                                                                                                                          |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| member `environments.<env>.queues.<name>`                          | an SQS queue `<project>-<env>-<member>-<name>` (SSE-SQS, the member's visibility timeout)                                         |
| member `dlq`, else root `shared.queues.dlq`                        | a `-dlq` queue (14 days) and a redrive after five receives                                                                        |
| root `shared.queues.provider: sns-sqs`                             | an SNS topic per queue (SSE), a raw subscription, a queue policy for that topic only                                              |
| root `shared.cache.engine: valkey` (`node`, `replicas`)            | the shared Valkey replication group `<project>-<env>-cache`                                                                       |
| member `requires.<name>` `engine: valkey`, `dedicated: true`       | a dedicated Valkey group sized from `cache.memoryMb`, `replicas` and `eviction`, only where the member's cache driver is `valkey` |
| member `environments.<env>.buckets.<name>`                         | an S3 bucket, public access blocked                                                                                               |
| root `shared.buckets.versioning`, `lifecycle.expireNoncurrentDays` | versioning (on unless `false`, ADR 0186) and the noncurrent-version expiry                                                        |
| root `topology` (groups, `default`)                                | the `group` tag beside `env` and `service` (ADR 0172 cost tags)                                                                   |

Names are lower-case with single hyphens (`loyalty_kit` becomes `loyalty-kit`) and are cut to the AWS limit with a
stable hash (ElastiCache ids 40, S3 63, SQS 80). A dedicated cache whose `memoryMb` no node holds, or whose `eviction`
Valkey does not know, fails as `RunwayInvalidError` naming the runway path. Caches use TLS and at-rest encryption on
port 6379 inside the security groups you pass; no secret is created or read.

## Not here

- The database server (`shared.database`, a dedicated `postgres` requirement), the VPC, the load balancer and the
  compute: the database and network stacks, not this one.
- Which environments compose this program: `stackra infra gen` decides it from `destinations.services`.
- Topic subscriptions between members (a consumer's queue on a producer's events) come from the manifests, through
  gen; this package subscribes each queue to its own topic only.
- Bucket replication to the backup account (ADR 0186 decision 3) needs that account's bucket and role from
  `@stackra/infra-aws`.

Agents only preview: `stackra infra preview` runs the program against Pulumi's diff, and `pulumi up` is the owner's
(ADR 0171). The unit tests run the program under Pulumi's mocks.
