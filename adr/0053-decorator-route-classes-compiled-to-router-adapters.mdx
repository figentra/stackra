## Context

Web and mobile both need routing, and a file-system router would tie route shape to one framework's folder convention.
Figentra OS, Stackra's ancestor, solved this with decorator route classes (`@Route`, `@Layout`, `@Guard`) whose loaders are resolved
through DI ([0005](/adr/0005-di-container-and-legacy-decorators)). [0011](/adr/0011-rejected-and-deferred-technologies) already rejects
expo-router for mobile; this decision extends the same stance to every surface and is consistent with it.

## Decision

1. **Routes are classes.** A route extends `Route({ path, ... })` and a layout extends `Layout({...})`. The class holds the route's
   `path` and options and the methods `loader`, `submit` and `meta`. Its dependencies arrive through the constructor. The
   component is a function in a `.tsx` file beside the class, so the class is never a component.
2. **One definition compiles to two adapters**: React Router 7 on web and a React Navigation adapter on mobile.
3. **No file-system routing anywhere in the repository**, including expo-router and React Router's own file-system route
   configuration. A URL comes from the class's `path`, and gen writes the route table from those paths. A route folder groups
   the files of one route; it does not decide the URL. The landing site's `routes.ts` ([0057](/adr/0057-landing-is-react-router-framework-mode-on-workers))
   is a code-based route list, not a folder convention.
4. **The router package is ported from Figentra OS** through the normal package gate; its category is chosen when it is scaffolded ([0028](/adr/0028-package-categories-appear-with-first-package)).
5. **React Router 7 mapping (web).** A route folder becomes one React Router 7 route module:

   | Route folder file or class member                                                                                                          | React Router 7 export                           |
   | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------- |
   | `<name>.route.ts`, method `loader(ctx)`                                                                                                    | `loader`                                        |
   | method `submit(ctx)` (a form submission)                                                                                                   | `action`                                        |
   | method `meta(args)`                                                                                                                        | `meta`                                          |
   | `<name>.tsx`                                                                                                                               | the default component                           |
   | `<name>.error.tsx`                                                                                                                         | `ErrorBoundary`                                 |
   | `<name>.fallback.tsx`                                                                                                                      | `HydrateFallback`                               |
   | `<name>.server.ts`                                                                                                                         | server-only code, never bundled for the browser |
   | route `middleware`, when the middleware flag is on ([0297](/adr/0297-web-runtime-on-workers-prerender-caching-locale-urls-and-forwarding)) | `middleware`                                    |

   A layout is the parent route module. Errors bubble from a route to its layout, then to the app's root boundary
   ([0232](/adr/0232-stackra-errors-package)).

## Consequences

- Route logic is testable without a framework and shared between web and mobile.
- Route classes take no decorators, so route options are checked by the base class, not by a decorator.
- We own the adapters and must keep them in step with React Router 7 and React Navigation 7 releases.
- The mapping in decision 5 is part of the web contract: a change to a route file's role is a change to a React Router export.

## Enforcement

In place: `expo-router` is in `FORBIDDEN_DEPENDENCIES` in `tools/scripts/validate-repository.mjs`.

planned — the `kind-path` check (STA-338) and the `folder-kinds` check (STA-340), which require each route folder to hold one route or layout, its
`.tsx` and its `__tests__/`, and reject a route folder that holds more than one; and a conformance test that one route definition
yields equivalent web and mobile route tables.
