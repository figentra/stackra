New `stackra upgrade` (ADR 0199 decision 2, STA-145): moves a consumer workspace from the `@stackra/*` version it pins to a release (by default the CLI's own version) in one mechanical step. It prints the upgrade note of every release in between that has an upgrade entry, moves every exact `@stackra/*` pin in `pnpm-workspace.yaml` and each member's `package.json` (prefix and layout kept; `workspace:`, `catalog:`, ranges and `@stackra-pro/*` left alone), runs those releases' codemods over the source, then runs `pnpm install`, each codemod's commands (`stackra encore:prepare` in every service) and `stackra gen`. ts-morph rewrites imports and re-exports of an export a release moved or renamed (`RichTextEditor` to `@stackra/ui/rich-text`, `DeviceSession` to `AccountSession`); ast-grep lists the code only a person can port (an `ApprovalGate` driver without `decide`, an `IdempotencyStore` without `completeRefused`, an Infisical store import) as `file:line:column` findings. `--dry-run` prints the plan, the notes and every diff and writes nothing; `--no-install` writes and prints the commands; `--only`, `--list`, `--from`, `--to`, `--allow-dirty` and `--json`. It refuses a dirty working tree, an inexact version and a pin newer than the target (exit 2). `@ast-grep/napi` and `ts-morph` are new dependencies, loaded only when `stackra upgrade` runs a source codemod.
