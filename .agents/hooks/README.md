# `.agents/hooks/`

The agent hooks, written once and wired into Claude Code by `.claude/settings.json` (`$CLAUDE_PROJECT_DIR/.agents/hooks/…`).
`pnpm agents:sync` also symlinks each file into `.claude/hooks/`. Node 24 and no dependencies, so a hook runs before
`pnpm install`. The permission rules live once, in `_rules.mjs` (ADR 0293); the OpenCode plugin,
`.opencode/plugins/guard`, evaluates the same module and turns every ask into a deny with the shared `unattended`.
In `guard-bash` only the deletes, deploys and releases in `HUMAN_ASKS` ask the owner, read through every runner
(STA-400, superseding STA-351's main-thread exemption); raw `infisical run` is a deny that names the wrapping pnpm
scripts, an ask for a command the guard cannot read is a deny with a rewrite hint from any thread, and the rest is
allowed. The settings ask rules hold only deletes, deploys and releases too. The OpenCode guard passes `executor`,
which adds the executor-only denies (`npx`, `eas`, `wrangler secret|--remote`, `secrets:import --confirm`).

## The plan gate (ADR 0362)

No code without an answered questionnaire and a plan. A Write or Edit to a source path is refused unless the branch
key (`figentra/sta-<n>-…` or `delegate/sta-<n>-…`) has exactly one `.agents/specs/sta-<n>-*/` folder in the file's
own git checkout, whose `spec.md` passes spec-gate's `checkSpec` (clarifications `complete`, an STA key, every Impact
line answered, no `[NEEDS CLARIFICATION`) and which holds a non-empty `plan.md`.

- **Source paths** (`PLAN_GATED`, repo-relative): `packages/**`, `services/**`, `workers/**`, `apps/**` except
  `apps/docs/**`, and `tools/**` except `tools/scaffold/templates/apps/docs/**`. Every other path (`.agents/**`, specs,
  docs, root files, the notes) is not gated, and neither is any Markdown file (`.md`, `.mdx`), even inside a source
  folder such as `packages/*/README.md`. A file outside any git checkout is not gated. During a rebase, when HEAD is
  detached, the branch is read from the rebase's `head-name`.
- **Hotfix.** A production hotfix may go first with the owner's approval. The owner writes
  `.agents/specs/sta-<n>-<slug>/hotfix.md` with three filled lines, `**Approved by**:`, `**Approved on**:` (a `YYYY-MM-DD` date) and
  `**Reason**:`; the gate then passes without spec or plan. An agent never writes `hotfix.md` (a write rule refuses
  it). The questionnaire and plan follow right after; whether the marker expires or is deleted then is open (ADR 0362).
- `decidePlanGate` is async (it loads `tools/scripts/spec-gate.mjs` only for a source path) and is wired into
  `guard-paths.mjs` only; the OpenCode guard does not call it yet. Like every hook it fails open on its own errors,
  and a shell write (`cat >`, `sed -i`) is not seen: it is an accident guard, not a boundary.
- Tests: `__tests__/plan-gate.test.mjs`.

## Rules

- A guard denies with a reason that names the right way to do the thing; a hint or check never blocks.
- Settings deny and ask rules are the floor in every mode; a rule here adds only what a prefix cannot see: runner
  wrappers (`pnpm exec`, `npx`, `mise exec --`), the checkout a git command targets, `agent_type`, and prose.
- A hook fails open on its own errors (`failOpen`): a crashed hook never blocks work.
- Change a pattern together with its test in `__tests__/`.
- `__tests__/guard-differential.test.mjs` (wrapper x guarded command, 150+ allowed commands, a time bound) stays
  green with every change to `_rules.mjs` or `_inbox.mjs`; a new wrapper or guarded command gets a row there.
- What the hooks do not enforce yet is listed under Enforcement in each rule in [`../rules`](../rules); the docs page
  is [hooks](../../apps/docs/src/docs/agents/hooks.mdx).
