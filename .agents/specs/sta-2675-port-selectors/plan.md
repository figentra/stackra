# Implementation Plan: two-driver ports are chosen by a config selector with a default

**Spec**: `.agents/specs/sta-2675-port-selectors/spec.md` · **Linear**: STA-2675 · **Date**: 2026-11-10

**Input**: Feature specification from `.agents/specs/sta-2675-port-selectors/spec.md`

## Summary

Each of the six ports gets what stackra#1016 gave `SecretStore`: a config field typed `DriverName<Port>` whose schema
default names a driver, a driver-names constant and `DriverRegistry` augmentation, the port's `~key`, and the
manifest's `selectedBy`. Settings and storage get a config class each; database and identity extend theirs.

## Technical Context

- **Language**: TypeScript (ESM)
- **Members**: database (data), settings (state), storage (data), identity (security)
- **Testing**: vitest in `src/**/__tests__/` (a boot with no config gets the default); manifests regenerated by gen
  on the Testbed; CI
- **Storage**: none
- **Runtime target**: every host that injects one of the ports

- **P-003**: with no config, `Storage` resolves to memory — Validates: AC-003
- **P-004**: with no config, `SessionStore` and `AppApprovalChallenges` resolve to memory — Validates: AC-004
- **P-005**: no boot above throws `UnresolvedPortError` — Validates: AC-005

## Architecture overview

`chooseDriver` takes a test's choice, then a wiring `default` (gen's per-runtime one for an app), then `selectedBy`,
then the only candidate. Each port now reaches `selectedBy`, a config field with a schema default, so a service with no
config boots on the default and production chooses in config.

## Components and responsibilities

- `DatabaseOptions.driver` (`database`), `SettingsOptions.store` and `.floors` (`settings`, new),
  `StorageOptions.driver` (`storage`, new), `IdentityOptions.sessionStore` and `.approvalChallenges` (`identity`).
- The driver-names constants and `DriverRegistry` augmentations; the ports' `~key`.
