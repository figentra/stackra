# Implementation Plan: `stackra db diff` and `stackra db structure`

**Spec**: `.agents/specs/sta-1808-db-diff-structure/spec.md` · **Linear**: STA-1808 · **Date**: 2026-11-01

The leader's answers (see the spec's Decisions): Q2 adds foreign keys to the first cut, Q3 compares column types
through a gen-side map, Q4 PGlite, Q5 gitignored `.stackra/`, Q6 a separate gate step, Q7 no live mode. The replay and
introspection are one `readMigratedSchema` in `@stackra/database/node`, and the model side, type map and comparison
are pure gen, as below.

## Summary

Three members, one way: config → lib → cli. Nothing new is imported upstream.

1. **`@stackra/database/node`: replay and introspect.** Add a `structure({ cwd, units })` function next to `migrate`
   and `rollback`:
   - It opens an in-memory PGlite and applies each ordered unit's `up` SQL, transactional or not, as the runner would.
     It records the migration id and statement position on failure.
   - It introspects through `@mikro-orm/postgresql`'s schema reader into a plain `SchemaSnapshot` value (schemas →
     tables → columns, indexes).
   - It renders that snapshot as normalised DDL.
   - PGlite and its MikroORM driver load dynamically. When they are absent, it throws an error that names the fix.
2. **`@stackra/gen`: model side and comparison, pure.**
   - `modelledSchema(ir: MemberIR): SchemaSnapshot` builds tables, columns, nullability and indexes from models,
     facets and trait-implied columns.
   - `diffSchemas(modelled, migrated): SchemaDifference[]` compares the two.
   - `writeDiffMigration(differences, module, next, name): GeneratedFile[]` writes the additive migration source, in
     `Blueprint` calls with literals, under the `// generated by stackra db diff` header. Destructive differences come
     back as contract steps.
   - The node side reuses `compileMigrations` and `orderMigrations` to produce the units.
3. **`@stackra/cli`: the commands.**
   - `DB_DIFF_COMMAND` and `DB_STRUCTURE_COMMAND` in `src/node/constants/`.
   - `DatabaseRunner` gains an optional `structure`. `loadDatabaseRunner` reports an older `@stackra/database` that
     lacks it with the existing "update @stackra/database" message, and `migrate` and `rollback` stay required.
   - Both commands are added to `COMMANDS` after `DB_ROLLBACK_COMMAND`.
   - The README and the `commands.constant.ts` docblock are updated.
4. **Docs.**
   - The CLI reference page.
   - The `db-models-and-migrations` skill: describe the real command, and fix the stale line about Encore's runner.

The `SchemaSnapshot` type is structural and defined twice, once in database `core` and once in gen `core`. Gen's pure
entry already avoids importing `@stackra/database` (the `MigrationUnit` precedent). The CLI passes the snapshot from
one to the other.

## Phases (one pull request each, ADR 0120 D8)

1. **US1, `db diff` check** (P1): the database `structure` replay, gen's `modelledSchema` and `diffSchemas`, and the
   CLI `db diff` without `--write`. This unblocks invoicing#4.
2. **US2, `db diff --write`** (P2): gen's `writeDiffMigration` and the CLI flag.
3. **US3, `db structure`** (P3): the DDL renderer and the CLI command. It starts only after Q1 and Q5 are answered.

## Correctness properties

- **P-001**: on a fixture member, the replay applies the ordered units of the member and its declared packages, and
  introspects every module schema's tables, columns and indexes; a failing statement names the migration id and the
  position — Validates: FR-001
- **P-002**: `modelledSchema` gives one table per model in its module schema, one column per persisted field with its
  nullability, trait-implied columns, and one `idx_` index per `@Index` and `@Searchable` filter with its `unique` and
  `where` — Validates: FR-002
- **P-003**: `diffSchemas` returns no difference for equal snapshots, and one difference of the right kind for each
  single mutation (table, column, nullability, index added or removed); the CLI maps them to exit 0, 1 and 2 and
  `--json` to an array — Validates: FR-003
- **P-004**: `writeDiffMigration` for an added column and an added index gives source that `compileMigration` accepts,
  numbered next per module, with the header, literals, nullability and comment; replaying it makes `diffSchemas`
  empty — Validates: FR-004
- **P-005**: for a dropped field, a dropped index or a tightened nullability, `writeDiffMigration` writes no file,
  returns a contract step and the CLI exits 1; an index on an existing table lands alone in a concurrent migration
  — Validates: FR-005
- **P-006**: `db structure` prints byte-identical DDL across two runs on the same fixture and writes the same text with
  `--write` — Validates: FR-006
- **P-007**: the commands' tests run with no `DATABASE_URL` or Infisical in the environment, and a spy on the database
  port records no connection outside PGlite; the CLI source imports no database driver — Validates: FR-007
- **P-008**: `COMMANDS` lists `db diff` and `db structure` right after `db rollback`, each with a summary and usage
  (`commands.constant.test.ts`) — Validates: FR-008

## Risks

- **Trait and macro columns (Q3).** If the first cut cannot map them from the IR, US1 would report false
  `undeclared_column` findings on every tenant table. Mitigation: read the macro list the migration compiler already
  receives (`CompileOptions.macros`) and treat their columns as declared by the model's traits.
- **PGlite gaps.** PostGIS is not available in PGlite. A member whose migrations need it fails the replay with exit 2
  and a named extension, until Q4 is revisited.
