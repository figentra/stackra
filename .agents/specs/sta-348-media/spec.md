**Feature Branch**: `figentra/sta-348-framework`

**Created**: 2026-10-24

**Status**: Implementing

**Linear**: STA-348

**Linear project**: Foundation kernel

**Clarifications status**: complete

**Input**: Build `@stackra/media` (data, wave 7) for real: the `Bucket` kind, signed direct uploads and their claim,

`fakeUpload`.

## Impact

- **Apps touched**: none (the template's console calls `useUpload`, its web app `useImageVariant` and `ImageFormat`,
  and its commerce service declares a bucket, takes an `Upload` and claims it; STA-344)
- **Services touched**: none
- **Packages touched**: `packages/data/media` (new member)
- **Cross-service events**: none
- **Tenancy and data**: no table; files live in the shared store bucket (ADR 0222 decision 1). No tenant vocabulary
  (R-59): a claim is bound to the signed bucket key and an unguessable id
- **Secrets**: none; the S3 driver uses the AWS SDK credential chain that runway syncs from Infisical
- **ADR needed**: no (ADR 0222, 0234, 0294 decisions 13, 15 to 17, 20 and 25, 0305, 0142, 0263; ADR 0127 2026-10-24
  note)
- **New dependencies**: none outside the workspace and the existing default (`@aws-sdk/client-s3`,
  `@aws-sdk/s3-request-presigner`, `zod`) and `frontend` catalogs (React as an optional peer)
- **Deploy modes**: the store is S3, R2 or MinIO in every mode; the memory drivers need no network
- **Licence tier**: free (MIT; distributed on npmjs with provenance when released, ADR 0177)
- **Docs to update**: `packages/data/media/README.md`, `packages/data/media/AGENTS.md`; ADR 0222, 0234, 0294, 0305 are cited and amended only by a note if a decision here changes
- **Lane**: full (a new package)
- **Change risk**: R3 (an upload endpoint and the claim of client-supplied tokens: the trust boundary of every file a
  member accepts)

## Clarifications

### Session 2026-10-24

The package follows the v3.1 registry row and the owner decisions of 2026-10-24 (programming model v3 and v3.1, ADR 0294, 0305). The choices recorded when it was specified:

- Registry v3.1 row: entries `.`, `./contracts`, `./react`, `./testing`; `.` Bucket, BucketVisibility, ImageFormat,
  MediaLibrary, MediaType, Upload, UploadBucketMismatchError; `./contracts` MediaDisk; `./react` useImageVariant,
  useUpload; `./testing` fakeUpload. The template's generated wiring loads the S3 disk from `./node`, one of the six
  entries the ADR 0127 note allows, so `./node` is built too and holds the media module (the S3 disk and the
  `upload.create` action).
- ADR 0222 decision 2: services never stream the bytes. The token carries the upload id only; the bucket key, media
  type and expiry are signed into the presigned `PUT` and read back from the store at claim. No secret and no table is
  needed, and a second claim finds nothing.
- The template calls `useUpload()` with no bucket: `null` takes the member's only registered bucket, the rule the
  container already uses for a port with one driver.
- Driver classes follow the `<Name><Port>Driver` naming (`S3MediaDiskDriver`, `MemoryMediaDiskDriver`); the
  template's generated wiring sample names them `S3MediaDisk` and `MemoryMediaDisk` and is regenerated by gen.
- The store's bucket, region and public URL are `FilesystemConfig`'s (one shared bucket per region and environment,
  ADR 0222 decision 1); `MediaConfig` holds only the driver choices, the upload lifetime and the endpoint.

## User Scenarios & Testing

### User Story 1 - Declare a bucket and claim an upload into it (Priority: P1)

A module declares `ProductImagesBucket extends Bucket({...})`; an action takes `image: Upload<ProductImagesBucket>`
and calls `media.claim(input.image, ProductImagesBucket)`.

**Independent Test**: `src/core/bases/__tests__/bucket.base.test.ts`,
`src/core/services/__tests__/media-library.service.test.ts`,
`src/testing/functions/__tests__/fake-upload.function.test.ts`.

**Acceptance Scenarios**:

1. **Given** the template's bucket, **Then** its options are checked and recorded, frozen, as kind `bucket`.
2. **Given** a finished upload, **Then** `claim` moves it to `<visibility>/<key>/<id>.<subtype>` and returns its URL.
3. **Given** a token of another bucket, an expired one, one with nothing uploaded, or a stored file of a type or size
   the bucket does not take, **Then** `claim` refuses with the matching refusal and moves nothing.

### User Story 2 - Upload from a client (Priority: P1)

A component calls `useUpload()` and sends the token to an action.

**Independent Test**: `src/node/actions/__tests__/create-upload.action.test.ts`,
`src/core/drivers/__tests__/http-uploader.driver.test.ts`, `src/react/upload/__tests__/use-upload.test.tsx`,
`src/node/drivers/__tests__/s3-media-disk.driver.test.ts`.

**Acceptance Scenarios**:

1. **Given** a registered bucket, **Then** `upload.create` returns a token and a presigned `PUT` whose signature covers
   the content type and the metadata headers.
2. **Given** a refusal, a malformed answer or a network failure, **Then** the HTTP uploader raises
   `UploadFailedError` and never builds a token from the answer.

### User Story 3 - Size an image (Priority: P2)

A storefront card calls `useImageVariant(product.image, { width: 480, format: ImageFormat.Webp })`.

**Independent Test**: `src/react/image-variant/__tests__/use-image-variant.test.tsx`,
`src/core/functions/__tests__/image-variant-url.function.test.ts`.

**Acceptance Scenarios**:

1. **Given** the template card, **Then** the `src` is `https://cdn.test/tee.jpg?w=480&format=webp`.
2. **Given** no image, **Then** the hook gives `undefined`.

## Requirements

- **FR-001**: Entries `.`, `./contracts`, `./node`, `./react`, `./testing` (registry row plus `./node` for the
  wiring's S3 disk).
- **FR-002**: `.` exports every value the template imports (`Bucket`, `BucketVisibility`, `ImageFormat`,
  `MediaLibrary`, `MediaType`, `Upload` with `Upload.schema`, `UploadBucketMismatchError`) with the shapes it uses.
- **FR-003**: `./contracts` exports `MediaDisk`, keyed `media.MediaDisk`, with the `memory` and `s3` drivers.
- **FR-004**: `./react` exports `useUpload` (returns `(file) => Promise<Upload>`) and `useImageVariant` (returns
  `{ url, width, height? } | undefined`).
- **FR-005**: `./testing` exports `fakeUpload(app, bucket | null, { mediaType })`, whose `url` equals the claimed
  file's.
- **FR-006**: The bytes never pass through a service, and a claim trusts nothing from the client but the upload id.

## Success Criteria

- **SC-001**: Every symbol the template imports from `@stackra/media` exists with the shape it uses.
- **SC-002**: A test beside every public symbol, plus a barrel test per entry, passes in the testing workflow.
- **SC-003**: No test touches the network; the memory disk and stubbed `fetch` and `S3Client.send` stand in.

## Not in this build

- Variant generation by sharp in queue jobs (ADR 0222 decision 4): no queue package exists yet; the bucket's
  `variants` are recorded for gen and runway, and `useImageVariant` writes the resizer's URL form.
- Multipart and tus uploads (ADR 0222 decision 2): one presigned `PUT` per file, up to the store's single-request limit.
- The malware scan before a file is served (ADR 0222 decision 2): a scan state belongs to the files service's records.
- The `HasMedia` model trait (R-61): its fields are not specified; nothing in the template uses it.
- The tenant part of the key layout (ADR 0222 decision 1): R-59 keeps tenant vocabulary in `@stackra/tenancy`.
