## Versions

- **One version for everything.** Every `@stackra/*` package releases at the same version (the changesets `fixed`
  group), and `@stackra-pro/*` releases at that same version
  ([0453](/adr/0453-the-stackra-registry-one-npm-compatible-store-on-cloudflare-and-our-own-licence-engine) decision
  18). Install matching versions of all Stackra packages; mixing versions is not supported.
- **Semantic versioning.** A patch fixes, a minor adds, a major breaks.
- **0.x.** Before `1.0.0`, as semver allows, a minor release may break an API. Every breaking release carries a
  written release note (what changes for you, the steps to take, how to verify and roll back;
  [0013](/adr/0013-versioning-and-release) decision 5).
- **A version is never replaced.** A published version is immutable, also after a deprecation, and the registry
  refuses unpublishing. A fix is a new version.

## Dist-tags

| Tag      | Holds                                                                                                  |
| -------- | ------------------------------------------------------------------------------------------------------ |
| `latest` | the current release                                                                                    |
| `next`   | a prerelease leading to the next release (`0.1.0-next.<n>`); never moves `latest`                      |
| `canary` | snapshot builds for early testing ([0177](/adr/0177-package-distribution-npmjs-and-keygen) decision 7) |

## Deprecation

A deprecated API keeps working for one minor release before `1.0.0`, and for one major release after
([0177](/adr/0177-package-distribution-npmjs-and-keygen) decision 6). A deprecated package version shows npm's
deprecation warning with the version to move to.

## Changes and upgrades

What changed in each release is in each package's changelog: see [Changelog](/customers/changelog).

## Security fixes

Report a vulnerability privately, as [Security overview](/customers/security#reporting-a-vulnerability) says. Our
policy acknowledges a report within three business days (`SECURITY.md`). A fix ships as a new version; there is no
in-place patch of a published version.
